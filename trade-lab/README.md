# trade-lab

ห้องแล็บวิจัยตลาด รันบนเครื่องตัวเอง — ตอบคำถามว่า **แนวคิดเทคนิคไหนทำกำไรได้จริง
แนวคิดไหนแค่ความเชื่อ** ด้วยตัวเลขจากข้อมูลราคาจริง ไม่ใช่ความรู้สึก

เจาะจง **XAUUSD บน M1 และ M5** (สายเทรดสั้น)

---

## มันทำอะไร

ไล่ดูราคาย้อนหลังเป็นแสนแท่ง หาทุกจุดที่ราคา **กลับตัว / เด้ง / เริ่มวิ่งจริง**
แล้วตรวจว่าจุดเหล่านั้นมีอะไรอยู่บ้าง — **180 feature** ครอบคลุม:

| กลุ่ม | มีอะไร |
|---|---|
| โครงสร้างราคา | swing HH/HL/LH/LL, BOS, CHoCH, equal highs/lows |
| โซน | FVG (อายุ + % ที่ถูก fill), order block, จำนวนครั้งที่โซนถูกแตะ |
| Liquidity | sweep / stop hunt, ความลึกของการกวาด, ระยะถึง liquidity |
| CRT | range ของแท่งใหญ่, ตำแหน่งในโซน, กวาดแล้วกลับเข้า range |
| แนวรับ-ต้าน | High/Low ของวัน-สัปดาห์-เดือนก่อน, Asia range, เลขกลม |
| เส้นเทรนด์ | ลากอัตโนมัติจาก swing, ระยะถึงเส้น, การทะลุ |
| Indicator | RSI, Stochastic, CCI, Williams %R, MACD, EMA, ADX, SAR, Bollinger, Keltner, Donchian, OBV, VWAP |
| ท่ามาตรฐาน | RSI<30, RSI divergence, MACD cross, golden cross, ADX>25, squeeze breakout |
| Volume | tick volume z-score, volume profile (POC/VAH/VAL) |
| เวลา | session, killzone, วันในสัปดาห์ |

แล้วเทียบกับ baseline เพื่อดูว่าอันไหนมีนัยจริง — และที่สำคัญกว่า **อันไหนทำกำไรได้จริง**

## ผลลัพธ์หน้าตาแบบไหน

รายงาน Markdown ภาษาไทยใน `reports/` แบ่ง 9 หัวข้อ เริ่มจาก**สิ่งที่ไม่ผ่าน**ก่อนเสมอ:

1. ตรวจความน่าเชื่อถือของระบบเอง (ถ้าไม่ผ่าน รายงานหยุดตรงนี้)
2. เหตุการณ์ที่ตรวจจับได้
3. **สรุปว่ามีอะไร "รอด" บ้าง** ← อ่านข้อนี้ก่อน
4. จุดกลับตัว / เด้ง / ก่อนวิ่ง เกิดที่ไหน
5. เงื่อนไขไหนทำกำไรจริง (หักต้นทุนแล้ว)
6. ผสมเงื่อนไขแล้วดีขึ้นมั้ย + walk-forward
7. indicator ซ้ำซ้อนกันแค่ไหน
8. รูปแบบที่ยังไม่มีชื่อ
9. ขั้นถัดไป

ตัวอย่างตาราง:

| เงื่อนไข | แท่ง | ครั้ง | แม่น | E[R]/ไม้ | CI ล่าง | รอดจริง |
|---|---|---|---|---|---|---|
| FVG ค้าง ยังไม่ fill | 1,847 | 213 | 34.0% | +0.36 | +0.11 | ✅ |
| RSI < 30 เดี่ยวๆ | 4,102 | 388 | 61.2% | −0.31 | −0.44 | — |

> **"ครั้ง" ไม่ใช่ "แท่ง"** — เงื่อนไขที่กิน 2,000 แท่งแต่เกิดแค่ 7 ครั้ง (เช่น "ทุกวันศุกร์")
> มีตัวอย่างจริง 7 ตัว ไม่ใช่ 2,000 ระบบคิดสถิติจากคอลัมน์นี้ ไม่ใช่จำนวนแท่ง
> — นี่คือจุดที่ระบบเคยพลาดจนหา "edge" เจอบนข้อมูลสุ่ม ดู [bugs.md](bugs.md)

## มันไม่ได้ทำอะไร

- ไม่ทำนายว่าพรุ่งนี้ราคาจะขึ้นหรือลง
- ไม่รับประกันกำไร — เงื่อนไขที่แม่น 40% ก็ยังผิด 60%
- ไม่ยิงคำสั่งเทรด (ต่อ MT5 เพื่อ**ดึงข้อมูลอย่างเดียว**) — ถ้าจะเทรดจริง ไปที่ [`smart-ea`](../smart-ea)
- ไม่ดูข่าว — เทคนิคอย่างเดียว

### ยังไม่มี MT5

ทดสอบว่าระบบทำงานถูกต้อง ด้วยข้อมูลจำลอง (random walk ที่**ไม่มี** edge อยู่จริง —
ถ้าเจออะไร "รอด" แปลว่าโค้ดมีบั๊ก):

```bash
.\.venv\Scripts\python.exe -m tradelab --synthetic --synthetic-bars 60000 study
```

หรือนำเข้าข้อมูลจากไฟล์ CSV ที่ export มาจากที่อื่น:

```bash
.\.venv\Scripts\python.exe -m tradelab import-csv path\to\bars.csv --timeframe M5
```

### คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
|---|---|
| `check` | ตรวจว่าต่อ MT5 ได้มั้ย |

## วิธีทำงานที่ระบบบังคับไว้

โปรเจกต์แบบนี้ตายเพราะหลอกตัวเอง ไม่ใช่เพราะโมเดลไม่เก่ง ระบบจึงบังคับ 5 อย่าง:

1. **กัน holdout 20% ไว้ ห้ามแตะระหว่างวิจัย** — `research()` ไม่โหลดมันเลย
2. **สุ่มเทรดต้องขาดทุนเท่าต้นทุน** — ถ้าไม่ใช่ ระบบหยุด ไม่วิเคราะห์ต่อ
3. **พิสูจน์ว่าไม่มี feature อ่านอนาคต** — คำนวณซ้ำบนข้อมูลที่ตัดท้ายทิ้ง ค่าต้องเท่าเดิม
4. **นับจำนวนครั้งที่เกิดจริง ไม่ใช่จำนวนแท่ง** — ป้องกันเงื่อนไขที่จริงๆ คือตัวกรองวันที่
5. **ยิ่งทดสอบเยอะ เกณฑ์ยิ่งเข้ม** — Benjamini-Hochberg + Bonferroni อัตโนมัติ

ระบบผ่าน **96 test** รวมถึง test ที่สำคัญที่สุด: *ต้องหา edge ไม่เจอบนข้อมูลสุ่ม*
