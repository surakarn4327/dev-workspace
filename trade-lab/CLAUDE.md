## โปรเจกต์นี้คืออะไร

ห้องแล็บวิจัยตลาด รันบนเครื่องตัวเอง — ไล่ดูราคาย้อนหลังเป็นแสนแท่ง หาจุดที่ราคา
**กลับตัว / เด้ง / เริ่มวิ่งจริง** แล้วตอบด้วยตัวเลขว่า **แนวคิดเทคนิคไหนทำกำไรได้จริง
แนวคิดไหนแค่ความเชื่อ**

ไม่ใช่ระบบทำนายราคา และไม่ใช่ EA — เป็นเครื่องมือ**วิจัย** ที่ผลลัพธ์ของมันเอาไปสร้าง
indicator (Pine) หรือ EA (MQL5 ใน [`../smart-ea`](../smart-ea)) อีกที

### 4 คำถามที่ระบบต้องตอบ

1. จุดกลับตัว/เด้ง/เริ่มวิ่ง มีอะไรร่วมกัน — ทั้งโครงสร้างราคา (FVG, order block, liquidity,
   CRT, trendline, S/R) และ indicator พื้นฐาน (RSI, MACD, EMA, ADX, Bollinger)
2. เงื่อนไขไหน**ทำกำไรจริง** — วัดด้วย expectancy หัก spread/slippage/swap แล้ว ไม่ใช่ winrate
3. ผสมหลายเงื่อนไขแล้วดีขึ้นมั้ย — และผสมยังไงโดยไม่ตกหลุมของปลอม
4. มีรูปแบบที่ยังไม่มีชื่อซ่อนอยู่มั้ย — จากการจัดกลุ่มแบบไม่ชี้นำ

## กฎเฉพาะของโปรเจกต์นี้

### 1. ห้ามใส่ credential ของ MT5/Exness ลงในโค้ด

login / password / server ต้องอ่านจาก `.env` หรือ config ที่ไม่เข้า git เท่านั้น
(ตาม [ธรรมนูญข้อ 4](../CLAUDE.md)) — โปรเจกต์นี้เชื่อมต่อ MT5 จริงเพื่อ**ดึงข้อมูลอย่างเดียว**
ห้ามเขียนโค้ดที่ส่งคำสั่งเทรดในโปรเจกต์นี้ (ถ้าจะเทรดจริง ไปทำที่ `smart-ea`)

### 2. Holdout ต้องแตะครั้งเดียว — ห้ามแอบดู

ตัดข้อมูลช่วงท้าย (เช่นปีล่าสุด) ออกเป็น holdout ตั้งแต่ต้น **ห้ามใช้มันตอนวิจัย ห้ามดูผลของมัน
แล้วกลับไปแก้สมมติฐาน** เปิดทดสอบครั้งเดียวตอนได้ผู้ชนะแล้วเท่านั้น

เหตุผล: ถ้าดูผล holdout แล้วกลับไปปรับ มันจะกลายเป็น training data ทันที และเราจะไม่มีทาง
รู้ได้อีกเลยว่าผลที่ได้จริงหรือปลอม

### 3. รายงานผลต้องมี expectancy + n + ช่วงความเชื่อมั่น เสมอ

ห้ามรายงาน winrate เปล่าๆ เพราะแม่น 60% ที่ RR 0.5 ขาดทุน แต่แม่น 34% ที่ RR 3 กำไร
ทุกตัวเลขผลลัพธ์ต้องหักต้นทุน (spread / slippage / swap) แล้ว และต้องบอกจำนวนตัวอย่าง —
`41%` เฉยๆ หลอกตา `41% ± 12% (n=204)` บอกความจริง

### 4. ทดสอบยิ่งเยอะ ยิ่งต้องเข้มขึ้น

ทดสอบ 500 เงื่อนไขจะเจอ "ผู้ชนะ" ~25 อันจากความบังเอิญล้วนๆ ทุกครั้งที่เพิ่มจำนวนสมมติฐาน
ต้องปรับเกณฑ์ตัดสินให้เข้มตามด้วย และเงื่อนไขที่ผ่านต้องอธิบายได้ว่า**ทำไม**มันควรใช้ได้ —
ถ้าอธิบายไม่ได้ ให้ทิ้ง ไม่ว่าตัวเลขจะสวยแค่ไหน

### 5. ห้าม lookahead — feature ต้องคำนวณจากข้อมูล ณ วินาทีนั้นเท่านั้น

เผลอใช้ข้อมูลอนาคตแม้แท่งเดียว ผลจะสวยหลอกทันที เขียน feature ใหม่ทุกตัวต้องมีเทสต์ยืนยัน
ว่าค่าที่แท่ง `t` ไม่เปลี่ยนเมื่อข้อมูลหลัง `t` เปลี่ยน

### 6. เจอผลลัพธ์ผิดปกติ ห้ามเดาสาเหตุแล้วแก้เลย

ต้องใส่ counter/log ตรวจจริงว่าไปตายจุดไหน แล้วค่อยแก้ตามข้อมูล
(กฎเดียวกับ [`../smart-ea/CLAUDE.md`](../smart-ea/CLAUDE.md) — เคยเสียเวลาเพราะเดาผิดจุดมาแล้ว)

### 7. Sanity check ก่อนเชื่อผลใดๆ

ก่อนเชื่อผลวิเคราะห์รอบไหนก็ตาม ต้องผ่านการทดสอบว่า **การเข้าออเดอร์แบบสุ่มต้องขาดทุน
เท่ากับต้นทุน spread พอดี** ถ้าสุ่มแล้วกำไร แปลว่าโค้ดมีบั๊ก (มักเป็น lookahead หรือลืมหักต้นทุน)
ไม่ใช่ว่าเจอ edge
