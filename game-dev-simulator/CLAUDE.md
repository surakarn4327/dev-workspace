# game-dev-simulator

> อยู่ใต้ธรรมนูญ `C:\dev\CLAUDE.md` — อ่านไฟล์นั้นก่อน กฎในไฟล์นี้ชนะเมื่อขัดกัน

## โปรเจกต์นี้คืออะไร

Roblox tycoon — ผู้เล่นเริ่มจากเด็กธรรมดาที่ผันตัวมาเป็น game dev ไต่จากศูนย์:

1. **สร้างเกม** — เลือก genre/เวลาที่ใช้ทำ ยิ่งใส่เวลา/ทรัพยากรมาก คุณภาพยิ่งสูง (ยังไม่มีทีม ไม่มีทุน ทำคนเดียว)
2. **ตระเวนขาย** — เดินไปเสนอขายเกมกับ publisher/แผงขายต่างๆ ในโลกเกม (ไม่ใช่กดปุ่มขายเฉยๆ)
3. **ราคาผันตามคุณภาพ** — เกมคุณภาพสูงขายได้แพง เกมกากขายได้ถูก
4. **ปั้นทุน → ซื้อบริษัทเล็ก** — จุดเปลี่ยนจาก freelance dev เป็นเจ้าของบริษัท
5. **จ้างพนักงาน** — เพิ่มความเร็ว/คุณภาพการผลิตเกม
6. **แข่งขันกับสตูดิโออื่น** — NPC/ผู้เล่นอื่นแย่งส่วนแบ่งตลาด

จุดต่างจาก Game Dev Tycoon ต้นแบบ: journey เริ่มจากศูนย์จริง (ไม่มีสตูดิโอให้ตั้งแต่ต้น), ระบบขายที่ต้อง active ไปเสนอเอง, และมีคู่แข่งในโลกเกม

(โปรเจกต์นี้เคยสร้างมาก่อนแล้วครั้งหนึ่งด้วย Rojo-only scaffold ที่ยังว่างเปล่า — ลบทิ้งแล้วเริ่มใหม่
2026-08-28 เพื่อเปลี่ยนมาใช้ Studio built-in MCP แทน แนวคิด/ธีมเกมเหมือนเดิมทุกอย่าง)

## หลักออกแบบ (อ่านก่อนออกแบบ/แก้ feature ไหนก็ตาม)

**นี่คือ "simulator" ไม่ใช่แค่ tycoon กดปุ่ม** ทุก feature ต้องผ่านขั้นตอนคิดนี้เสมอ:

1. **นึกภาพความเป็นจริงก่อน** — dev จริงทำอะไรบ้างตอนสร้างเกม/ขายเกม/จ้างคน (เดินไปนั่งคอม, เขียนโค้ดใช้เวลาจริง,
   ต้องเดินไปเสนอ publisher ไม่ใช่กดปุ่มลอยๆ, สัมภาษณ์คนก่อนจ้าง ฯลฯ) ห้ามเริ่มออกแบบจาก "ปุ่ม UI ที่ทำง่ายสุด"
2. **ค่อยลดทอนให้เล่นง่าย** — เอาภาพความจริงจากข้อ 1 มาปรับให้ไม่ซับซ้อนเกินไป ไม่ต้องจำลองทุกรายละเอียด
   (เช่น ไม่ต้องมี syntax error ให้ debug จริง) แต่ต้อง**รู้สึกเหมือน**กำลังทำสิ่งนั้นอยู่ — มีการเดิน/มี
   เวลาผ่าน/มี interaction กับโลกเกม ไม่ใช่กดปุ่มบนจอแล้วจบ
3. **เช็คทุกครั้งก่อนส่งมอบ feature**: ถ้าฟีเจอร์นี้ทำได้ด้วยการกดปุ่มเดียวจากเมนูลอยๆ โดยไม่ต้องขยับตัว/ไม่ต้อง
   รอเวลา/ไม่ต้องอยู่ในโลกเกมเลย ให้กลับไปคิดใหม่ตามข้อ 1

### หลักย่อย: UI ที่ควรผูกกับโลก 3D ต้องผูกจริง ไม่ใช่ ScreenGui ลอย

ถ้า UI ไหน "แทนของจริงในโลกเกม" (เช่นจอคอมพิวเตอร์, ป้ายร้าน, จอทีวี) ต้องนึกภาพว่าคนมองของจริงชิ้นนั้นเห็น
อะไร — สายตาจดจ่อกับตัววัตถุที่อยู่ในโลก ไม่ใช่มี popup 2D ลอยขึ้นมาทับหน้าจอเฉยๆ (ไม่ว่าจะเต็มจอหรือเป็น
กรอบเล็กตรงกลาง ก็ยังเป็น "popup" อยู่ดีถ้าไม่ได้ผูกกับวัตถุจริง)

วิธีที่ถูก: ใช้ **SurfaceGui** ติดบนตัว Part ที่เป็นจอ/ป้ายนั้นจริงๆ ในโลก 3D แล้วถ้าต้องการให้ผู้เล่น
"จดจ่อ" กับมัน (เช่นนั่งใช้คอม) ให้ขยับกล้อง (`Camera.CameraType = Enum.CameraType.Scriptable`) เข้าไป
มองใกล้ๆ วัตถุนั้นแทน ไม่ใช่ hardcode ให้ ScreenGui ธรรมดาเต็มจอ — กล้องเข้าใกล้เองตามธรรมชาติของระยะ
ทำให้รู้สึก "สมจริง" กว่า ScreenGui จะเหมาะกับ HUD ทั่วไปที่ไม่ได้แทนของจริงในโลก (เช่น เงิน, notification)
เท่านั้น

## Tech stack

- **ภาษา**: Luau (ภาษา script ของ Roblox)
- **การเชื่อมกับ Studio**: **Studio built-in MCP server** (เปิดผ่าน `File → Studio Settings → Beta
  Features → enable MCP Server`, ฟัง `localhost:3004`) — Claude สั่ง insert object, เขียน/รัน script,
  อ่าน console, คุม playtest ผ่าน MCP โดยตรง ไม่ต้องพึ่ง Rojo sync ไฟล์แบบโปรเจกต์เดิม
  - ต้องเปิด Roblox Studio ค้างไว้เสมอตอนให้ Claude ทำงานกับโปรเจกต์นี้ (MCP เป็น session-based)
  - โค้ดที่ Claude เขียน/แก้ผ่าน MCP จะอยู่ใน place file (`.rbxl`) ไม่ใช่ไฟล์ `.luau` แยกบนดิสก์เหมือน Rojo
  - **ทุกครั้งที่ Claude สร้าง/แก้ script ของโปรเจกต์เอง (ไม่ใช่ script ของ asset pack ที่ import มา) ผ่าน MCP
    ต้อง sync กลับมาเขียนไฟล์ใน `src/` ให้ตรงกับ Source ล่าสุดเสมอ โดยไม่ต้องรอผู้ใช้สั่ง** (เพิ่ม 2026-08-29
    ตามคำขอผู้ใช้ ให้เป็น default ทุก session ไม่ใช่ต้องขอทีละครั้ง) — path map ตาม `src/server|client|shared`
    ปกติ, ชื่อไฟล์ตรงกับชื่อ instance, นามสกุลตาม script type (`.server.luau` / `.client.luau` /
    `.luau` สำหรับ ModuleScript)
    - **ต้องอ่าน Source จาก `datamodel_type: "Edit"` เท่านั้น** ห้าม sync จาก Server/Client datamodel ตอน
      Play mode เด็ดขาด เพราะนั่นคือ runtime clone ชั่วคราว — แก้ `.Source` ใน datamodel นั้นแล้วกด Stop
      จะหายหมด ไม่ persist กลับ place file จริง (เจอเคสนี้มาแล้ว 2026-08-29: แก้บั๊ก apartment door,
      สั่ง `s.Source = ...` ใน Server datamodel ตอน Play คิดว่าเซฟแล้ว แต่พอ Stop กลับไปโค้ดเก่า ต้องแก้ซ้ำใน
      Edit datamodel ถึงเซฟจริง)
    - เฟอร์นิเจอร์/Part ที่สร้างผ่าน `execute_luau` ก็เช่นกัน — สร้างตอน Play มันจะหายตอน Stop เหมือนกัน
      (ไม่ใช่แค่ script) ถ้าต้องการให้ของถาวรอยู่ในโลกเกมจริง ต้องสร้างตอน `datamodel_type: "Edit"` เท่านั้น
    - asset pack ที่ import มา (vehicle kit, `PlayerModule`, `RealisticDoorPack`, click-sit ของม้านั่ง/เก้าอี้
      จาก endorsed models ฯลฯ) **ไม่ต้อง** sync ลง `src/` — เป็นของ vendor ไม่ใช่โค้ดที่ Claude เขียนเอง

## โครงสร้าง

```
src/            # สำเนาโค้ด Luau ไว้ track ใน git (sync มือ/เป็นระยะจากที่แก้ผ่าน MCP ใน Studio)
├── server/     # โค้ดฝั่ง server เท่านั้น (เงิน, การขาย, จ้างพนักงาน — ต้อง server-authoritative ทั้งหมด)
├── client/     # UI, input, effect ฝั่งผู้เล่น
└── shared/     # ค่าคงที่/type ที่ทั้งสองฝั่งใช้ร่วมกัน (ReplicatedStorage)
```

## ตัวละครผู้เล่น (fixed avatar — ใช้เป็นตัวอ้างอิงขนาดเฟอร์นิเจอร์)

ทุกคนสปอนด้วยตัวละครขนาด/รูปร่างเดียวกันเป๊ะ ล็อกด้วย `src/server/FixedAvatarController.server.luau`
(ปิด `Players.CharacterAutoLoads` แล้ว **clone** จาก `ServerStorage.PlayerCharacterTemplate` เองทุกครั้งที่
spawn/respawn — ผู้เล่นปรับแต่ง avatar เองไม่ได้ผลอะไร เพราะโดน override ทับทุกรอบ) เหตุผล: งานปรับขนาด
furniture ต่อๆ ไปจะใช้ขนาดตัวละครนี้เป็น reference ในการคำนวณสัดส่วน (ตามกฎ "ห้าม hardcode ค่าตำแหน่ง/สัดส่วน"
ด้านล่าง) ถ้าตัวละครขนาดไม่คงที่ค่าที่คำนวณไว้จะพัง

**ทำไมใช้วิธี clone ไม่ใช่ `HumanoidDescription`**: ลองแบบ `player:LoadCharacterWithHumanoidDescription`
พร้อม `BodyTypeScale = 0` ก่อน (2026-08-29) หวังว่าจะได้ตัวเรียบๆ สีเทา แต่ระบบ body-type blending ของ
Roblox ไม่เสถียร — ตั้ง `BodyTypeScale = 0` แต่ humanoid จริงกลับมาเป็น `0.3` แล้วได้ mesh ชุด "noob"
บล็อกเหลี่ยมสีเหลือง/น้ำเงินมาตรฐานแทน (ไม่ใช่ตัวเทาเรียบที่ต้องการเลย) แก้โดยเอา Rig ที่ผู้ใช้เลือกเอง
(R15 เรียบๆ สีเทาเดียวกันทั้งตัว ไม่มีหน้า) มาเก็บไว้ที่ `ServerStorage.PlayerCharacterTemplate` แล้ว
`:Clone()` ตรงๆ ทุก spawn — รับประกันเหมือนต้นแบบเป๊ะ ไม่ผ่านระบบ blending ที่ไม่เสถียรเลย
**ถ้าจะเปลี่ยนหน้าตาตัวละครทีหลัง ให้แก้ที่ตัว template instance นี้โดยตรง** ไม่ใช่กลับไปเล่นกับ
`HumanoidDescription`

**ค่าที่วัดได้จริงจาก fixed avatar (R15, ทุก scale = 1, วัดตอน Play จริง 2026-08-29):**
- `Humanoid.RigType` = `R15`
- `Humanoid.HipHeight` = `2`
- `HumanoidRootPart.Size` = `2, 2, 1`
- `Head.Size` ≈ `1.196, 1.203, 1.198`
- ความสูงรวมทั้งตัว (bounding box) ≈ `5.12` studs (กว้าง ≈ `4.24`, ลึก ≈ `1.53` — ท่ายืนปกติ แขนกางเล็กน้อย)

ถ้าจะคำนวณความสูงโต๊ะ/เก้าอี้/ระยะเอื้อมของผู้เล่น ให้ query ค่าพวกนี้จาก character จริงในโค้ด (เช่น
`character.Humanoid.HipHeight`, `character:GetExtentsSize()`) ไม่ใช่จำตัวเลขด้านบนไปเขียนเป็นค่าคงที่ในโค้ด
โดยตรง (เผื่อวันหลังปรับ `FIXED_DESCRIPTION` เปลี่ยน scale — โค้ดที่ query สดจะยังถูกต้องอัตโนมัติ)

## กฎเฉพาะของโปรเจกต์นี้

- **ห้าม hardcode ค่าตำแหน่ง/ระยะ/สัดส่วนที่คำนวณจากวัตถุจริงได้** — ทุกครั้งที่ค่าหนึ่งสัมพันธ์กับอีกวัตถุหนึ่ง
  (เช่น "จอต้องหันเข้าหาเก้าอี้", "กล้องต้องอยู่ใกล้จอแค่ไหนถึงจะพอดีจอผู้เล่น", "มอนิเตอร์ต้องสูงแค่ไหนไม่ให้จม
  โต๊ะ") ให้ **คำนวณจาก property จริงของวัตถุนั้น** (ตำแหน่ง, ขนาด, FOV, ViewportSize ฯลฯ) เสมอ ห้ามเดาตัวเลข
  คงที่ (เช่น `Vector3.new(0,0,1.6)`, `Face = Enum.NormalId.Back` แบบเดา) เพราะพอมีอะไรขยับ (ย้ายโต๊ะ, จอ
  ใหญ่ขึ้นจาก gear upgrade, ผู้เล่นจอคนละขนาด) ค่าที่เดาไว้จะพังทันทีและหาสาเหตุยาก
  - ข้อยกเว้น: ค่าคงที่ balance เกม (ราคา, สูตร, อัตรา ฯลฯ ใน `Config.luau`) ไม่นับ เพราะไม่มี "วัตถุจริง"
    ให้คำนวณอ้างอิง เป็นค่าออกแบบเกมล้วนๆ
- **ห้าม trust client เรื่องเงิน/ราคาขาย/คุณภาพเกมเด็ดขาด** — คำนวณและเก็บสถานะทั้งหมดฝั่ง server
  (`src/server/`) เท่านั้น ฝั่ง client ส่งแค่ "เจตนา" (เช่น "อยากขายเกมนี้") แล้ว server ตัดสินผล
  ป้องกันการโกงผ่าน exploit ฝั่ง client ซึ่งเป็นช่องโหว่ที่พบบ่อยสุดในเกม Roblox แนว tycoon
- ค่าคงที่ที่ balance เกม (ราคาพนักงาน, สูตรคำนวณคุณภาพ, อัตราขาย) เก็บรวมที่ `src/shared/Config.luau`
  จุดเดียว ห้าม hardcode กระจายในหลายไฟล์ — ปรับ balance ทีหลังจะได้แก้จุดเดียว
- DataStore (เซฟข้อมูลผู้เล่น) ต้องมี retry/pcall ครอบทุกครั้ง Roblox DataStore ล้มเหลวเป็นระยะได้
- **ข้อความ UI ในเกม (ปุ่ม, label, ข้อความที่ผู้เล่นเห็นในจอ) ต้องเป็นภาษาอังกฤษเท่านั้น** ห้ามมีภาษาไทยปนใน
  string ที่ render ขึ้นจอผู้เล่น — override กฎกลางที่อนุญาต UI ภาษาไทย (README/CLAUDE.md/comment ในโค้ด
  ยังเป็นภาษาไทยได้ตามปกติ กฎนี้ครอบเฉพาะข้อความในเกมจริงเท่านั้น)
- **เฟอร์นิเจอร์ทุกชิ้นในเกม (โต๊ะ, เก้าอี้, ชั้นวาง ฯลฯ) ออกแบบรูปลักษณ์อ้างอิงจากไลน์สินค้าแบรนด์จริงเท่านั้น**
  — ก่อนออกแบบ/เพิ่มเฟอร์นิเจอร์ชิ้นใหม่ ให้ค้นหาไลน์สินค้าแบรนด์จริงที่ใกล้เคียงก่อนเสมอ แล้วอ้างอิงสัดส่วน/
  สี/วัสดุ/ฟีเจอร์เด่นจากรุ่นจริงนั้น ไม่ใช่เดาดีไซน์เอง เพื่อให้ progression ราคาถูก→แพงในเกมสมจริงและเดา
  รูปลักษณ์ต่อ tier ได้ง่าย — เลือกแบรนด์ไหนก็ได้ที่มีสเปกจริงประกาศ (เช่น IKEA, Uplift Desk, Flexispot,
  Steelcase, Herman Miller, Secretlab) แต่ **ต้องบันทึกลง `FURNITURE_SOURCES.md` ทุกครั้งที่เลือกใช้แบรนด์/
  ไลน์ไหนทำของชิ้นไหน** (กันต้องไล่หาใหม่ทุกรอบ)
