# ea-tuner

> อยู่ใต้ธรรมนูญ `C:\dev\CLAUDE.md` — อ่านไฟล์นั้นก่อน กฎในไฟล์นี้ชนะเมื่อขัดกัน

## โปรเจกต์นี้คืออะไร

หน้าต่าง desktop (Python + Tkinter) สำหรับควบคุมการทดสอบ/จูน EA ของโปรเจกต์พี่น้อง
[`../smart-ea`](../smart-ea/CLAUDE.md) โดยไม่ต้องพิมพ์คอมมานด์ไลน์เอง — เลือก EA, ไฟล์ `.set`,
สัญลักษณ์, ช่วงวันที่ (เฉพาะโหมดที่ไม่ใช่จูน), โหมด (รันเดี่ยว/จูน/จำลองถอนกำไรรายสัปดาห์-รายเดือน)
แล้วกดปุ่ม **รัน** โปรแกรมจะสั่ง MT5 ผ่าน `optimizer/bin/*.ps1` ที่มีอยู่แล้วของ smart-ea ให้เอง
รอจนจบ แล้วเปิดหน้าสรุปผล HTML ให้อัตโนมัติ (ตารางอันดับทุกชุดที่จูน + กราฟกำไรรายงวด)

**หลักการออกแบบ (คำขอผู้ใช้ 2026-09-12, ยืนยันซ้ำหลายรอบ): ทุกอย่างที่มี "คำตอบที่ดีที่สุด"
ทางเทคนิคชัดเจนต้องล็อกเป็นค่าคงที่ ไม่ใช่ช่องให้ผู้ใช้ปรับ** — เหลือให้ผู้ใช้เลือกเองแค่สิ่งที่เป็น
การตัดสินใจทางธุรกิจจริงๆ (จะเทรด EA ตัวไหน, สัญลักษณ์ไหน, ทุนเท่าไหร่) ตัวอย่างที่ถูกล็อกไปแล้ว:
- **โมเดล tick ไม่มีช่องให้เลือกอีกต่อไป** (เดิมมี dropdown default "Every tick" ซึ่งเป็นบั๊กเสี่ยงจริง
  ถ้าใช้กับโหมดจูน — `smart-ea/bugs.md` บันทึกไว้ว่ารันกริดด้วย Every tick ช้ากว่า 1-minute OHLC
  ~50 เท่าจนดูเหมือนเครื่องค้าง) ตอนนี้ล็อกอัตโนมัติตามด่าน: `config.MODEL_GRID` (1-minute OHLC)
  สำหรับขั้นที่รันหลายร้อยชุด (genetic/exhaustive), `config.MODEL_ACCURATE` (Every tick) สำหรับ
  ขั้นที่รันแค่ 1 pass (รันเดี่ยว/holdout/รายสัปดาห์-เดือน) ซึ่งความช้าไม่กระทบเพราะมีแค่ pass เดียว
- **TF กับ `.set` เดาให้อัตโนมัติตาม EA ที่เลือก** (`config.guess_period_for_ea`,
  `config.guess_set_for_ea` — ผูกกับ dropdown EA ผ่าน `_on_ea_change`) ยังแก้เองได้เสมอ
  (ไม่ได้ล็อกแบบเดียวกับช่วงวันที่/holdout/genetic reps เพราะ TF ที่เหมาะสมต่างกันจริงตาม
  EA/สัญลักษณ์ ไม่มีค่าเดียวที่ถูกเสมอ) — **ต้องกรองด้วย TF ที่ตรงกันเป๊ะเสมอ ไม่ใช่แค่ชื่อกลยุทธ์
  ตรง** เจอบั๊กจริงตอนพัฒนา (2026-09-12): กลยุทธ์เดียวกันมักมี `.set` แยกคนละ TF (เช่น
  `amdpo3_clean2025_M5.set` กับ `..._M15.set`) เรียงตามตัวอักษร "M15" มาก่อน "M5" เสมอ
  (ตัวอักษร '1' < '5') ถ้าไม่กรอง TF จะได้ไฟล์ผิด TF ทุกครั้งที่ EA เป็น M5 แต่มีไฟล์ M15 อยู่ด้วย
  — และ regex ที่ใช้ตัด prefix ต้องเรียง alternation ของ TF ยาวไปสั้นด้วย (`M15` ก่อน `M1`)
  ไม่งั้น regex จะจับแค่ "M1" ในคำว่า "M15" แล้วเหลือเศษ "5_..." ค้างอยู่

**โหมด "จูน" กดครั้งเดียวแต่รันเป็น 3 ขั้นเสมอ** (คำขอผู้ใช้ 2026-09-12 — ให้ทำหน้าที่แทนขั้นตอนที่
เคยทำด้วยมือตอนจูน EA ในโปรเจกต์นี้ ไม่ใช่แค่รัน genetic รอบเดียวแล้วเชื่อผู้ชนะ):
**ทุกค่าในทั้ง 3 ขั้นล็อกไว้ตายตัวหมดแล้ว ไม่มีช่องให้ผู้ใช้ปรับเลยสักช่อง** (คำขอผู้ใช้ 2026-09-12
รอบสอง — "ไม่ควรให้ฉันตั้งค่าเอง ควรตั้งค่าที่ดีที่สุดเป็นค่าเริ่มต้น เพื่อให้โปรแกรมใช้งานง่ายที่สุด")
ค่าคงที่ทั้งหมดอยู่ใน `config.py`: `OPTIMIZE_TRAIN_START`, `OPTIMIZE_HOLDOUT_DAYS`,
`OPTIMIZE_GENETIC_REPS` — ถ้าจะเปลี่ยนค่าเริ่มต้นเหล่านี้ในอนาคต แก้ที่ค่าคงที่ในโค้ดตรงๆ
ไม่ใช่เพิ่ม UI control กลับมา (ขัดกับคำขอผู้ใช้โดยตรง):

1. **genetic รันซ้ำ `OPTIMIZE_GENETIC_REPS` รอบ (ตายตัว = 3)** บนช่วง **train** เท่านั้น — รวมผู้ชนะ
   ทุกรอบเข้าด้วยกันแล้วเลือกคะแนนสูงสุดจากทั้งหมด (genetic ของ MT5 สุ่มทดสอบแค่บางส่วนของกริด
   ทั้งหมด ต่างรอบอาจลงคนละจุด รอบเดียวไม่พอ)
2. **exhaustive ไล่ครบทุกจุด ±1 step** รอบผู้ชนะของขั้น 1 (ยังบนช่วง train) — เช็คว่าเป็น "ที่ราบ" จริง
   หรือ "ยอดแหลม" เดี่ยวๆ ค่าที่ควรใช้จริงมาจากขั้นนี้เสมอ ไม่ใช่ขั้น 1
3. **ตรวจสอบ holdout** — เอาค่าที่ชนะขั้น 2 ไปรัน single-pass บนช่วง **holdout** (ท้ายสุด
   `OPTIMIZE_HOLDOUT_DAYS` วันของช่วงวันที่ทั้งหมด = ตายตัว 45 วัน ไม่ใช่ % อีกต่อไป) ซึ่งไม่เคย
   ถูกใช้เลือกค่าเลยทั้งขั้น 1-2 — ถ้าผลพังตรงนี้ (กำไร ≤ 0 หรือ PF < 1) รายงานจะเตือนชัดเจนว่า
   "ไม่ผ่าน" **ห้ามเอาผล holdout กลับไปเลือกค่าใหม่เด็ดขาด** (จะทำให้ช่วงนั้นกลายเป็นข้อมูลที่ใช้จูน
   ไปด้วย ไม่เหลืออะไรไว้ตรวจสอบอีก)

**ทำไม holdout ใช้ "ส่วนท้ายสุดของช่วงที่ขอ" ไม่ใช่ปีที่ตรึงไว้ตายตัว** (คำถามผู้ใช้ 2026-09-12: ตลาด
เปลี่ยน regime ตลอด ค่าที่จูนจากข้อมูลเก่าอาจใช้ไม่ได้กับตอนนี้) — `runner.split_train_holdout()`
คำนวณ holdout จากท้ายช่วง `date_to` เสมอ ดังนั้นถ้าผู้ใช้ขยับ `date_to` มาเป็นวันนี้ทุกครั้งที่จูนใหม่
holdout ก็จะเป็น "ช่วงล่าสุดที่สุด" ที่มีข้อมูลจริงเสมอ ไม่ใช่ปี 2568 ที่แช่แข็งไว้ — มิเรอร์กติกา
walk-forward ที่ `optimizer/README.md` ของ smart-ea ใช้กับ AMD Po3 (2026-09-11)

**สิ่งที่ทำอัตโนมัติไม่ได้ (ยังต้องส่งผลให้ผู้ใช้/Claude ตัดสินใจต่อ)**: การรีดีไซน์ตรรกะเทรดใหม่เมื่อ
ทั้ง 3 ขั้นข้างบนยังไม่ผ่าน (เช่น เปลี่ยนสูตร SL, เปลี่ยนตัวกรอง entry) — เป็นการตัดสินใจเชิงสร้างสรรค์
ที่ไม่ใช่แค่ขยับพารามิเตอร์ในกริดเดิม ผู้ใช้ตกลงว่าจะส่งผลจาก ea-tuner กลับไปให้ Claude คิดใหม่ในกรณีนี้
(2026-09-12) ไม่ได้พยายาม automate ส่วนนี้

**ห้าม import โค้ด MQL5 ข้ามโฟลเดอร์** (ตามธรรมนูญ) — ea-tuner ไม่รู้จักตรรกะภายในของ EA ใดๆ เลย
คุยกับ smart-ea ผ่านสองทางเท่านั้น: (1) เรียก `optimizer/bin/*.ps1` เป็น subprocess (2) อ่านไฟล์ผลลัพธ์
`.csv` ที่สคริปต์เหล่านั้นเขียนไว้ใน `optimizer/results/` กลับมา

## คำสั่งที่ใช้จริง

```bash
python src\main.py      # เปิดหน้าต่างโปรแกรม
pytest                  # test
```

ไม่มี dev server/พอร์ตจริง (เป็นโปรแกรม desktop ล้วน ไม่ใช่เว็บ) — ค่าพอร์ต 8000 ใน `PROJECTS.md`
เป็นแค่ค่า default ของสคริปต์ scaffold ไม่ได้ใช้งานจริง

## โครงสร้าง

- `src/config.py` — ค่าคงที่ + ค้นหาไฟล์ของ smart-ea (path ของ `optimizer/bin`, `sets`, `results`,
  รายชื่อ EA จาก `smart-ea/src/*.mq5`, mapping ชื่อไฟล์ `*Core.mqh` → โฟลเดอร์ dump ผลใน
  `Common\Files\` ของ MT5) **ถ้าเพิ่ม EA ใหม่ใน smart-ea ที่ import Core.mqh ตัวใหม่ ต้องเพิ่ม
  entry ใน `CORE_TO_DUMPDIR` ที่นี่ด้วย** (เช็คจาก path ที่ `FileOpen()` ใช้ใน `DumpPass()` ของ
  Core.mqh นั้น)
- `src/runner.py` — ประกอบ argument list แล้วรัน `run-opt.ps1` / `run-weekly-reset.ps1` /
  `run-monthly-reset.ps1` เป็น subprocess, stream stdout ทีละบรรทัดกลับมา + ตัวช่วยของ pipeline
  3 ขั้น (`parse_set_file`, `build_neighbor_set`, `build_fixed_set`, `split_train_holdout`) —
  **`parse_set_file`/`build_neighbor_set`/`build_fixed_set` ต้องรับ list ค่าที่ตัด 2 คอลัมน์แรก
  (symbol, timeframe) ออกแล้วเสมอ** เพราะ `DumpPass()` ของทุก Core.mqh ในโปรเจกต์นี้เขียน
  `_Symbol` แล้วก็ `tf` เป็น 2 คอลัมน์แรกก่อนพารามิเตอร์ตัวแรกที่มาจาก `.set` จริงๆ (ค่าคงที่
  `config.PARAM_PREFIX_COLS`) — เคยลืมตัดจุดนี้มาแล้วครั้งหนึ่ง (2026-09-12) ทำให้ไฟล์ .set
  เพื่อนบ้านเพี้ยนทั้งไฟล์ (เช่น `InpCompressionPct` ได้ค่าเป็น string "M5" แทนตัวเลข) เงียบๆ
  ไม่มี error จนกว่าจะไปพังตอน MT5 อ่าน .set ไม่ได้
- `src/report.py` — parse ไฟล์ผล `.csv` (ผังคอลัมน์: พารามิเตอร์ N ช่อง + 17 ช่องตัวชี้วัดท้ายบรรทัด
  ตาม `MetricsCsvTail()` ใน `smart-ea/src/TesterMetrics.mqh` — ea-tuner ไม่รู้ชื่อจริงของแต่ละ
  พารามิเตอร์ แสดงเป็น `Param1..N` เสมอ เพื่อให้ใช้ได้กับ EA ใหม่ในอนาคตโดยไม่ต้องแก้โค้ดที่นี่)
  แล้วประกอบเป็นหน้าเว็บ HTML เดี่ยว (self-contained ไม่พึ่ง asset ภายนอก) เขียนลง `output/`
  (ไม่เข้า git — สร้างใหม่ได้ทุกครั้งจากไฟล์ผลดิบใน `smart-ea/optimizer/results/`)
- `src/gui.py` — หน้าต่างหลัก (Tkinter) + หน้าต่างแก้ไฟล์ `.set` แบบ text ธรรมดา
- `src/main.py` — entry point

## กฎเฉพาะของโปรเจกต์นี้

- **ไม่มี dependency ภายนอกเกินจำเป็น** — ใช้แต่ standard library ของ Python (Tkinter, subprocess,
  threading) เพื่อไม่ต้องพึ่ง `pip install` อะไรเพิ่มตอนย้ายเครื่อง (เครื่องนี้ไม่มี Python ติดตั้งมา
  ด้วยซ้ำตอนสร้างโปรเจกต์ — ต้องลงผ่าน `winget install Python.Python.3.12` ก่อน)
- **โหมดความเสี่ยง (fixed USD / % equity) ไม่มี control แยกในหน้าต่างหลัก** ตั้งใจให้แก้ผ่านไฟล์
  `.set` โดยตรง (ปุ่ม "แก้ไฟล์ .set") เพราะชื่อ input ของแต่ละ EA ไม่เหมือนกัน
  (`InpRiskMode`/`InpRiskPct`/`InpRiskFixedUsd`) การสร้าง control เฉพาะจะผูก ea-tuner
  เข้ากับ EA ตัวใดตัวหนึ่งมากเกินไป
- **การรันจริงทุกครั้งเรียก `optimizer/bin/run-opt.ps1` ของ smart-ea เสมอ** (ไม่เขียน logic
  เรียก MT5 ซ้ำเอง) เพราะสคริปต์นั้นมีด่านตรวจ/แก้บั๊กสะสมมาเยอะแล้ว (ดู `smart-ea/bugs.md`
  และ `smart-ea/optimizer/README.md`) — ถ้า `run-opt.ps1` เปลี่ยน interface ต้องแก้
  `src/runner.py` ให้ตรงกันด้วย
- **path ของ Expert ที่ส่งให้ `run-opt.ps1` ต้องมี `Advisors\` นำหน้าเสมอ** (เช่น
  `Advisors\SmartIndicatorEA`) เพราะไฟล์ `.ex5` ถูก deploy ไปที่ `MQL5\Experts\Advisors\`
  ไม่ใช่ `MQL5\Experts\` ตรงๆ — พลาดจุดนี้แล้ว `run-opt.ps1` จะหาโฟลเดอร์ terminal ไม่เจอ
- **PowerShell บนเครื่องนี้ไม่มี `git`/`python` ใน PATH ของ process ใหม่โดย default**
  ถ้าจะรันคำสั่งที่ต้องใช้สองตัวนี้จาก terminal ภายนอก IDE ต้องเซ็ต `$env:Path` เพิ่มเอง
  ชี้ไป `AppData\Local\Programs\Python\Python312` และ
  `AppData\Local\GitHubDesktop\app-*\resources\app\git\cmd` — ea-tuner เองไม่ต้องพึ่งเรื่องนี้
  เพราะเรียก `powershell.exe` ตรงๆ ผ่าน `subprocess` ซึ่งสืบทอด PATH จาก process ที่รันโปรแกรมนี้อยู่แล้ว
