# PARTS.md — วิธีเพิ่มอุปกรณ์/ชิ้นส่วนใหม่ใน wire-up

ไฟล์นี้คือ **ขั้นตอนบังคับ** ทุกครั้งที่เพิ่มหรือแก้หน้าตา/พฤติกรรมของชิ้นส่วน (ทั้งคนและ Claude) เขียนขึ้นเพราะครั้งหนึ่งชิ้นส่วนถูกเพิ่มโดยข้ามขั้นตอน (ไม่ดูภาพจริง ไม่อ่านหลักของ resistor)
ทำให้หน้าตาได้แค่ "ร่างแรก" — ขั้นตอนข้างล่างกันไม่ให้เกิดซ้ำ ใช้ได้ทุกเครื่องหลัง clone repo (ไม่ต้องมีอะไรนอก repo: ฟอนต์อยู่ใน `public/fonts`)

> ใน Claude Code: `/new-part <ชื่อชิ้นส่วน>` จะพาทำตามขั้นตอนนี้ทีละข้อ

## หลักการ 3 ข้อ

1. **ไม่มีชิ้นไหนเสร็จจนกว่าผู้ใช้ดูภาพแล้วอนุมัติ** — Claude ตั้งสถานะ `approved` เองไม่ได้ ใส่ `draft` ใน `style.md` 1.3 เสมอ แล้วเปลี่ยนเมื่อผู้ใช้บอก
2. **หน้าตาต้องมาจากของจริง** — หาภาพอ้างอิงจริงก่อนวาด ลงแหล่งภาพใน `style.md` หัวข้อ 5.x ของชิ้นนั้น
3. **เทสต์ล้มถ้าลืมอะไร** — `src/parts/registry.test.ts` ตรวจทุกชิ้นใน `ALL_PARTS` อัตโนมัติ (ดูข้างล่าง) ถ้าเพิ่มชิ้นแล้ว `npm run test` ไม่ผ่าน = ยังไม่เสร็จ

## ขั้นตอน

### 0. ก่อนเขียนโค้ด — อ่าน (ห้ามข้าม)

- `style.md` หัวข้อ **1.1** (หลัก 8 ข้อของ resistor) และ **5** (รายละเอียด resistor), **3.5** (ตำแหน่งป้าย), **5.14** (ความยาวขา), **5.15** (ไหม้) และตาราง **1.3** (สถานะแต่ละชิ้น)
- เลือก **ชิ้นที่หน้าตาใกล้ที่สุดและสถานะ `approved`** เป็นแบบอย่างโค้ด:

| รูปทรงของชิ้นใหม่ | ดูแบบอย่างจาก |
|---|---|
| ทรงกระบอกนอน ขาออกสองข้าง | `resistor`, `diode` (`parts/passives.ts`, `parts/semis.ts`) |
| ตัวกลมแบน ขายื่นลง | `ldr`, `ntc` |
| ตัวตั้ง ขายื่นลง | `led`, `bc547` |
| กล่องมีลูกบิด/จอ | `pot`, `meter`, `supply` |
| สวิตช์/ปุ่มที่กดได้ | `parts/switches.ts` |
| IC หลายขา | `parts/ic.ts` (`dipSprite`) |

  ห้ามลอกจากชิ้นที่สถานะ `draft`

### 1. ภาพอ้างอิง — ผู้ใช้ต้องเห็นก่อนวาด

1. หาภาพจริงของชิ้นส่วน (Wikimedia Commons หรือค้นรูป) อย่างน้อย 1–2 ภาพ ดูสัดส่วน สี ตำแหน่งขา ขั้ว
2. **เสนอผู้ใช้**: ชื่อชิ้น, ลิงก์/ภาพอ้างอิง, ขนาดโดยประมาณเทียบกับชิ้นอื่น, ตำแหน่งขา (pin กี่ตัว ห่างกันกี่ช่อง), พฤติกรรมที่จะจำลอง, พิกัดและเงื่อนไขพัง ถามเมื่อมีจุดที่ต้องเลือก (ผู้ใช้ตัดสินเรื่องหน้าตา/พฤติกรรม)
3. รอผู้ใช้ตอบก่อนเริ่มวาด

### 2. ฟิสิกส์ (ความถูกต้องมาก่อนความสวย)

- ค่าคงที่/พิกัดไปที่ `src/sim/models.ts`
- ถ้าใช้ element เดิม (R, V, B, I, D, Q, K...) ประกอบกันใน `build()` ได้ ก็ไม่ต้องแตะ solver; ถ้าต้อง element ใหม่ → `src/sim/solver.ts` (`Element`, `stamp`, `currents`) + `board/flow.ts` `draws()` + เทสต์ใน `sim/solver.test.ts` ที่เทียบกับสูตร/ค่าที่คำนวณมือ **และห้าม import อะไรจาก render/ui/board/parts ใน `src/sim`**
- ทุกชิ้น (ยกเว้นที่ระบุไว้ใน `NO_STRESS` ของ `registry.test.ts` พร้อมเหตุผล) ต้องมี `stress` ใน `evaluate()`: `ratio` (1 = พิกัดสูงสุด) + ข้อความอธิบายเป็นตัวเลขจริง ("LED carried 1.25 A; max 30 mA")
- ชิ้นที่พังแล้ว `build()` ต้องไม่ add อะไรเลย (วงจรเปิด) ยกเว้นสวิตช์/ปุ่ม (เชื่อมค้าง)
- ชิ้นที่เปลี่ยนตามเวลา → ดู `Simulation.step` (`charge` ของตัวเก็บประจุเป็นตัวอย่าง)

### 3. ไฟล์ที่ต้องแตะ (เช็กให้ครบ)

| ไฟล์ | ทำอะไร |
|---|---|
| `src/parts/art.ts` | สไปรต์พิกเซล (`PixelGrid` + `sprite(key, …)` + `export function xxxSprite`) |
| `src/parts/<กลุ่ม>.ts` | `PartDef`: type (kebab-case), name, category, blurb, pins, bounds, build, evaluate, draw (มี branch `scene.pixel` + เวกเตอร์สำรอง), fields, summary, ป้ายขา (`pinLabelPlace`/`tipPastPin`) |
| `src/parts/index.ts` | ใส่ใน `ALL_PARTS` (ลำดับ = ลำดับใน toolbox); ใส่ชื่อใน `TALL_PARTS` หรือ `LOW_PARTS` ถ้าชั้นการวาดไม่ใช่ค่าปริยาย (4) |
| `src/board/world.ts` | ชิ้นที่ขายื่นลงและปรับความยาวได้ → เพิ่มใน `HANGING_LEG_PARTS` (และใส่ `LEG_FIELD`) |
| `src/board/obstacles.ts` `leadDirs` | ถ้าชิ้นมีกฎทิศสายออกจากขา (แบต=บน, สวิตช์=ข้าง...) |
| `src/render/burnt.ts` `NOT_BURNT` | ถ้า `failed` ไม่ได้แปลว่าไหม้ |
| `src/sim/models.ts` | ค่า/พิกัด |
| `style.md` | แถวใน **1.3** (สถานะ `draft`), แถวใน **1.2**, หัวข้อ **5.x** ใหม่ (ภาพอ้างอิง ขนาด พิกัดสไปรต์ สีทุกเฉด ตำแหน่งขา) |
| `bugs.md` | ถ้าเจอบั๊กระหว่างทำ |
| `CLAUDE.md` / `README.md` | ถ้ามีกฎใหม่หรือฟีเจอร์ที่ผู้ใช้เห็น |

### 4. กฎการวาด (ย่อจาก style.md)

- แสงบนซ้าย 6–7 เฉดต่อชิ้น (ไล่เฉดตามรูปทรง ไม่ใช่สีแบน) มุมมนจริง (`rrect`/`disc`) ขอบสีเข้มของตัวเอง จุดสะท้อนมุมบนซ้าย
- 1 พิกเซลอาร์ต = 2 หน่วยโลก; ตำแหน่ง pin เป็นจำนวนเต็ม grid (20 px) และตรงกับ `pins()`
- ข้อความไม่ฝังในสไปรต์ (`drawText`, ป้ายค่าใช้ `drawLabelAbove/Below` + `spriteInk`)
- ขาโลหะที่วาดเองต้องใช้ `pxLeg` / `pxLegH` / `pxLegDiag` (`render/pixel.ts`) ให้มีขอบดำและเงาเหมือนขาชิป วาดขาก่อนตัวและให้ขายื่นเข้าไปใต้ตัว (ห้ามขาลอยจากตัว) แล้วตั้ง `tipPastPin` +2 ตามที่ harness วัดได้ (style.md 5.19)
- ชิ้นตัวกลมที่ขาไม่อยู่ใต้ตัว: ให้ขาตรงขึ้นไปซ่อนใต้ตัวจนต่อกับตัวจริง (ดู `ldr`, `ntc`, `cap-ceramic`)
- สีใหม่ → ใส่ `COL.*` / ลงทะเบียนใน style.md หัวข้อ 2

### 5. ตรวจก่อนบอกว่าเสร็จ (ทุกข้อ)

1. `npx tsc --noEmit` ผ่าน
2. `npm run test` ผ่านทั้งหมด **รวม `registry.test.ts`** (มันจะบอกเองว่าลืมอะไร: ไม่มีแถวใน style.md 1.3, ไม่มี stress, pin ไม่ตรงกรอบ ฯลฯ)
3. เปิด **http://localhost:5173/gallery.html** (`npm run dev`) — ดูชิ้นใหม่ครบ 4 มุมหมุน ทั้งโหมด Pixel และ Vector เทียบกับภาพอ้างอิง; กดปุ่ม **Check label gaps** ต้องขึ้น "every label gap is 4" ทั้งโหมดพิกเซล (โหมดเวกเตอร์ 4–4.3 ยอมรับตามค่าฐานเดิม)
4. วางลงบอร์ดจริง ต่อวงจรอย่างน้อยหนึ่งวงจรที่ใช้ชิ้นนั้น ดูค่าอ่านและลองให้พัง (เกินพิกัด) เห็นข้อความอธิบาย
5. ถ่ายภาพจาก gallery ให้ผู้ใช้ดู; แก้ตามที่ผู้ใช้ติ ทำซ้ำข้อ 3–5 จนผู้ใช้อนุมัติ
6. เมื่อผู้ใช้อนุมัติ: เปลี่ยนสถานะใน style.md 1.2 และ 1.3 เป็น `approved`
7. commit แยกต่อชิ้น (ข้อความอังกฤษ ขึ้นต้นด้วยกริยา เช่น `add buzzer part ...`) ไม่ push จนกว่าผู้ใช้สั่ง

> ตอนใช้ Browser pane ตรวจ: ห้ามสั่งรีโหลด/เปลี่ยนหน้าจากในสคริปต์ `javascript_tool` และห้ามรอนาน (สคริปต์จะค้างจนผู้ใช้ต้องกดหยุด) ใช้ `navigate` แยกครั้งแล้วค่อยรันสคริปต์สั้นๆ

## เครื่องมือที่มีใน repo

| อะไร | ใช้ทำอะไร |
|---|---|
| `src/parts/registry.test.ts` | ตรวจความครบ/ความสอดคล้องของทุกชิ้นอัตโนมัติ (รันกับ `npm run test`) |

## เครื่องใหม่ (clone แล้วเริ่มทำงาน)

```bash
git clone https://github.com/surakarn4327/dev-workspace   # monorepo เดียว
cd dev-workspace/wire-up
npm ci
npm run test          # ต้องผ่านทั้งหมดก่อนเริ่ม
npm run dev -- --port 5173   # แล้วเปิด /gallery.html
```

Node เวอร์ชันตาม `.nvmrc` ไม่ต้องติดตั้งอะไรเพิ่ม (ฟอนต์ Silver อยู่ใน `public/fonts`, ไม่มี asset ภายนอก)
