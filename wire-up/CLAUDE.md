# wire-up

> อยู่ใต้ธรรมนูญ `C:\dev\CLAUDE.md` — อ่านไฟล์นั้นก่อน กฎในไฟล์นี้ชนะเมื่อขัดกัน

## โปรเจกต์นี้คืออะไร

Wire-Up = lab ทดลองอิเล็กทรอนิกส์เสมือน สำหรับคนไม่มีเครื่องมือ/อุปกรณ์ หรืออยากจำลองก่อนต่อของจริง
หลักการเหมือนของจริงทุกอย่าง: breadboard, อุปกรณ์วัด, ชิ้นส่วนพังจริง, บทเรียนแบบภารกิจ
(แรงบันดาลใจ: Tiny Logic บน itch.io แต่ **ไม่ใช่** เกมไต่ transistor→chip, **ไม่มี** DOOM, **ไม่มี** ตัวละครครู)
คู่แข่งที่ต้องต่าง: Wokwi, Tinkercad Circuits, Falstad — จุดต่างคือ "พังจริง + อธิบายเป็นตัวเลข" และบทเรียนภารกิจ

## Requirement (ตกลงแล้ว 2026-10-07)

1. **ผู้ใช้**: มือใหม่ (บทเรียน = กล่องภารกิจ + เช็กลิสต์ + hint) และคนทำโปรเจกต์ (โหมด lab อิสระ)
2. **แพลตฟอร์ม**: เว็บบนคอม (desktop browser)
3. **โค้ดในเกม**: Arduino = C++, ESP32 = C++ หรือ MicroPython, มีโหมดต่อบล็อกที่แปลงเป็น C++ ให้ดู
4. **ต่อผิด = ชิ้นส่วนพังจริง** (ไหม้/ควัน ต้องเปลี่ยนชิ้นใหม่) + อธิบายสาเหตุเป็นตัวเลข (เช่น "LED รับ 85 mA เกินพิกัด 30 mA")
5. **การต่อ**: ได้ทั้งบน breadboard และลากสายอิสระบนจอ
6. **เครื่องมือวัด**: มัลติมิเตอร์, แหล่งจ่ายไฟปรับได้, Serial Monitor — **ไม่มี** ออสซิลโลสโคป
7. **ESP32 WiFi**: จำลองใน lab (ESP32 เปิดหน้าเว็บเล็กๆ กดปุ่มสั่ง pin ได้) ไม่ออกเน็ตจริง
8. **เซฟ**: auto-save ใน browser (localStorage) + export/import ไฟล์ — ไม่มีบัญชี ไม่มี server
9. **ภาษา UI**: อังกฤษอย่างเดียวก่อน
10. **เป้าหมาย**: ใช้เอง ยังไม่ตัดสินเรื่องเผยแพร่
11. **ภาพ**: pixel นีออนพื้นมืด แต่รูปทรง/ตำแหน่งขา/สีชิ้นส่วนตรงของจริง (แถบสี resistor อ่านค่าได้)
    วาดด้วยโค้ด Canvas ทั้งหมด ไม่ใช้ไฟล์รูป/asset ภายนอก
12. **v1 = วงจรไฟฟ้าก่อน**: แหล่งจ่าย/แบต, resistor, LED, switch, diode, transistor, breadboard,
    มัลติมิเตอร์, ระบบพังจริง **+ sensor แบบอนาล็อก** (LDR, thermistor, potentiometer — ผู้ใช้สั่งเพิ่ม 2026-10-07)
    บอร์ด Arduino/ESP32, Serial Monitor, โหมดบล็อก, WiFi = v2
13. **UI**: toolbox แบบแท็บด้านซ้าย (ลากชิ้นส่วนลงจอ), inspector + missions ด้านขวา

## สถานะ

**v1 เสร็จ (2026-10-07)** — solver, breadboard + สายอิสระ, 26 ชิ้นส่วน (แบต 4 ชนิดแยก, สวิตช์ rocker + สวิตช์เลื่อน, logic gate 7 ตัวแบบสัญลักษณ์ไม่มีขาไฟเลี้ยง), หน้าตาพิกเซลทุกชิ้น (ดู style.md), ระบบพังจริง, เซฟ, undo/redo, 9 mission
เทสต์ผ่านทั้งหมด (`npm run test`) และ build ผ่าน ดูรายละเอียดงานถัดไปใน README

## เทคนิค

- Vite + TypeScript `strict: true` + Canvas 2D (ไม่มี dependency runtime เลย; dev: vite, typescript, vitest)
- ตัวคำนวณ SPICE-style: **MNA** + Newton-Raphson (diode/LED/BJT Ebers-Moll, junction limiting `pnjlim`),
  source stepping เป็น fallback, ขีดจำกัดกระแสของ supply (โหมด CC) วนแก้ใน `solve()`
- DC + ตัวเก็บประจุตามเวลาจริง (ผู้ใช้สั่ง 2026-10-09: เวลาจริง ไม่มีปุ่มเร่ง ไม่มี mission): element `K` ใน solver คือวงจรเปิดตอน solve DC และเป็น backward Euler (`C/dt` ขนานแหล่งกระแส) เมื่อส่ง `Transient` ให้ `solve`; `advance(circuit, charge, seconds)` เดินเวลาแบ่งก้าวย่อยตามค่าคงที่เวลา RC เล็กสุด (`transientStep`, ไม่นับ ESR ที่ id ลงท้าย `:esr`) ไม่เกิน 200 ก้าวต่อเฟรม; ประจุของทุกตัวเก็บใน `Simulation.charge` (ตาม id, เริ่มที่ 0 ทุกครั้งที่เปิด/โหลดไฟล์, ไม่เซฟ); วงจรไม่มี C ใช้เส้นทาง solve เดิม ไม่ช้าลง — ความร้อนสะสมของชิ้นส่วนคำนวณแยกต่อเฟรมใน `Simulation.step`
- ไม่มี backend ทุกอย่างฟรีไม่ผูกบัตร (ธรรมนูญข้อ 4)

## คำสั่งที่ใช้จริง

```bash
npm run dev -- --port 5173   # รัน dev (พอร์ต 5173) หรือใช้ Browser pane: preview_start ชื่อ wire-up

```

## โครงสร้าง

```
src/
├── sim/         ← solver MNA (solver.ts), โมเดล/พิกัดชิ้นส่วน (models.ts) — ไม่แตะ DOM
├── board/       ← world (ข้อมูล+validate ไฟล์), connectivity (จุดซ้อนกัน = ต่อกัน → วงจร),
│                  simulation (solve + สะสมความเครียด/ไหม้), hit (ทดสอบการคลิก),
│                  follow (ของที่ตามเมื่อลาก/ย้ายกลุ่ม), group (กรอบเลือก, copy/paste กลุ่ม)
├── parts/       ← นิยามชิ้นส่วนละ 1 PartDef: pins, build (→ element solver), evaluate (→ stress), draw, fields
├── render/      ← renderer (กล้อง/สาย/ควัน), draw.ts (พาเลตนีออน, ตัวอักษร pixel), scene.ts
├── ui/          ← workspace (เมาส์/คีย์บอร์ด/loop), toolbox, inspector, lessonPanel, app (ประกอบทุกอย่าง)
├── lessons/     ← lessons.ts (9 mission data-driven) + lessons.test.ts (เฉลยของทุก mission)
└── save/        ← storage (autosave/export/import), history (undo/redo)
```

## กฎเฉพาะของโปรเจกต์นี้

- **sim แยกจาก UI เด็ดขาด**: `src/sim` ห้าม import อะไรจาก `render`/`ui`/`board`/`parts` เพื่อเทสต์ solver โดยไม่มี browser
- ความถูกต้องของฟิสิกส์มาก่อนความสวย: ค่าที่แสดง (V, A, Ω) ต้องมาจาก solver จริง ไม่ fake
- **หลักการต่อ:** จุดสองจุดที่ตำแหน่งตรงกันบน grid 20 px = ต่อกัน (ขาชิ้นส่วน, ปลายสาย, รูบอร์ด) — ทุกอย่างสแนป grid
  breadboard: รูในคอลัมน์เดียวกัน (5 รู) ต่อกัน, รางไฟยาวตลอดแถว
  **สายแตกกิ่ง:** ปลายสายที่วางทับ "กลางตัวสาย" เส้นอื่น (ไม่ใช่ขา/รู/ปลายสายเส้นนั้น) = เชื่อมเป็นเส้นเดียวกัน แสดงสีเดียวกับเส้นหลัก และถูกลบพร้อมชิ้นส่วนที่มันถูกลากมา — คำนวณจากตำแหน่งปลายสายล้วนๆ ไม่เก็บใน save (`board/wireJoin.ts`)
- **สายแตกกิ่งตามสายหลักเมื่อสายหลักถูกขยับ** (ผู้ใช้สั่ง 2026-10-08): ลากมุมของสายหลัก หรือลากชิ้นส่วนที่ทำให้ท่อนของสายหลักเลื่อน ปลายกิ่งที่วางอยู่บนท่อนนั้นเลื่อนตามไปบนท่อนใหม่ (กิ่งยาวขึ้น/สั้นลง) ยังต่อกันอยู่ — `board/branches.ts` (`branchEndsOf`, `slideEnd`, `carryBranches`) เรียกจาก `bend` ใน `ui/workspace.ts` และ `applyFollow` ใน `board/follow.ts`; ถ้าปลายกิ่งต้องขยับเฉียงกับท่อนแรกของกิ่ง (ท่อนที่มันนั่งอยู่หดสั้นกว่า) กิ่งเลี้ยวเพิ่มหนึ่งมุมให้ยังต่ออยู่ (`reattach`); ลากมุม/ปลาย/ชิ้นส่วนจนสายซ้อนทับตัวเอง `unfold` ตัดลูปทิ้ง; สายที่ยุบเป็นจุดถูกลบตอนปล่อย (`dropEmptyWires`); เทสต์สุ่ม `board/wireFuzz.test.ts` ต้องผ่านทุกครั้งที่แตะโค้ดรูปสาย; ลากมุมออกไปแล้วปล่อย แล้วลากมุมเดิมกลับมาที่จุดเริ่ม สายกลับเป็นรูปเดิมเป๊ะแม้ลากครั้งแรกจะตัดมุมที่ไม่จำเป็นทิ้ง (`BendMemo` ใน `board/wireEdit.ts`, จำต่อสาย ลืมเมื่อสายถูกแก้ทางอื่น)
- **สายไม่ทับตัวชิ้นส่วน (ยกเว้น breadboard ที่สายวิ่งบนได้):** เส้นทางอัตโนมัติ (`routeVia`) อ้อมกรอบชิ้นส่วน และตอนปรับรูปสายด้วยมือ (ลากมุม/ปลาย) ช่วงที่จะตัดผ่านกรอบถูกส่งให้ router อ้อมให้ (`wrapAround` ใน `ui/workspace.ts`) ส่วนมุมที่ถูกปล่อยลงกลางตัวชิ้นส่วนเลยไม่มีทางอ้อม = ไม่รับรูปนั้น — กรอบคำนวณใน `board/obstacles.ts` (ตัดขอบที่ครอบขาตัวเองออก ให้ต่อขาได้เสมอ); สายเก่าที่ทับอยู่แล้วยังปรับได้; สายใหม่ที่ปลายไปจบ/เริ่มกลางตัวชิ้นส่วนสร้างไม่ได้ (เส้นประเป็นสีแดง); **วางหรือย้ายชิ้นส่วนไปทับสายแล้ว สายไม่ขยับ** (ผู้ใช้สั่ง 2026-10-08: ปล่อยให้สายลอดใต้/ทับชิ้นส่วนตามลำดับชั้น ห้ามกลับไปจัดสายอัตโนมัติ); `board/untangle.ts` จัดเส้นทางใหม่เฉพาะสายที่ออกจากขาผิดทิศตามกฎ lead ด้านล่าง (เรียกตอนปล่อย/วาง/วาง-คัดลอก/ขยับด้วยลูกศร และตอนโหลดไฟล์; ข้ามสายที่มี `taps` หรือมีสายอื่นแตกกิ่งอยู่)
- **สายที่ต่อกับ bench supply เข้า/ออกจากเสา (post) จากด้านล่าง และสายที่ต่อกับแบตทุกชนิดเข้า/ออกจากขั้วจากด้านบนเสมอ** (ผู้ใช้สั่ง 2026-10-08; "บน/ล่าง" ตามทิศหมุนของชิ้นส่วน; หมวดที่ใช้กฎ: bench supply = ล่าง, แบตทุกชนิด = บน, สวิตช์ทุกชนิด (rocker, slide) = ด้านข้าง (ขาซ้ายออกซ้าย ขาขวาออกขวา) ยกเว้น push button ไม่บังคับ, ชิป 74HC = ออกจากตัวชิป (แถวบนขึ้น แถวล่างลง) — ตารางอยู่ที่ `leadDirs` ใน `board/obstacles.ts` เพิ่มหมวดใหม่ที่นั่น + แก้บรรทัดนี้): `routeVia(..., leads)` ก้าวออกไป 1 grid ตามทิศของขาก่อนแล้วค่อยหาเส้นทาง (`leadPins` ใน `board/obstacles.ts`) และ `untangle` จัดสายเก่าที่เข้าด้านข้างใหม่; ลากมุมสายด้วยมือยังเป็นอิสระ
- **ก๊อปวางทับของเดิมต้องไม่ต่อกันเอง** (ผู้ใช้สั่ง 2026-10-08 — ไม่ให้ต่อกันเองโดยไม่ตั้งใจ): ชิ้นส่วนจาก toolbox (ลากหรือคลิก) **วางแล้วต่อกันตามตำแหน่งปกติ ไม่มีกรอบแดง** (ผู้ใช้ต้องการเปลี่ยนอุปกรณ์เดิมได้); เฉพาะ **ก๊อปวาง** (ทั้งชุดรวมสาย) ที่ชนจะทั้งชุดขึ้นกรอบแดงและ **ถูกตัดจากวงจรอื่นทั้งหมด** (ต่อกันเองภายในชุดได้) จนกว่าจะลากออกพ้น — `world.isolated` (item → group) ใช้ namespace คีย์แยกใน `board/connectivity.ts`, ตรวจที่ `groupCollides` ใน `board/wireJoin.ts`, สายของอีกฝั่งไม่ตามชุดที่ถูกกักตอนลาก (`skip` ใน `board/follow.ts`); **ย้ายชิ้นส่วนเดิมไปทับปลายสายแล้วต่อกันเงียบๆ = ตั้งใจ** (ผู้ใช้ยืนยัน 2026-10-08) ห้ามเพิ่มการตรวจตอนย้าย
- ทุกชิ้นส่วน (ยกเว้น logic gate ที่เป็นสัญลักษณ์ ไม่มีวันไหม้ ผู้ใช้สั่ง 2026-10-08) มี **พิกัดสูงสุด** ใน `evaluate()` (คืน `stress.ratio` + ข้อความอธิบายตัวเลขจริง) — เกินเมื่อไรสะสมความร้อน
  แล้วพัง (ratio ≥ 6 พังทันที) ชิ้นที่พังแล้ว build เป็นวงจรเปิด (สวิตช์/ปุ่มจะเชื่อมค้าง) จนกว่าจะ Replace
- เพิ่มชิ้นส่วนใหม่: เขียน `PartDef` → ใส่ใน `ALL_PARTS` (`parts/index.ts`) → ทุกอย่าง (toolbox, inspector, เซฟ) ตามมาเอง
  ชิ้นส่วนที่มีขา "สายอ่อน" (ปัจจุบันมีแค่โพรบมัลติมิเตอร์; แบตเปลี่ยนเป็นขั้วคงที่ต่อสายแข็งแล้ว) ใช้ `freeLeads: true`; สถานะชั่วคราวของเมาส์ใช้ชื่อ param `pressed` (ไม่ถูกเซฟ)
- รูปทรง/ขา/สีต้องตรงของจริง (resistor color code, LED ขายาว=แอโนด + ด้านแบน=แคโทด, ขั้ว diode, pinout BC547 = C B E)
- **หน้าตาทั้งหมดอยู่ที่ [`style.md`](style.md)** (สถานะรายชิ้น `approved`/`draft` ดูตาราง 1.3) — อ่านก่อนแตะสี ฟอนต์ ขนาด หรือรูปอุปกรณ์ และแก้ไฟล์นั้นพร้อมโค้ดเสมอ
  สไตล์อุปกรณ์ทุกตัวยึดจาก **resistor** (ชิ้นที่สถานะ `draft` ใน style.md 1.3 ถือเป็นร่าง ห้ามลอก)
- **เพิ่ม/แก้ชิ้นส่วนต้องทำตาม [`PARTS.md`](PARTS.md) ทุกข้อ (ผู้ใช้สั่งเป็นมาตรฐานถาวร 2026-10-09)** — ใช้ `/new-part <ชื่อ>` ได้: อ่าน style.md 1.1/5 ก่อน → หาภาพอ้างอิงจริงแล้วให้ผู้ใช้เห็นก่อนวาด → โค้ดครบทุกไฟล์ในตาราง → `npm run test` ต้องผ่านรวม `src/parts/registry.test.ts` (บังคับ: มีแถวใน style.md 1.3, มี stress/เหตุผลที่ไม่มี, pin อยู่ในกรอบ, ชื่อสไปรต์มีจริง, ลงทะเบียน HANGING_LEG_PARTS/TALL_PARTS ครบ) → ดู `/gallery.html` 4 มุม pixel+vector + ปุ่ม Check label gaps → ให้ผู้ใช้ดูภาพ **Claude ตั้งสถานะ `approved` เองไม่ได้** (ใส่ `draft` จนผู้ใช้บอก) — ห้ามบอกว่าชิ้นส่วนเสร็จถ้าข้ามขั้นไหน ต้องบอกตรงๆ ว่าข้ามอะไร
- **ชิ้นส่วนใหม่ทุกชิ้นต้องตามมาตรฐานสไตล์/ป้าย/ระยะห่างเดียวกับของเดิม** (ผู้ใช้สั่งเป็นมาตรฐานถาวร): ทำตามเช็กลิสต์ `style.md` หัวข้อ 6 (ข้อ 11–12) และรัน `scripts/label-gap-harness.js` ก่อนจบงาน
- **ตำแหน่งป้ายทุกชนิดตามมาตรฐาน [`style.md`](style.md) 3.5:** ช่องว่าง `LABEL_GAP` เท่ากันทุกด้าน วัดจากขอบกล่องถึงขอบที่มองเห็นจริง, ป้าย + - และเลขขาต้องอยู่ที่ปลายขั้ว/ปลายขา, ห้ามฝังตำแหน่งเป็นตัวเลขตายตัว
- **logic gate ไม่มีขากราวด์:** อิงขั้ว − ของแหล่งจ่ายในวงจรเดียวกับมัน (`partRef` ใน `board/connectivity.ts`) ห้ามอิงโหนด 0 ตรงๆ ไม่งั้นพังเมื่อมีแบตหลายก้อน (ดู bugs.md); gate ไม่มีวันไหม้
- **ชิป 74HC แบบ DIP-14 (IC จริง)** (ผู้ใช้สั่ง 2026-10-08, อยู่คู่กับ gate สัญลักษณ์ ห้ามลบ gate เดิม): 74HC00 NAND, 02 NOR, 04 NOT, 08 AND, 32 OR, 86 XOR ใน `parts/ic.ts` — pinout ตาม datasheet (ขา 14 = VCC, 7 = GND, ขา 1 ซ้ายล่าง แถวขาห่าง 3 grid คร่อมร่องกลาง breadboard), ต้องต่อไฟเลี้ยงเอง (ขา VCC หรือ GND ที่ไม่มีอะไรต่ออยู่เลย = ชิปไม่ทำงาน เอาต์พุตลอย: `BuildCtx.wired`); องค์ประกอบ `C` ใน `sim/solver.ts` (Y ต่อ VCC/GND ผ่าน 50 Ω ตามตรรกะ, อินพุตตัดที่ครึ่งหนึ่งของไฟเลี้ยง, อนุพันธ์เชิงตัวเลข); พิกัดใน `HC` (`sim/models.ts`): ไฟเลี้ยงเกิน 7 V, เอาต์พุตเกิน 25 mA, VCC/GND เกิน 50 mA หรือต่อกลับขั้ว (ไดโอด substrate), อินพุตเกินช่วง GND..VCC จนไดโอดป้องกันของขานั้นรับกระแสเกิน 20 mA = ไหม้; **ขาอินพุตที่ไม่มีอะไรต่อเลยลอยจริง** (ผู้ใช้สั่ง 2026-10-09: ไม่เตือน ลอยจริง): ตัวแบ่งแรงดัน 2 MΩ ที่ค่าเดินไปมากลางไฟเลี้ยงตามเวลา (`drift` ใน `parts/ic.ts`) เอาต์พุตจึงกะพริบมั่วจนกว่าจะต่อขาเข้า + หรือ − ; netlist สร้างใหม่ทุก 0.2 วินาทีเมื่อมีขาลอย (`BuildCtx.animate`, `Netlist.animated`)
- **จอ 7-segment `seg7`** (ผู้ใช้สั่งเพิ่ม 2026-10-09): 1 หลัก 10 ขา (แบบ FND500, ขาห่างแถว 6 grid) แต่ละส่วนเป็น LED แดง ไหม้ที่ 30 mA ต่อส่วน เลือก common cathode/anode ได้ — `parts/display.ts`; ใช้คู่ 74HC ต่อเอาต์พุตผ่านตัวต้านทานต่อส่วน
- **คลิกชิ้นส่วนที่ไม่มีอะไรให้ปรับ ไม่เด้งแผงขวา** (ผู้ใช้สั่ง 2026-10-08): ชิ้นเดี่ยวที่ `fields()` ว่าง (gate, ชิป 74HC, แบต, ปุ่มกด, breadboard) ไม่เปิดแผงขวาและไม่สลับไปแท็บ Inspector ตอนเลือก (`followSelection` ใน `ui/app.ts`); ชิ้นที่มีให้ปรับ, สาย, และการเลือกเป็นกลุ่มยังเปิดแผงตามเดิม; ถ้าผู้ใช้เปิดแผงไว้เองก็ไม่ปิด

- **จุดกระแสไหลบนสาย** (ผู้ใช้สั่ง 2026-10-08): `board/flow.ts` คำนวณกระแสของสายแต่ละเส้นจากกระแสที่ชิ้นส่วนดึงที่ขา (เครือข่ายสายที่เป็นต้นไม้เท่านั้น: สายที่มีสายอื่นแตกกิ่งมาวางกลางตัวจะถูกตัดเป็นท่อนตรงจุดแตกกิ่ง แต่ละท่อนมีกระแสของตัวเอง; มีวนลูปหรือมีจุดเสียบ `taps` ของตัวเอง = ไม่มีจุด) เก็บใน `Simulation.flowParts` (`Simulation.flow` มีเฉพาะสายที่ไม่ถูกตัด); `Renderer.drawFlow` วาดจุดพิกเซลเคลื่อนตามทิศกระแส เร็วขึ้นตามกระแส (ไม่มีจุดถ้าน้อยกว่า 10 µA); gate สัญลักษณ์ไม่มีขาไฟเลี้ยง จุดจึงเริ่มที่ Y ส่วนชิปจริงจุดวิ่งเข้าทางขา VCC
