### คีย์ลัดตัวอักษรไม่ทำงานเมื่อเปิดแป้นพิมพ์ภาษาไทย
- **อาการ:** เปิดแป้นไทยแล้ว Ctrl+A/C/V/D, R, W, F, Ctrl+Z/Y, `[` `]` ไม่ตอบสนอง (ลูกศร/Delete/Esc ปกติ)
- **สาเหตุ:** โค้ดเทียบ `e.key` กับตัวอักษรละติน แต่แป้นไทยส่ง `e.key` เป็นตัวอักษรไทย (Ctrl+C = "แ")
- **วิธีแก้:** `keyName()` ใน `src/ui/workspace.ts` อ่านตัวอักษร/วงเล็บจากตำแหน่งปุ่ม `e.code` — คีย์ลัดใหม่ทุกตัวต้องผ่าน `keyName()` ห้ามใช้ `e.key` ตรงๆ กับตัวอักษร

### Push button ค้างกดหลังโหลดไฟล์เซฟ

- **วิธีแก้:** `World.load()` รีเซ็ตทุก param ชื่อ `pressed` เป็น `false` (`src/board/world.ts`) — ชิ้นส่วน momentary ใหม่ต้องใช้ชื่อ `pressed` ด้วย

### มุมมองแรกเข้าไม่ fit ตอนเปิดครั้งแรก

- **สาเหตุ:** `fitView()` ถูกเรียกใน `requestAnimationFrame` แรก ซึ่ง layout ของ canvas ยังไม่นิ่ง (ขนาด canvas ยังไม่ถูกวัด)
- **วิธีแก้:** หน่วง 80 ms ก่อนเรียก (`src/ui/app.ts`)

### Mission 6: สายจั๊มเสียบรูที่ไม่มีอยู่จริง
- **อาการ:** สายสีน้ำเงินของ mission "Current in series" ปลายไม่ต่อกับอะไร LED ไม่ครบวงจร
- **สาเหตุ:** อ้างแถว 8 ของ breadboard ซึ่งเป็นร่องกลาง (ไม่มีรู) — แถวที่มีรูคือ 0–1, 3–7, 10–14, 16–17
- **วิธีแก้:** เปลี่ยนไปต่อรางลบแถว 1 (`src/lessons/lessons.ts`) และเขียนเทสต์ที่สร้างเฉลยของทุก mission (`lessons.test.ts`) กันซ้ำ

### Mission 7: เช็กอัตราขยายไม่มีวันผ่าน
- **อาการ:** ต่อทรานซิสเตอร์ถูกต้องหมด LED ติด แต่ข้อสุดท้ายไม่ติ๊ก
- **สาเหตุ:** เงื่อนไข `Ic > 20 x Ib` แต่ทรานซิสเตอร์อิ่มตัว (LED+470R จำกัด Ic ≈ 14.5 mA, Ib ≈ 0.83 mA → อัตราส่วน ≈ 17) ทำให้ผ่านไม่ได้
- **วิธีแก้:** ลดเกณฑ์เป็น `> 10x` ที่ยังพิสูจน์ว่า "กระแสเล็กคุมกระแสใหญ่" ได้

### LED pixel ตอนดับมีพื้นที่ดำเป็นก้อน
- **อาการ:** สไปรต์ LED สถานะดับ ส่วนเงาตรงกลางและขวากลายเป็นสีดำสนิท
- **สาเหตุ:** `mix()` ใน `render/draw.ts` คืน `rgb(r,g,b)` แต่ parse อินพุตเป็น hex — เอาผลของ `mix` ไปผสมซ้ำจึงได้ NaN → ดำ
- **วิธีแก้:** แปลงฐานสีสถานะดับกลับเป็น hex ก่อนผสมต่อ (`ledSprite` ใน `src/parts/art.ts`)

### ขา LDR pixel ลอยห่างจากตัว
- **อาการ:** ขา 2 เส้นของ LDR อยู่ใต้ตัวกลมแต่ไม่แตะตัว
- **สาเหตุ:** ขาอยู่ที่ x = 0/40 แต่ตัวเป็นวงกลม ที่ตำแหน่งนั้นขอบวงกลมอยู่สูงกว่าก้นตัวมาก ขาที่เริ่มวาดจาก y = −10 จึงห่างจากตัว
- **วิธีแก้:** ให้ขาเฉียงเข้าไปซ่อนใต้ตัว (ผู้ใช้ขอขาเฉียง) วาดก่อนสไปรต์ให้ตัวบัง (`ldr` ใน `src/parts/passives.ts`) — ชิ้นส่วนกลมที่ขาไม่อยู่ตรงก้นต้องเช็กแบบเดียวกัน

### สายตามชิ้นส่วนแล้วจุดต่อ (taps) หลุดจากมุม
- **อาการ:** ย้ายชิ้นส่วน/บอร์ดที่มีสายต่ออยู่ แล้วบางครั้งสายมี `taps` ชี้จุดที่ไม่ใช่มุมของสายอีกต่อไป (fuzz เจอ 7 จาก 3000 ครั้ง)
- **สาเหตุ:** `followWire` เลื่อนปลาย `a` ไปทับจุด tap พอดี หรือ `tidy` ยุบมุมนั้นทิ้ง แต่ไม่ได้กรอง `taps` ตาม
- **วิธีแก้:** หลังจัดรูป กรอง `taps` ให้เหลือเฉพาะจุดที่ยังเป็นมุมใน `via` (`followWire` ใน `src/board/follow.ts`) — กฎ: `taps` ต้องเป็นสับเซตของ `via` เสมอหลังแก้รูปสายทุกครั้ง

### Logic gate ไม่ทำงานเมื่อมีแบตมากกว่า 1 ก้อนบนกระดาน
- **อาการ:** NOT gate ไฟสถานะเขียว (Y สูง) แต่ LED ที่ต่อกับ Y ได้กระแสแค่ ~12 nA ไม่ติด เกิดเมื่อมีแบต/supply อีกตัวบนกระดานที่ไม่ได้ใช้
- **สาเหตุ:** gate เป็นสัญลักษณ์ไม่มีขากราวด์ จึงอ้างอิงโหนด 0 ซึ่งคือขั้ว − ของแหล่งจ่าย "ตัวแรกในรายการชิ้นส่วน" ถ้าตัวแรกไม่ใช่แบตในวงจรเดียวกัน Y จึงไม่มีทางไหลกลับ
- **วิธีแก้:** gate อ้างอิงขั้ว − ของแหล่งจ่ายในวงจรเดียวกัน (`partRef` ใน `board/connectivity.ts`: โหนดที่เชื่อมกันผ่านชิ้นส่วนอื่น ไม่นับแหล่งจ่ายกับ gate) ไม่มีก็ใช้โหนด 0; `GateElement.ref` ใน `sim/solver.ts` — เทสต์ `gates.test.ts` "own circuit" — กฎ: ชิ้นส่วนที่ไม่มีขากราวด์ห้ามอิงโหนด 0 ตรงๆ

### ไฟล์ import ที่ถูกแก้มือทำให้ค่าผิดเงียบๆ / id ซ้ำ
- **อาการ:** ไฟล์ที่ใส่ตัวต้านทาน 0 หรือติดลบได้กระแส 0 แทนที่จะลัดวงจร, สายสองเส้น id เดียวกันผ่านการตรวจ, `counter` ต่ำกว่า id ที่ใช้อยู่ทำให้ชิ้นใหม่ id ชนของเดิม
- **สาเหตุ:** `validateWorldData` ตรวจแค่ชนิดข้อมูล ไม่ตรวจช่วงค่าตาม field ของชิ้นส่วน ไม่ตรวจ id สายซ้ำ ไม่ปรับตัวนับ id
- **วิธีแก้:** `sanitizeParams` (`parts/index.ts`) ดึงค่ากลับเข้าช่วงของ field (slider ตัดขอบ, ตัวเลือกต้อง > 0, toggle ต้องเป็น boolean ไม่งั้นใช้ค่า default) เรียกใน `save/storage.ts`; `validateWorldData` ปฏิเสธ id สายซ้ำและดัน `counter` ให้เกิน id ทั้งหมด — เทสต์ `save/storage.test.ts`

### จุดกระแสไหลของชิป 74HC ขึ้นบนสายอินพุตแทนสาย VCC
- **อาการ:** ต่อขาอินพุตของชิปเข้าขั้ว + ตรงๆ แล้วจุดกระแสไหลวิ่งบนสายอินพุต (ขา 1) แทนสายไฟเลี้ยง (ขา 14) ทั้งที่ขาอินพุตไม่ดึงกระแส
- **สาเหตุ:** `computeFlow` หาขาของชิ้นส่วนจากโหนดด้วย `nodes.indexOf(n)` ซึ่งคืนขาแรกที่อยู่บนโหนดนั้น ขา 1 กับขา 14 อยู่บนโหนดเดียวกัน (ต่อเข้า + ทั้งคู่) กระแสไฟเลี้ยงเลยถูกนับเป็นของขา 1
- **วิธีแก้:** กระแสที่องค์ประกอบ `C` ดึงจาก VCC/GND ผูกกับขา 14/7 ก่อนเสมอ (`board/flow.ts`) — เทสต์ "flowing dots run from the battery into VCC" ใน `board/ic.test.ts` — กฎ: ชิ้นส่วนที่หลายขาอาจอยู่โหนดเดียวกัน ห้ามหาขาจากโหนดด้วย `indexOf` เฉยๆ

### ภาพ pinout ของชิป: สายพาดทับสัญลักษณ์ gate และคำ VCC ถูกตัด
- **อาการ:** สายของ gate แถวบนพาดผ่าน gate แถวล่าง และคำ VCC เห็นแค่ครึ่งล่าง
- **สาเหตุ:** ตัวชิปสูงแค่ 88 แต่ต้องมี gate สองแถวพร้อมสายเข้า/ออก (ต้องการราว 92) สายเลยล้ำเข้าครึ่งของอีกแถว; canvas ไม่มีขอบบนพอสำหรับคำเหนือขา 14
- **วิธีแก้:** ตัวชิป 112 สูง แบ่งสองครึ่ง gate กับสายทุกเส้นของมันอยู่ในครึ่งตัวเอง (`GATE_Y`, `CHIP` ใน `ui/icSheet.ts`) และเลื่อนกรอบวาดให้เหลือขอบบน — กฎ: เปลี่ยนขนาดตัวชิปต้องเช็กว่าสองแถว gate ไม่ซ้อนกันในแนวตั้ง

### ข้อความสรุปของชิป 74HC ซ้ำชื่อรุ่น
- **อาการ:** แถบสถานะและ Inspector ขึ้น "74HC08 quad AND: 74HC08 quad AND: 4 gates..."
- **สาเหตุ:** `summary()` ใส่ชื่อรุ่นไว้แล้ว แต่ผู้เรียกใส่ชื่อชิ้นส่วนนำหน้าอยู่แล้ว
- **วิธีแก้:** `summary` ของชิปคืนแค่ "4 gates, VCC pin 14, GND pin 7" (`parts/ic.ts`)

### ป้ายค่า resistor ห่าง 4.7 ตอนหมุน 90°/270° (โหมดเวกเตอร์) และ harness รายงานผิด
- **อาการ:** `label-gap-harness` ได้ 4.7 ที่ resistor บางมุม และรายงานว่ากล่องป้ายของ gate เปลี่ยนรูปตอนหมุน
- **สาเหตุ:** resistor ตะแคงทำให้กล่องป้ายอยู่ข้างตัว คลุมช่วงกลางที่บางกว่าปลายมน แต่โค้ดวัดจากขอบปลายมน (−10); ส่วน gate: ตอนหมุน 270° ป้ายขาหนึ่งอันเลยขอบภาพของ harness (`OY` น้อยไป) จึงไม่ถูกนับ
- **วิธีแก้:** ใช้ −9.3 ตอนหมุนตะแคง (`parts/passives.ts`), `OY = 500` ใน `scripts/label-gap-harness.js` — กฎ: ผล harness ที่ "รูปเปลี่ยนตอนหมุน" ให้ตรวจก่อนว่าป้ายหลุดภาพ

### solver ใช้ 70–280 รอบเมื่อบนกระดานมีวงจรแยกกันหลายวงจร
- **อาการ:** แถบสถานะขึ้น "solved in 116 iterations" (ไฟล์ทดลอง 4 วงจรบนกระดานเดียว: สลับสวิตช์แล้วใช้ 66–279 รอบ ทั้งที่วงจรเดียวใช้ 3–8)
- **สาเหตุ:** วงจรที่ไม่ได้ใช้ขั้ว − ร่วมกับ "กราวด์อ้างอิง" (ขั้ว − ของแหล่งจ่ายตัวแรก) ถูกผูกกราวด์ด้วยตัวต้านทาน 1 GΩ เบาจนแรงดันรวมของวงจรนั้น (common-mode) แทบไม่ถูกบังคับ Newton เดินหลงทางนั้นช้า ยิ่งมีชิปที่อนุพันธ์เป็นเชิงตัวเลขยิ่งเห็นชัด (เห็นเหมือนกันแม้เพิ่มวงจรเล็กๆ อีกวงจรเดียว)
- **วิธีแก้:** `FLOAT_TIE` = 10 MΩ ใน `board/connectivity.ts` (รั่วแค่ 0.5 µA ที่ 4.5 V) ได้ 3–15 รอบ — กฎ: ตัวผูกกราวด์ของวงจรลอยต้องแรงพอให้ common-mode ไม่ลอยเลื่อน แต่อ่อนพอไม่รบกวนค่าที่แสดง

### ลากมุมสายหลักแล้วสายแตกกิ่งหลุด
- **อาการ:** เลื่อนท่อนของสายที่มีกิ่ง (เช่นสายแดงจากแบตที่แตกไปสวิตช์สองตัว) กิ่งค้างอยู่ที่เดิมกลางอากาศ สวิตช์หลุดจากวงจร (net เพิ่ม 35 → 37)
- **สาเหตุ:** การต่อกิ่งคำนวณจากตำแหน่งปลายสายที่ทับกลางตัวสายหลักล้วนๆ ไม่ได้ผูกกัน ตอนสายหลักเปลี่ยนรูป ไม่มีโค้ดขยับปลายกิ่ง
- **วิธีแก้:** `board/branches.ts` จำปลายกิ่งตอนเริ่มลาก แล้วเลื่อนไปบนท่อนใหม่ของสายหลักทุกเฟรม (ทั้งตอนลากมุมและตอนชิ้นส่วนลากสายตาม) — กฎ: โค้ดใหม่ที่เปลี่ยนรูปสายต้องเรียก `carryBranches`

### ลากมุมสายกลับมาตามตัวสายไม่ได้ (สายหดไม่ได้ ขยายออกได้อย่างเดียว)
- **อาการ:** ลากท่อนยาวของสายไปทางซ้ายได้ แต่ลากกลับมาทางขวาให้สั้นลงไม่ได้ สายค้างที่เดิม
- **สาเหตุ:** `moveBend` ลองเข้ามุมแบบแรก (แนวนอนก่อน) พอท่อนบนที่เหลือกลายเป็นพับกลับตัวเอง (ปลายท่อนบนเดิมอยู่เลยจุดที่ลากมาถึง) ก็ตัดสินว่า "ซ้อนตัวเอง" แล้วสลับไปเข้าแบบที่สอง ซึ่งผลคือสายกลับเป็นรูปเดิมทุกครั้ง ทั้งที่ `unfold` ตัดรอยพับนั้นทิ้งได้และมุมยังอยู่ตรงที่วาง
- **วิธีแก้:** ยอมรับแบบแรกถ้าตัดรอยพับแล้วมุมที่ลากยังเป็นมุมอยู่ (`moveBend` ใน `board/wireEdit.ts`) สลับไปแบบที่สองเฉพาะกรณีลากเลยปลายไกล — เทสต์ 'pulling a corner back along its own wire' — กฎ: ตัดสินว่ารูปไหนซ้อนตัวเองหลังตัดรอยพับแล้ว ไม่ใช่ก่อน

### สายซ้อนทับตัวเอง / กิ่งหลุด / ลากมุมไม่ไป (พบจากการสุ่มลากสายหลายพันครั้ง)
- **อาการ:** (1) ลากมุมหรือปลายสายแล้วสายวิ่งทับตัวเอง (1.5%) ทำให้ตัวแก้ไขไม่รับรูปและสายค้าง (2) ลากชิ้นส่วนแล้วสายที่ตามไปซ้อนทับตัวเอง (3) ปลายสายกิ่งหลุดเมื่อท่อนที่มันวางอยู่หดสั้นกว่าตำแหน่งของมัน (15–28% ของการลากแรงๆ) (4) ลากมุมไปวางบนแนวสายตัวเองแล้วสายไม่ขยับ (1%) (5) ลากชิ้นส่วนจนปลายสองด้านชนกัน เหลือสายยาวศูนย์ที่มองไม่เห็น
- **สาเหตุ:** (1,2) `unfold` ตัดเฉพาะรอยพับกลับตัว ไม่ตัดท่อนที่อยู่บนแนวเดียวกันแต่ไม่ติดกัน (3) ปลายกิ่งขยับได้เฉพาะตามแนวท่อนแรกของกิ่ง ถ้าต้องขยับเฉียงกับมันก็ปล่อยไว้ (4) `moveBend` ลองเข้ามุมได้แค่สองแบบจากมุมข้างเคียงเดิม (5) ไม่มีใครลบสายที่ยุบเป็นจุด
- **วิธีแก้:** `unfold` ตัดลูประหว่างสองท่อนที่ซ้อนกันเป็นเส้นตรงเส้นเดียว และใช้ใน `followWire` ด้วย; `board/branches.ts` `reattach` ให้กิ่งเลี้ยวหนึ่งมุมเมื่อต้องขยับเฉียง และ `slideEnd` มีทางเลือกสำรองเมื่อไม่เหลือท่อนทิศเดียวกัน; `moveBend` ถ้าไม่ได้มุมที่จุดวางจะลองตัดมุมวนข้างเคียงทิ้ง; `World.dropEmptyWires` ลบสายยาวศูนย์ตอนปล่อยเมาส์ — เทสต์สุ่ม `board/wireFuzz.test.ts` (ผ่านทุกข้อ: ไม่ซ้อนทับ มุมฉาก กิ่งยังต่อ) — กฎ: แก้โค้ดรูปสายต้องรันเทสต์สุ่มนี้

### เลือกสายหลายเส้นแล้วลากทั้งกลุ่ม กิ่งที่ไม่ได้เลือกไม่ตามไป
- **อาการ:** เลือกสายหลักแต่ไม่เลือกสายกิ่งที่วางกลางตัวมัน ลากกลุ่ม สายหลักไปแต่ปลายกิ่งค้างที่เดิม (หลุดจากสายหลัก)
- **สาเหตุ:** `applyFollow` กรณีสาย `whole` เลื่อนสายแล้ว `continue` ข้ามขั้นตอน `carryBranches` ของสายที่ตามแบบ `followWire`; และ `slideEnd` เก็บตำแหน่งตามแนวเดิมแบบสัมบูรณ์ เหมาะกับท่อนที่ยืด/หด ไม่เหมาะกับสายที่เลื่อนทั้งเส้น (ปลายกิ่งโดนหนีบเข้าขอบท่อนใหม่)
- **วิธีแก้:** `board/follow.ts` เก็บสาย `whole` ที่เลื่อนแล้ว แล้วเลื่อนปลายกิ่งที่วางบนมันด้วยระยะ (dx, dy) เท่ากันผ่าน `moveBranchEnd` (แยกออกจาก `carryBranches` ใน `board/branches.ts`) ข้ามกิ่งที่เป็น `whole` หรือ `skip` เอง — เทสต์ 'carries an unselected branch resting on a selected wire' ใน `board/group.test.ts`

### จอ 7-segment: ต่อแค่ขาส่วนเดียว ปล่อยขา COM ลอย แล้วเกมกระตุก ขึ้น "solver did not converge"
- **อาการ:** ต่อแบตเตอรี่ + ผ่านสวิตช์และตัวต้านทานเข้าขา 1 (หรือขาส่วนอื่น) ของจอ โดยไม่ต่อขา COM และไม่ต่อขั้ว − ของแบต เกมกระตุกหนัก มุมขวาล่างขึ้น "solver did not converge"
- **สาเหตุ:** ขา COM ลอย มี LED 8 ดวงรวมที่ COM โดยทุกดวงมีแค่ GMIN (1e-12) ต่อลงกราวด์ Newton หาแรงดันของโหนดลอยที่มีแต่ไดโอดไม่ลงตัว วนครบ 150 รอบ + source stepping 20 ขั้น (ราว 2800 รอบต่อเฟรม ~16–20 ms)
- **วิธีแก้:** `parts/display.ts` ใส่ตัวต้านทานรั่ว 10 MΩ ระหว่างขาแต่ละส่วนกับ COM ของหลักนั้น (พลาสติกไม่ใช่ฉนวนสมบูรณ์ เหมือน `leak` ของชิป 74HC) — เทสต์ `board/seg7-floating.test.ts` (ต่อขา 1, 4, 7 ของจอ 1 และ 4 หลัก ต้อง converge ภายใน 60 รอบ) — กฎ: ชิ้นส่วนที่มีหลาย LED/ไดโอดรวมที่ขาเดียว ต้องมีทางรั่วให้โหนดลอยเสมอ

### จุดกระแสไหลบนสายที่โยงขาของจอ/ชิปเข้าด้วยกัน เห็นแค่ขาเดียว สายอื่นไม่มีจุด
- **อาการ:** ต่อขาส่วนต่างๆ ของจอ 7-segment เข้าด้วยกันด้วยสาย แล้วป้อนไฟทางขา 1 จุดกระแสวิ่งแค่สายที่เข้าขา 1 สายที่โยงขาอื่นไม่มีจุดเลย ทั้งที่ทุกส่วนติดและมีกระแสจริง
- **สาเหตุ:** `board/flow.ts` ตัดสินว่ากระแสของ element เป็นของขาไหนจากหมายเลขโหนดอย่างเดียว เมื่อโยงหลายขาเป็นโหนดเดียวกัน กระแสทุกส่วนถูกนับให้ขาแรกที่ใช้โหนดนั้น ขาอื่นเลยไม่ดึงกระแส สายที่โยงจึงไม่มีกระแสให้แสดง
- **วิธีแก้:** element ชนิด R และ D มีฟิลด์ `pinA` / `pinB` (หมายเลขขาของชิ้นส่วน) ให้ชิ้นส่วนบอกเองว่ากระแสนี้เป็นของขาไหน `parts/display.ts` ใส่ให้ครบ `flow.ts` ใช้เมื่อมี — เทสต์ 'charges each pin of a display its own current when the pins are wired together' — กฎ: ชิ้นส่วนที่ผู้ใช้อาจโยงหลายขาเข้าด้วยกัน (จอ ชิป) ต้องใส่ `pinA`/`pinB` ใน element ของตน (ชิป 74HC ยังใช้วิธีเดิม)

### ชิ้นส่วน (แบตเตอรี่) ไหม้เองตอนโหลดหน้าหรือแก้สาย ทั้งที่วงจรไม่ผิด
- **อาการ:** รีหน้าเกมแล้วแบตเตอรี่ไหม้ (เซฟเป็นชิ้นที่ไหม้แล้ว)
- **สาเหตุที่น่าจะเป็น (ยังไม่ได้เห็นไฟล์เซฟจริงของผู้ใช้):** ตอนโหลดไฟล์ ตัวคำนวณเริ่มจากศูนย์ (ไม่มี warm start) ถ้าวงจรนั้นคำนวณไม่ลงตัว ("solver did not converge") ผลที่ได้เป็นตัวเลขไร้ความหมาย กระแสพุ่งหลายแอมป์ `Simulation.step` เอาตัวเลขนั้นไปคิดความเครียด ratio ≥ 6 = ไหม้ทันที แล้ว autosave เก็บสถานะไหม้ไว้
- **วิธีแก้:** `Simulation.step` ไม่สะสมความร้อนและไม่ทำให้ชิ้นส่วนไหม้เมื่อ solve ล่าสุดไม่ converge (รอ solve ที่ converge) — เทสต์ 'does not burn anything on a solve that did not converge' ใน `board/board.test.ts` — กฎ: ห้ามตัดสินให้ชิ้นส่วนไหม้จากผลที่ไม่ converge

### ก๊อปวางวงจรซ้อนของเดิมแล้วลากออก มีสายยืดเชื่อมสองวงจร (แบตไหม้จากลัดวงจร)
- **อาการ:** ก๊อปวางวงจรทั้งชุดแล้วลากสำเนาออกจากของเดิม มีสายเส้นหนึ่งยืดข้ามระหว่างสองวงจรและต่อเข้าด้วยกัน แบตเตอรี่ของวงจรเดิมไหม้ (กระแส 5.9 A)
- **สาเหตุ (ที่น่าจะเป็น ยังไม่ได้เห็นไฟล์เซฟจริง):** `groupCollides` ตรวจเฉพาะขา/ปลายสายที่ทับกัน ไม่ตรวจกรณีปลายสายของฝั่งหนึ่งวางบน "ตัวสาย" ของอีกฝั่ง (การเชื่อมแบบสายแตกกิ่ง) สำเนาที่วางเยื้อง 2 grid ทับสายเดิมจึงเกิดการเชื่อมแบบนี้โดยไม่ถูกกักเป็นกรอบแดง พอลากสำเนาออก สายที่แตกกิ่งอยู่ก็ตามไปยืดเป็นสายเชื่อมสองวงจร
- **วิธีแก้:** `groupCollides` เพิ่มเงื่อนไขนี้ทั้งสองทิศ (ปลายสายของชุดบนตัวสายนอกชุด และปลายสายนอกชุดบนตัวสายของชุด) สำเนาจึงถูกกักจนลากพ้น — เทสต์ใน `board/group.test.ts` ('a pasted group laid over a wire')

### ก๊อปวางวงจร ลากออก แล้วกด Undo สำเนากลับไปทับของเดิมและลัดวงจร
- **อาการ:** ก๊อปวางวงจร (สำเนาถูกกักเป็นกรอบแดงแล้วลากออกได้ปกติ) พอกด Undo สำเนาเด้งกลับไปอยู่ทับของเดิม ต่อติดกันและช็อต (ชิ้นส่วนไหม้)
- **สาเหตุ:** สถานะ "ถูกกัก" (`holdGroups` ใน `ui/workspace.ts`) ไม่ได้อยู่ในขั้น undo (snapshot เก็บแค่ตัวโลก) พอ Undo กลับไปขั้นที่เพิ่งวาง ตำแหน่งสำเนากลับมาทับของเดิมแต่ไม่มีใครบอกว่าชุดนี้ต้องถูกกักอยู่ จึงต่อกับของเดิมเงียบๆ
- **วิธีแก้:** snapshot ของ undo/redo เก็บรายการชุดที่ถูกกักไว้ด้วย (`App.snapshot()` เก็บ `{ world, holds }`) ตอน Undo/Redo เรียก `Workspace.importHolds` ใส่กลับ ชุดที่ไม่ได้ทับอะไรแล้วจะถูกปล่อยเองในเฟรมถัดไป (ไฟล์เซฟและ Export ไม่เปลี่ยนรูปแบบ)

### วงจรใหญ่ (สายเป็นร้อยเส้น) กระตุก หน่วง ทั้งที่ solver แค่ ~2 ms
- **อาการ:** วงจรจอ 7-segment 4 หลัก + ตัวต้านทานเป็นสิบ + สาย 100+ เส้น ลากหรือเลื่อนแล้วกระตุกหนัก ลบวงจรแล้วลื่น (status ขึ้นแค่ 126 nets, 2 iterations)
- **สาเหตุ:** solver ไม่ใช่ตัวช้า (วัดแล้ว: ทั้งสร้าง netlist+แก้+flow ~5 ms และทำเมื่อวงจรเปลี่ยนเท่านั้น) ตัวช้าคือโหมดพิกเซลคำนวณ `cableShape(wirePath(w))` (rasterize + Set/Map ของพิกเซลทุกเม็ด) ใหม่ **ทุกเฟรมทุกเส้น** — สาย 133 เส้นกิน ~175 ms ต่อเฟรม; รูปทรงสายเป็นฟังก์ชันของพิกัดล้วนๆ ไม่ต้องคำนวณซ้ำ
- **วิธีแก้:** `render/pixelwire.ts` จำ shape ตามพิกัดที่ปัดแล้ว (`remember`, เคลียร์เมื่อเกิน 2000 รายการ) ทั้ง `cableShape` และ `junctionShape` เฟรมถัดไปเหลือ ~0.1 ms — กฎ: ห้ามทำงานที่เป็นฟังก์ชันของข้อมูลคงที่ใหม่ทุกเฟรมใน `Renderer.draw` ถ้าทำได้ให้ cache ตามกุญแจของข้อมูล

### ยังกระตุกหลัง cache สาย: วงจรที่มีตัวเก็บประจุแก้ solver ทุกเฟรม และลากอะไรก็แก้ใหม่ทั้งก้อน
- **อาการ:** ไฟล์ 7-segment 5 หลัก (127 โหนด, ตัวเก็บประจุ 2 ตัววางลอยไม่ได้ต่ออะไร) ยังกระตุกทั้งตอนอยู่เฉยๆ และตอนลากสาย/ชิ้นส่วน
- **สาเหตุ:** (1) `Simulation.step` เรียก `advance` ทุกเฟรมทันทีที่วงจรมีตัวเก็บประจุสักตัว แม้ประจุหยุดนิ่งแล้ว = Newton + Gauss เต็มก้อน 4-10 ms ทุกเฟรม (2) `refresh` แก้ solver ใหม่เต็มๆ (20-80 ms) ทุกครั้งที่ `world.version` เปลี่ยน แม้การลากแค่ขยับรูปสายโดยวงจรไฟฟ้าเหมือนเดิมทุกอย่าง
- **วิธีแก้:** `board/simulation.ts` — (1) ธง `settled`: เมื่อประจุทุกตัวเปลี่ยนน้อยกว่า 1e-7 V ต่อเฟรม หยุดเดินเวลาจนกว่าวงจรจะเปลี่ยน (เฟรมนิ่งเหลือ ~0.03 ms) (2) เทียบ `JSON` ของ circuit + partPins + partRef กับรอบที่แล้ว ถ้าเหมือนเดิมและ solve ก่อนหน้า converge ให้ใช้คำตอบเดิม คำนวณใหม่แค่จุดกระแสบนสายกับค่าที่แสดง (ลากมุมสาย ~7 ms แทน ~40-80 ms) — กฎ: อย่าแก้ solver ใหม่เมื่อวงจรไฟฟ้าไม่เปลี่ยน, อย่าเดินเวลาเมื่อไม่มีอะไรเคลื่อนไหว; solver ยังเป็น dense Gauss O(n³) ถ้าวงจรใหญ่กว่านี้มากต้องทำ sparse

### ยังกระตุกในไฟล์ที่ไม่มีตัวเก็บประจุ: ส่วนวาดเฟรมละ 31 ms (วัดในเบราว์เซอร์จริง)
- **อาการ:** ไฟล์ 7-segment 5 หลัก สาย 86 เส้น ชิ้นส่วน 52 ชิ้น ไม่มีตัวเก็บประจุ ยังกระตุก ทั้งที่ solver เฟรมนิ่ง 0.02 ms ลากมุมสาย 7 ms
- **สาเหตุ:** วัดใน Browser pane ด้วยการห่อเมธอดของ `Renderer`: `draw` เฉลี่ย 31 ms (สูงสุด 223) แยกเป็น (1) `effectiveColors` 6.4 ms — O(N²) ต่อเฟรม (ทุกสายไล่หา `tapTarget` ผ่าน `wirePath` ของทุกเส้น) + `tapEnds` อีกสองรอบ ทั้งที่ผลขึ้นกับผังเท่านั้น (2) ทุกชั้นของสาย (เงา ขอบ สามเฉด) วนเรียก `rect()` ทีละเซลล์ทุกเฟรม (`fillCells`) ~6 ms
- **วิธีแก้:** `Renderer.wireInfo` เก็บสีสาย/จุดแตกกิ่งตาม `world.version` (`render/renderer.ts`); `render/pixelwire.ts` เก็บแต่ละชั้นเป็น `Path2D` ติดกับ shape (`fillLayer`) วาดด้วย `fill(path)` ครั้งเดียว — วัดซ้ำ: `draw` เฉลี่ย 12 ms (สูงสุด 21), `drawWire` 0.02 ms ต่อเส้น เหลือหนักสุดคือ `drawPart` ~0.13 ms ต่อชิ้น — กฎ: ห้ามทำงานที่ขึ้นกับผังอย่างเดียวซ้ำทุกเฟรม ให้ cache ตาม `world.version`; ปัญหาประสิทธิภาพให้วัดจริงก่อนเดา (ห่อเมธอดด้วย performance.now ผ่าน `window.__wireup.ws.renderer`)

### สายแดงรอบนอกไม่มีจุดกระแสวิ่งเลย ทั้งที่กระแสไหลอยู่ (สายที่เสียบผ่านขาแล้วไปต่อ)
- **อาการ:** วงจร 7-segment ที่มีสายแดงรอบนอก (รางบน รางล่าง) จุดกระแสวิ่งขึ้นเฉพาะสายอื่น สายแดงรอบนอกทั้งเครือข่ายเงียบ
- **สาเหตุ:** `computeFlow` ใน `board/flow.ts` ทิ้ง **ทั้งเครือข่ายสาย** ถ้ามีสายแม้เส้นเดียวมี `taps` (มุมที่เสียบเข้าขา/รู แล้วสายไปต่อ เช่น เส้นที่เดินผ่านปลายตัวต้านทานแล้วเลยไปอีก) เพราะโค้ดเดิมถือว่า "ไม่รู้จะแบ่งกระแสยังไง" — เส้นเดียวที่ผู้ใช้เสียบกลางทางทำให้สายแดงทุกเส้นที่ต่อถึงกันหายหมด
- **วิธีแก้:** ตัดสายตามจุด `taps` เหมือนตัดตามจุดแตกกิ่ง (แต่ละท่อนมีกระแสของตัวเอง ปลายท่อนอยู่ที่ขา/รูซึ่งเป็นโหนดอยู่แล้ว) เลิกข้ามเครือข่าย — เทสต์ 'cuts a wire that is plugged in on the way' ใน `board/flow.test.ts` — กฎ: ห้าม "ไม่รู้ก็ข้ามทั้งกลุ่ม" ในโค้ดที่ผลต้องต่อเนื่อง ให้ตัดเป็นท่อนที่รู้ได้แทน

### สายพิกเซลทำให้เฟรมช้า ~23 ms บนการ์ดจอ Intel HD 520 ทั้งที่ JS ใช้ไม่ถึง 8 ms (วัดด้วยปุ่ม hide ของ Frame meter)
- **อาการ:** วงจร 7-segment ผู้ใช้ได้ 17 fps (เฟรม ~59 ms) ตอนนิ่ง ทั้งที่งาน JS ต่อเฟรมแค่ ~8 ms; Chrome ใช้ GPU เร่งอยู่ (chrome://gpu: Canvas hardware accelerated) แต่ GPU เป็น Intel HD Graphics 520
- **วัด (ผู้ใช้, วงจรเดียวกัน):** ไม่ซ่อนอะไร 58.9 ms | ซ่อน grid 58.0 | ซ่อน parts 60.4 | **ซ่อน wires 36.1** | ซ่อน dots 54.7 — สายคือตัวลงสีช้าสุด (~23 ms), จุดกระแส ~4 ms, ชิ้นส่วนกับกริดแทบไม่กิน; ยังเหลือฐาน ~30 ms ที่ยังหาที่มาไม่เจอ (ต้องวัด "ซ่อนทั้งสี่")
- **สาเหตุ:** สายหนึ่งเส้นคือสี่เหลี่ยมหนึ่งพิกเซลหลายพันอัน ถูกยัดเป็น `Path2D` เดียวต่อชั้นสี (5 ชั้นต่อเส้น) ทุกเฟรม GPU เล็กจัดการ path ที่ประกอบจากสี่เหลี่ยมนับพันได้ช้า (JS แค่สั่งไม่กี่คำสั่ง จึงไม่เห็นในเวลา JS)
- **วิธีแก้:** `render/pixelwire.ts` วาดสายลงภาพเล็กสองใบต่อ (รูปทรง, สี) ครั้งเดียว (ใบฐาน = เงา+ขอบ, ใบตัว = สามเฉดของตัวสาย) ความละเอียด 1 พิกเซลงานศิลป์ต่อ 1 พิกเซลภาพ (`cablePictures`) แล้วแต่ละเฟรมแค่ `drawImage` แบบไม่ทำให้เนียน — คมทุกระดับซูม (ตรวจที่ zoom 3), ไม่มีการยืดภาพ; สายที่กรอบใหญ่กว่า 400,000 พิกเซลกลับไปใช้ Path2D — กฎ: ปัญหาลงสีบน GPU อ่อนอย่าเชื่อเวลา JS ให้วัดด้วยปุ่ม hide ของ Frame meter

### ยังไม่ถึง 60 fps บน Intel HD 520 หลังแก้สาย — ทุกส่วนกินนิดหน่อย รวมแล้วเกินงบ 16.7 ms → ภาพสำรองที่ไม่ยืดภาพ
- **วัด (measure all, ผู้ใช้):** ไม่ซ่อน 22.2 ms (45 fps) | ซ่อนกริด 17.7 | ซ่อนชิ้นส่วน 17.7 | ซ่อนตัวสาย 16.7 | ซ่อนหัวโลหะสาย 19.9 | ซ่อนจุดกระแส 23.0 | แสดงทีละอย่าง (ตัวสายอย่างเดียว, หัวโลหะอย่างเดียว, ชิ้นส่วนอย่างเดียว) 16.7 ทั้งหมด — ไม่มีส่วนไหนช้าลำพัง แต่ทุกส่วนรวมกันเกินงบเฟรมของ GPU อ่อน (ตัวสายกินมากสุด ~5 ms, กริด/ชิ้นส่วน ~4.5 ms, หัวโลหะ ~2.3 ms)
- **วิธีแก้:** `render/renderer.ts` วาดชิ้นส่วน+สาย (ใต้จุดกระแส) และชิ้นส่วนชั้นบน ลงภาพสำรอง 2 ชั้นที่ใหญ่กว่าจอ (เผื่อขอบ 256 px) แล้วแต่ละเฟรมแค่ copy; จุดกระแส ส่วนที่เลือก ชิ้นที่กำลังวาง ควัน วาดสดเหมือนเดิม; หัวโลหะสายวาดด้วย `fillRect` ตรงๆ แทน `Path2D` — วัดในเบราว์เซอร์ผม (หน้าต่างอยู่เบื้องหลัง ตัวเลขหยาบ): เฟรมนิ่ง/เลื่อนจอ ~1.3 ms, วาดสดไม่ใช้ภาพสำรอง ~14 ms
- **ข้อห้าม (ผู้ใช้สั่ง):** ห้ามยืดภาพที่เก็บไว้ตอนซูม (ภาพแตก) และห้ามมีช่วงที่ของหายตอนเลื่อนเร็ว — ตอนซูม/ลาก/เลื่อนเกินขอบเผื่อ เฟรมนั้นวาดสดหรือวาดภาพสำรองใหม่ในเฟรมเดียวกันเสมอ ไม่ปล่อยให้ว่าง ไม่ยืดภาพ
- **กฎ (สำคัญ):** กุญแจของภาพสำรอง (`drawCached`) = `world.version`, `sim.stamp`, pixelMode, zoom, dpr, ขนาด, ชิ้นที่เลือก/ชิ้นที่ชี้ (ป้าย), สายที่เลือก, สวิตช์ hide ของ Frame meter — ถ้าเพิ่มอะไรที่วาดในชั้นสแตติกและขึ้นกับสถานะนอกรายการนี้ ต้องใส่ในกุญแจ ไม่งั้นภาพค้าง; ชิ้นที่ไหม้/ร้อน (`state.failed`/`heat`) ทำให้วาดแบบเก่าทั้งเฟรม (แอนิเมชันขึ้นกับเวลา); ปุ่ม "cache" ใน Frame meter ปิดภาพสำรองเพื่อวัดต้นทุนการวาดสด

### ลากทั้งวงจรกระตุกหนัก (เฟรมละ 260 ms ตอนเลือกทั้งหมด) เพราะรูปทรงสายถูกคำนวณใหม่ทุกเฟรม
- **อาการ:** ลากวงจร 7-segment ที่เลือกทั้งหมด (52 ชิ้น 86 สาย) ได้ 4 fps; ซ่อนสายแล้วลื่นขึ้นมาก (Frame meter: draw 131.7 ms → 19.6 ms, solve แค่ 5 ms)
- **สาเหตุ:** \`cableShape\`/\`junctionShape\` (\`render/pixelwire.ts\`) จำรูปทรงสายตาม **ตำแหน่งสัมบูรณ์** พอลากวงจร สายทุกเส้นเปลี่ยนตำแหน่งทุกเฟรม ที่จำไว้ใช้ไม่ได้ ต้อง rasterize สร้างรูปทรง+ภาพสายใหม่ทั้ง 86 เส้นทุกเฟรม (งานนี้เคยวัด: สาย 133 เส้น ~175 ms)
- **วิธีแก้:** จำรูปทรงตาม **รูปร่าง** (มุมทุกจุดเทียบกับจุดแรก) เก็บเซลล์แบบสัมพัทธ์ แล้ว \`place\` วางที่ตำแหน่งใหม่ (\`ox\`, \`oy\`) โดยใช้ path และภาพที่เก็บไว้ร่วมกัน สายที่แค่เลื่อนจึงไม่ต้องคำนวณใหม่; เทสต์ \`render/pixelwire.test.ts\` (เซลล์ตรงกับการคำนวณอิสระ, สายที่เลื่อนใช้รูปทรงเดิม) — กฎ: อะไรที่ cache ต้องไม่ใช้ตำแหน่งสัมบูรณ์เป็นกุญแจถ้าของนั้นถูกลากได้

### เลือกหลายชิ้น (เช่น เลือกทั้งหมด) แล้วกระตุกหนัก ลากเลือกก็กระตุก — ต้นเหตุคือกรอบสีฟ้า ไม่ใช่เอฟเฟกต์เบลอเพียงอย่างเดียว
- **อาการ:** เลือกทั้งวงจร (52 ชิ้น 86 สาย) เฟรมละ 54 ms; ปุ่ม selection ใน Frame meter ซ่อนกรอบสีฟ้าแล้วลื่นขึ้นมาก
- **ต้นเหตุ (วัดแล้ว):** กรอบเลือกของสายหนึ่งเส้นประกอบจากสี่เหลี่ยมพิกเซลหลายร้อยอัน (86 เส้น รวม ~56,000 อัน) วาดเป็น Path2D ทุกเฟรม เส้นทึบอย่างเดียวไม่มีเรืองแสงก็ 31 ms (ในเบราว์เซอร์ผม) และ \`shadowBlur\` ยิ่งแพงกว่าวาดธรรมดา ~4 เท่า (โตตามจำนวนและพื้นที่) **การรวมสายเป็น Path2D ก้อนเดียวแล้วเบลอครั้งเดียว ช้ากว่าเบลอทีละเส้น** (52 กรอบกระจาย: 9.4 เทียบ 5.4 ms) เพราะเบลอทั้งกรอบสี่เหลี่ยมที่คลุมทุกอัน; การแทนเบลอด้วยแสงฟุ้งหลายชั้นเป็น Path2D ก็ช้าพอๆ กัน (70.6 เทียบ 66.9 ms) — ตัวการจริงคือ "ฝูงสี่เหลี่ยมจิ๋วต่อเฟรม"
- **วิธีแก้:** วาดกรอบเลือก (สาย: \`selectionPicture\` ใน \`render/pixelwire.ts\`; ชิ้นส่วน: \`ringPictures\` ใน \`render/renderer.ts\`) ลงรูปเล็ก ขนาดพิกเซลงานศิลป์ ครั้งเดียว (เส้นสีฟ้า + แสงฟุ้งสองชั้น \`SELECT_GLOW_STEPS\` กว้างรวม 2 พิกเซลงานศิลป์ ไม่เบลอ) แล้วแต่ละเฟรมแค่ \`drawImage\` แบบไม่ทำให้เนียน; รูปของสายเก็บกับรูปทรงสาย (ใช้ร่วมกันเมื่อสายแค่เลื่อน), รูปของชิ้นส่วนเก็บตามวงแหวนของชนิดชิ้นส่วนและสี (4 รูปต่อวงแหวนตามจังหวะเส้นประเคลื่อน)
- **ลองแล้วเลิก:** ถ่ายรูป "ก้อนที่ลาก" เก็บไว้เลื่อนตามเมาส์ (ลากลื่นแต่ค้างตอนเริ่มลากและตอนปล่อยเพราะต้องถ่ายรูปใหม่สองรอบ) — โค้ดส่วนนี้ลบออกแล้ว ตอนบอร์ดเปลี่ยนทุกเฟรม (ลาก ซูม) วาดสดเสมอ ภาพสำรองใช้ตอนนิ่ง/เลื่อนจอเท่านั้น
- **กฎ:** อย่าวาดอะไรที่มีหลายร้อยชิ้นเล็กๆ (เซลล์พิกเซล) เป็น Path2D ทุกเฟรม ให้ทำเป็นรูปแล้ว drawImage; ก่อนแก้ประสิทธิภาพให้วัดด้วย Frame meter (ปุ่ม hide / measure all) ก่อน อย่าเดา

### ปลายโพรบมัลติมิเตอร์แตะสาย แล้วสายเปลี่ยนสี / ลบมิเตอร์แล้วสายหายตามไปด้วย
- **อาการ:** เอาปลายโพรบไปวางตรงปลายสายหรือจุดต่อ สายสีเขียวเปลี่ยนเป็นสีแดงของสายหลัก (หรือกลับกัน); ลบมิเตอร์แล้วสายท่อนนั้นหายไปด้วย
- **สาเหตุ:** ปลายโพรบถูกนับเป็น "ขา" ของมิเตอร์ใน `socketKeys` / `branchesOfParts` (`board/wireJoin.ts`) กฎสายแตกกิ่งจึงมองว่าปลายสายตรงนั้นถูกเสียบ (ไม่ใช่กิ่งที่วางบนตัวสาย) สีเลยเปลี่ยน และสายแตกกิ่งที่ปลายอีกด้านอยู่ที่ปลายโพรบก็ถูกนับว่า "ดึงมาจากมิเตอร์" เลยถูกลบพร้อมมิเตอร์
- **วิธีแก้:** ข้ามชิ้นส่วนที่เป็น `freeLeads` ใน `socketKeys`, `branchesOfParts` และ `groupCollides`; เทสต์ในกลุ่ม `meter probes only touch` ของ `board/wireJoin.test.ts` — กฎ: ของที่แค่ "แตะ" ห้ามนับเป็นการเสียบ/เป็นเจ้าของสาย (ค่าที่วัดยังอ่านจากโหนดที่ปลายโพรบแตะใน `connectivity.ts` เหมือนเดิม)

## ข้อควรระวังที่รู้ล่วงหน้า (ยังไม่เคยพัง)
- Solver: LED/diode ต้องใช้ `pnjlim` (junction limiting) ไม่งั้น Newton ระเบิดเมื่อต่อ LED ตรงกับแหล่งจ่าย และต้อง clamp `exp` ที่ 80 (LED สีน้ำเงิน Vf ≈ 3 V ถ้า clamp ต่ำกว่านี้ค่ากระแสผิด)
- ไฟล์ใช้ `erasableSyntaxOnly`: ห้ามใช้ parameter property (`constructor(private x)`), enum, namespace

## Relay module: green power LED on with GND unconnected, no current shown
- **Symptom:** VCC wired, GND left open, green LED lit; supply ammeter 0.000 A and no flow dots.
- **Cause:** the LED was drawn from the VCC pin voltage only (`v(vcc) - v(gnd)`, floating GND reads 0 V), and the board drew no current of its own, so there was nothing for the meter or flow to show.
- **Fix:** `src/parts/relay.ts` adds a 1.2 kΩ element `pw` between VCC and GND (the power LED branch); the green LED lights only when its current is >= 0.5 mA (`live.pw`). Open GND = no current = LED off.
- **Prevention:** `src/parts/behaviour.test.ts` drives each pin of every part alone and requires zero current and an unchanged drawing; the old relay code fails it. Same sweep fixed the plain LED, which glowed by about 1e-6 from solver leakage (now dark under 1 µA, `semis.ts`).

## Wire hooks back over its straight run out of a terminal
- **Symptom:** relay module wire went up 3 grid from a terminal, came back down 1 and then turned (a hook folded over itself), so the real straight run was only 2 grid.
- **Cause:** `routeVia` stepped out to the end of the straight run and then routed from there as if the run did not exist, so the cheapest path could step straight back into it. `untangle` only checked the first segment's direction, so saved hooks were never found.
- **Fix:** `src/board/router.ts` blocks the cells of the straight run for the route (`lane`); `src/board/untangle.ts` treats an end that doubles back on itself as wrong and re-routes it (also on load). Test in `src/parts/relay.test.ts`.
