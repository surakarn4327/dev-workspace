# bugs.md — agent-office

บันทึกบั๊กที่เจอและแก้จริง (ไม่ใช่ feature ใหม่) ต่อ 1 บั๊กจด 3 อย่าง:

1. **ชื่อ/อาการ** — ผู้ใช้เห็นหรือรายงานว่าอะไรผิดปกติ
2. **สาเหตุ** — root cause จริง และ pattern โค้ดที่เสี่ยงพังซ้ำ
3. **วิธีแก้** — แก้ยังไง อ้างไฟล์/บรรทัด/commit

ก่อนแก้จุดที่เคยมีปัญหา ให้ดูไฟล์นี้ก่อน

## 2026-10-02 — คูเรียร์อาจไม่ตื่นหลัง reset (หลุดจากการรีวิวโค้ด ยังไม่เคยถึงผู้ใช้)

- **อาการ**: หลังกด Reset คิวเอกสารไม่ถูกส่ง คูเรียร์นั่งเฉย
- **สาเหตุ**: loop ของคูเรียร์ `await` promise ที่เก็บ resolver ไว้ใน `this.wake` แล้วหลังตื่นสั่ง `this.wake = null` — แต่ loop ใหม่ (หลัง reset) ตั้ง `this.wake` ของตัวเองไปแล้ว loop เก่าจึงมาล้างทับ resolver ของ loop ใหม่ pattern เสี่ยง: ตัวแปร "กลไกปลุก" ร่วมกันหลายผู้รอ ที่ผู้รอล้างค่าเอง
- **วิธีแก้**: ผู้รอไม่ล้างค่าเอง ให้ผู้ปลุกเป็นคนล้าง (`kick()` ใน `src/sim/simulator.ts`) เทสต์ `jam queues several memos...` และ `reset cancels...` คุมไว้

## 2026-10-02 — Auto-answer ตอบคำถามแรกผิดหลัง Reset

- **อาการ**: กด Reset แล้วเปิด Auto-answer ชื่องานกลายเป็น "Beginners, friendly tone" แทนที่จะเป็นไอเดียงาน
- **สาเหตุ**: เลือกคำตอบสำเร็จรูปจากตัวนับ `chatSeq === 1` ซึ่งไม่ถูกรีเซ็ตตอน reset ทำให้คำถามแรกของงานถัดไปไม่ใช่ลำดับที่ 1 pattern เสี่ยง: ผูกพฤติกรรมกับตัวนับสะสมข้ามรอบ
- **วิธีแก้**: ให้แต่ละคำถามระบุคำตอบอัตโนมัติของตัวเอง (`auto` ใน `ask()` ที่ `src/sim/simulator.ts`)

## 2026-10-02 — กล่องแชทขยับขนาดตอนพิมพ์ข้อความ

## 2026-10-03 — `npm test` ค้างไม่จบหลังเทสต์ผ่านครบ

- **อาการ**: เทสต์ทุกข้อขึ้น ✔ แต่ `node --test` ไม่ออกจากโปรเซส (รอจน timeout)
- **สาเหตุ**: `MockOffice` ที่เปิด `ambient` สร้างลูป `setTimeout` ที่เกิดใหม่เรื่อยๆ (แม้หลัง `reset()` ก็สร้างลูปใหม่) ไม่มีใครหยุด timer จึงค้างตลอด pattern เสี่ยง: ลูปเบื้องหลังที่รีสตาร์ตตัวเองโดยไม่มีทางปิดถาวร
- **วิธีแก้**: เพิ่ม `dispose()` ใน `src/sim/simulator.ts` (หยุดทุกลูปและไม่สตาร์ตใหม่) เทสต์ที่เปิด ambient ต้องเรียกท้ายเทสต์ และเทสต์เดิมตั้ง `ambient: false`

## 2026-10-03 — ชื่อขั้นตอนภาษาไทยขาดกลางคำ / ปุ่มขั้นตอนล้นกล่อง HUD บนจอแคบ

- **อาการ**: โหมดไทยบนจอ 375px ชื่อขั้นตอนปัจจุบัน ("รับบรีฟ") ตัดเป็น 2 บรรทัดกลางคำ และ pip ขั้นที่ 7 หลุดออกนอกกล่อง HUD
- **สาเหตุ**: ภาษาไทยไม่มีช่องว่างคั่นคำ เบราว์เซอร์จึงตัดบรรทัดตรงไหนก็ได้ และแถว `.steps` เป็น flex แบบไม่ wrap เมื่อชื่อขั้นตอนยาวกว่าอังกฤษก็ดันล้น pattern เสี่ยง: กล่อง/ป้ายขนาดเล็กที่ออกแบบด้วยความกว้างของคำอังกฤษ
- **วิธีแก้**: `.step .l { white-space: nowrap }` และ `.steps { flex-wrap: wrap; min-width: 0 }` (`src/style.css`) ตรวจตาจริงที่ 375px และ 1280px
## 2026-10-03 — โหมดไทย: กล่อง ปุ่ม ขนาดตัวอักษรเพี้ยน ลำดับขนาดหาย (ต่างจากอังกฤษที่พอดี)

- **อาการ**: หลังใช้ฟอนต์ Silver กล่อง/ปุ่ม/แผงข้างในโหมดไทยสูงเกินและดูไม่สมดุล ป้ายเล็ก ชิป หัวข้อ กลายเป็นขนาดเดียวกันหมด
- **สาเหตุ**: Silver เล็กกว่า Cascadia ที่ font-size เท่ากัน จึงแก้ด้วยการบังคับ `font-size: 24px !important` ทุก element (หลังลอง 16px แล้วเล็กไป) ซึ่งทำลายลำดับขนาดตัวอักษรที่ออกแบบไว้ และ line-height ที่คิดจากขนาดใหญ่ทำให้ปุ่มสูง 43px (อังกฤษ 31px) pattern เสี่ยง: แก้ปัญหาฟอนต์เล็กด้วยการบังคับขนาดทั่วทั้งหน้า
- **วิธีแก้**: ลบการบังคับขนาด ขยายเฉพาะกลิฟ Silver ด้วย `size-adjust: 162%` ใน `@font-face` ให้ x-height เท่า Cascadia ขนาดกล่องจึงเท่าอังกฤษ (ปุ่ม 31px, หัวข้อ 16px เหมือนกัน) (ลอง `font-size-adjust` ก่อนแล้วเลิก: `font:` shorthand ใน CSS เดิมรีเซ็ตมัน และมันขยายตัวอังกฤษด้วย) เทสต์ `core/font.test.ts` กันการบังคับขนาดกลับมา

## 2026-10-03 — ข้อความจาก Gemini ขาดกลางประโยค และคิดนานเกิน 10 วินาที

- **อาการ**: ลองกับ key จริงครั้งแรก (6g) Rex ถามว่า "ข้อความสรุปนี้มีกลุ่มเป" แล้วขาด และคำถามเดียวใช้เวลาคิดเกิน 10 วินาที
- **สาเหตุ**: ใช้รุ่น `gemini-flash-latest` (ตอนนี้ชี้ไป gemini-3.8-flash) ซึ่ง **คิดก่อนตอบ** ตามค่าเริ่มต้น และ **token ที่ใช้คิดนับรวมใน `maxOutputTokens`** (เอกสาร Google ระบุ) เราตั้งไว้แค่ 300 สำหรับคำถาม ภาษาไทยก็กิน token มากอยู่แล้ว ส่วนที่เหลือสำหรับคำตอบจึงหมดกลางประโยค (`finishReason: MAX_TOKENS`) และช่วงคิดนั้นก็คือเวลาที่รอ โค้ดเดิมนับ `MAX_TOKENS` ว่าปกติและส่งข้อความที่ขาดให้ผู้ใช้เลย เทสต์เดิมไม่เห็นเพราะโมเดลปลอมไม่เคยตอบแบบถูกตัด pattern เสี่ยง: ตั้งเพดาน token ต่ำกับโมเดลที่ "คิดก่อน" และถือว่าคำตอบที่ถูกตัดคือคำตอบสมบูรณ์
- **วิธีแก้**: (1) รุ่นเริ่มต้นเป็น `gemini-flash-lite-latest` (เบา เร็ว ค่าเริ่มต้นแทบไม่คิดนาน) (2) เพดานเป็น 800 token ต่อคำถาม และ 1,500 ต่อ brief (3) `complete()` ใน `src/ai/gemini-brain.ts`: ถ้าได้ `MAX_TOKENS` (หรือไม่ได้ข้อความเลย) ให้ถามซ้ำ 1 ครั้งด้วยเพดาน ×3 และไม่ส่งข้อความที่ถูกตัดไปให้ผู้ใช้ (4) `src/ai/gemini.ts` ส่ง `finishReason` กับจำนวน token ที่ใช้คิด (`thoughtTokens`) ออกมา เทสต์ใน `gemini-brain.test.ts` และ `gemini.test.ts` คุมไว้
