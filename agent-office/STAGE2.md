# ขั้น 2 — ต่อ agent จริงด้วย Gemini (แผนงาน)

> ร่างเมื่อ 2026-10-03 ตามที่ตกลงกับผู้ใช้ ยังไม่เริ่มลงมือ รออนุมัติ

## ข้อตกลงที่ล็อกแล้ว

- **โมเดล: Gemini อย่างเดียว** ใช้ API key ของผู้ใช้เองจาก Google AI Studio (ชั้นฟรี ไม่ผูกบัตร) ไม่ใช้ Ollama / Groq / OpenRouter ในขั้นนี้
- **เรียกจากเบราว์เซอร์ตรงๆ ไม่มี server** ผู้ใช้วาง key ในหน้าเว็บ เก็บใน `localStorage` (ห่อ try/catch) มีปุ่มลบ key
  - key ห้ามอยู่ใน bundle / repo / `.env` ที่ commit / คอนโซล / ฟีด / event ใดๆ
  - ไม่มี server จึงเขียนโฟลเดอร์งานลงดิสก์ไม่ได้ → เก็บงานในเบราว์เซอร์ + ปุ่มดาวน์โหลดผลลัพธ์
- **บริษัทเปล่า** ผลิตอะไรก็ได้ตาม brief ที่เจ้าของเก็บมา ไม่ผูกกับงานใดงานหนึ่ง (รอบนี้ผลิตได้เฉพาะงานที่เป็นข้อความ)
- **โมเดลสร้างข้อความอย่างเดียว** ลำดับ 7 ขั้น คิวผู้ส่งเอกสาร การตีกลับ 1–2 รอบ และ event เป็นหน้าที่ของโค้ดธรรมดา
- ข้อความดิบจากโมเดลส่งผ่าน `raw()` ข้อความของระบบยังใช้ `msg()` สองภาษา

## ความเสี่ยงที่ต้องตรวจก่อนเชื่อ

| เรื่อง | สถานะ |
|---|---|
| Gemini เรียกจากเบราว์เซอร์ได้ (CORS) | **ยังไม่ทดสอบ** → ทดสอบเป็นข้อแรก (งาน 1) |
| โควตาฟรีจริง (RPM / TPM / RPD ต่อรุ่น) | เอกสารทางการไม่ลงเลข เลขจากเว็บภายนอกไม่ตรงกัน → **ไม่ถามผู้ใช้** (ผู้ใช้กรอกแค่ key) ตัวคุมอัตราเรียนรู้จาก 429 เอง |
| ประมาณการ 20–30 คำขอ และ 60k–120k token ต่องาน | ประมาณเอง วัดจริงในขั้น 3 |
| ชั้นฟรีอาจให้ Google นำข้อมูลไปปรับปรุงผลิตภัณฑ์ | แจ้งผู้ใช้ในหน้าใส่ key |

## รายการงาน (ทำทีละข้อ แต่ละข้อมีเทสต์และ commit ของตัวเอง)

เทสต์ทุกข้อใช้ **โมเดลปลอม (fake model)** ไม่เรียกเครือข่ายจริง เพื่อไม่กินโควตาและไม่ผูกกับผลลัพธ์ของโมเดล

1. ✅ **ทดลองยิง Gemini จากเบราว์เซอร์** — เสร็จ 2026-10-03: ยิงด้วยค่าหลอกแล้วได้ HTTP 400 `API_KEY_INVALID` เป็น JSON อ่านได้ = CORS ไม่เป็นปัญหา (หน้าทดสอบลบทิ้งแล้ว) ส่วนเลขโควตา/รูปแบบ 429 จริงยังไม่ได้วัด รอ key จริง
2. ✅ **ช่องใส่ key ในเมนู** — เสร็จ 2026-10-03: ส่วน "ตั้งค่า AI" ในลิ้นชัก Menu (`ui/ai-settings.ts`, `core/ai-settings.ts`) วาง/บันทึก/ลบ key, ช่องล้างหลังบันทึก, ไม่แสดง key กลับ, ข้อความ en+th, เทสต์ 98 ข้อผ่าน สถานะยังเป็น "ยังไม่ได้ต่อเอเจนต์จริง" จนกว่าข้อ 3 เสร็จ
3. ✅ **`ModelClient` + Gemini adapter** — เสร็จ 2026-10-03 (`src/ai/`: `model-client.ts`, `gemini.ts`, `retry.ts`, `models.ts`; เทสต์ 123 ข้อด้วย fetch ปลอม) ยังไม่เคยยิง Gemini จริง: ชื่อรุ่นเริ่มต้น `gemini-flash-latest` และรูปแบบ error จริงต้องยืนยันตอนใช้ key จริงครั้งแรก 429 ส่งออกเป็น `ModelError{kind:'rate-limit', retryAfterMs}` ให้ข้อ 4 จัดการรอ — เดิมวางแผนไว้ว่า: อินเทอร์เฟซ `generate(prompt, history) → text` ที่ config ได้ต่อตำแหน่ง (`roster.ts` มีฟิลด์ `model` อยู่แล้ว ปัจจุบันเป็น MOCK ทุกตัว) จัดการ timeout, retry, 429 → ส่งสัญญาณ "รอโควตา"
4. ✅ **ตัวคุมอัตรา (rate limiter)** — เสร็จ 2026-10-03 (`src/ai/limiter.ts`) **ผู้ใช้ไม่ต้องกรอกเลขใดๆ นอกจาก key**: ทีละคำขอ เริ่มห่าง 6 วินาที ถูก 429 แล้วหยุดรอตามที่ Google บอก (+1 วิ) และช้าลง ×1.5 ส่วนสำเร็จติดกัน 8 ครั้งเร็วขึ้น ×0.85 (ไม่เร็วกว่า 4 วิ) ถ้า Google ขอรอเกิน 2 นาที (น่าจะโควตารายวันหมด) หรือรอครบ 3 รอบแล้ว จะปล่อย error ออกไปให้ออฟฟิศบอกผู้ใช้ มีสถานะ `idle / working / quota-wait` ให้ UI ดู (`limiter.status`, `onStatus`) ทุกตำแหน่งใช้ตัวเดียวกัน (`createModels`) — **ที่ยังไม่ทำ:** event/ภาพ "กำลังคิด" "รอโควตา" ในออฟฟิศ และปุ่มยกเลิกงานระหว่างรอ เลื่อนไปทำพร้อมข้อ 6 เพราะต้องมีตัวคุมงานจริงเรียกโมเดลก่อน (เปลี่ยน event ต้องแก้ตัวจำลองกับชั้นวาดพร้อมกัน)
5. ✅ **ขยาย `OfficeSource`** — เสร็จ 2026-10-03: `OfficeSource` มี `isRunning/start/reset` เพิ่ม ส่วนปุ่มทดลองแยกเป็น `DemoControls` (+ `isDemoSource`) ที่มีเฉพาะ `MockOffice` `main.ts` รู้จักแค่ `OfficeSource` และซ่อนปุ่มทดลอง (ความเร็ว, QA ตีกลับ, เอเจนต์ขัดข้อง, คูเรียร์ล้น, ตอบอัตโนมัติ — ติด `data-demo`) เมื่อแหล่งไม่ใช่ตัวจำลอง event ชุดเดิมไม่เปลี่ยน เทสต์ 137 ข้อ — เดิมวางแผนไว้ว่า: ตอนนี้ `main.ts` เรียกสมาชิกที่มีเฉพาะ `MockOffice` (`start`, `reset`, `isRunning`, `rejectNextReview`, `injectError`, `jam`, `setSpeed`, `autoAnswer`) ต้องแยกเป็นส่วนควบคุมร่วม (start/reset/isRunning) กับส่วนทดลองที่มีเฉพาะเดโม แล้วให้ UI ซ่อนปุ่มทดลองเมื่อใช้ของจริง — event ชุดเดิม ไม่เพิ่ม/เปลี่ยนรูปแบบถ้าไม่จำเป็น (ถ้าเปลี่ยนต้องแก้ตัวจำลองและชั้นวาดในงานเดียวกัน)
6. **เจ้าของ + เลขา: เก็บ requirement จริง** — เจ้าของถามกลับหลายรอบ (ข้อความดิบผ่าน `raw()`, ปุ่มตอบ `{id,label}` ยังใช้ได้) เลขาสรุปเป็น brief ผู้ใช้อนุมัติหรือขอแก้ก่อนไปต่อ (ขั้น 1–2 ของลำดับงาน)
7. **เทสต์เส้นทางเต็มด้วยโมเดลปลอม** — ขอแก้ brief, โมเดลตอบพัง/ว่าง, โดน 429, ผู้ใช้ยกเลิกกลางทาง; ขยาย `language-sweep` ให้ครอบคลุมสถานะใหม่ ห้ามมีข้อความหลุดภาษา/`{placeholder}`
8. **แผนกวิจัยจริง** — เจ้าของประชุมกับหัวหน้า หัวหน้าแตกงานให้ลูกน้อง 2 คน ลูกน้องทำ หัวหน้ารวมผล (ผู้ส่งเอกสารยังเป็นคิวโค้ดธรรมดา แอนิเมชันเดิม)
9. **แผนกผลิตงาน + ผู้ตรวจ + ส่งมอบ** — ผลิตตามผลวิจัยและ brief, ผู้ตรวจเทียบกับ brief (ตีกลับไม่เกิน 1–2 รอบ), เลขาสรุปส่งผู้ใช้, ปุ่มดาวน์โหลดผลลัพธ์/บันทึกการทำงาน
10. **เอกสาร** — อัปเดต `CLAUDE.md` (สถานะ/โครงสร้าง/กฎ key), `THIRD-PARTY.md` (Gemini API + เงื่อนไขชั้นฟรี), `bugs.md` เมื่อมีบั๊กจริง

## แผนย่อยข้อ 6 — เจ้าของ + เลขา เก็บ requirement จริง (ร่าง 2026-10-03 · ผู้ใช้ตัดสินใจครบทั้ง 4 ข้อแล้ว รอสั่งเริ่ม 6a)

### แนวคิดหลัก: แยก "ท่าทาง" ออกจาก "ถ้อยคำ"

ตอนนี้ `MockOffice` (`sim/simulator.ts`) ทำทั้งสองอย่างปนกัน: เดิน/นั่ง/ส่งเอกสาร/คิวคูเรียร์ (ท่าทาง) และตัดสินว่าใครพูดอะไร (ถ้อยคำ — ใน `runJob` ขั้น 1–2: `ask.idea → ask.audience → ask.limits → เลขาเขียน brief → ask.approve วนแก้ได้`)

ข้อ 6 ไม่เขียนออฟฟิศใหม่ แต่ **เปิดช่อง "สมอง" (`IntakeBrain`)** ให้ออฟฟิศเดิมเรียกตรงจุดที่ต้องมีถ้อยคำ:

- `ScriptedBrain` — ทำเหมือนเดิมเป๊ะ (ไม่มี key = เดโมเดิม เทสต์เดิมต้องผ่านโดยไม่แก้)
- `GeminiBrain` — ถามผ่าน `ModelClient` (ข้อ 3) ผ่านตัวคุมอัตรา (ข้อ 4)
- ขั้น 3–7 (ประชุม, ทีมทำงาน, QA, ส่งมอบ) **ยังเป็นสคริปต์** จนถึงข้อ 8–9 จึงปุ่มทดลอง (`DemoControls`) ยังใช้ได้ และไม่ต้องเพิ่มคลาสออฟฟิศตัวที่สอง

### จุดที่สมองต้องตอบ

| จุดในลำดับงาน | คนพูด | สมองต้องให้ |
|---|---|---|
| ผู้ใช้ตอบแล้ว ถามต่อหรือพอแล้ว | Rex | `ask(คำถามถัดไป)` หรือ `ready(ชื่องานสั้นๆ)` |
| ตอนจด brief | Sam | ข้อความ brief จากบทสนทนาทั้งหมด |
| ผู้ใช้ขอแก้ brief | Sam | brief ฉบับแก้ตามที่ขอ |

ข้อความจากโมเดลส่งออกเป็น `raw()` (ไม่แปล) ข้อความของระบบยังเป็น `msg()` สองภาษา ปุ่ม อนุมัติ/แก้ไข ยังเป็นของระบบ ตัวตัดสินว่าอนุมัติหรือยัง ยังใช้ `core/intent.ts` และปุ่มตามเดิม ไม่ให้โมเดลตัดสิน

### ลำดับย่อย (ทำทีละข้อ แต่ละข้อมีเทสต์ + commit)

- ✅ **6a ช่องสมอง** — เสร็จ 2026-10-03: `core/brain.ts` (`IntakeBrain`: `ownerTurn` / `writeBrief` / `reviseBrief`, ประวัติ `Exchange`), `sim/scripted-brain.ts` (เหมือนเดิมเป๊ะ) และ `MockOffice` รับ `brain` factory ต่อหนึ่งงาน (ค่าเริ่มต้น = สคริปต์) เทสต์เดิมทั้ง 137 ข้อผ่านโดยไม่แก้ + เพิ่ม 3 ข้อ (`sim/brain.test.ts` ด้วยสมองปลอม) ตรวจในเบราว์เซอร์จริงแล้วว่าเดโมถามลำดับเดิม ชื่องานขึ้นหลังคำตอบแรก brief ถูกประกอบจากคำตอบ — เดิมวางแผนไว้ว่า: ย้ายถ้อยคำขั้น 1–2 ออกเป็น `IntakeBrain` + `ScriptedBrain` พฤติกรรมเดิมทุกอย่าง เทสต์เดิมทั้งหมดผ่านโดยไม่แก้
- ✅ **6b คำสั่งประจำตัว + `GeminiBrain`** — เสร็จ 2026-10-03 (`ai/prompts.ts`, `ai/gemini-brain.ts`, เทสต์ 155 ข้อ ด้วยโมเดลปลอมทั้งหมด) คำถามแรก (คำทักทาย "ยินดีต้อนรับ...") เป็นข้อความตายตัว **ไม่เรียกโมเดล** คลิก Rex แล้วตอบทันที และนับเป็น 1 ใน 6 คำถาม จึงเรียกโมเดลถามต่อได้อีกไม่เกิน 5 ครั้ง + 1 ครั้งเขียน brief (+1 ต่อการขอแก้) `READY:` ต้องมีเครื่องหมาย `:` (หรือคำเดียวโดดๆ) เพราะคำถามที่ขึ้นต้นว่า "Ready to..." ต้องไม่ถูกนับว่าจบ ตอบยาวเกิน 700 ตัวอักษรขอย่อ 1 ครั้ง ยังยาวก็ตัดเอา brief ที่ได้ถูกล้าง markdown ข้อความของผู้ใช้อยู่ในบทสนทนาเท่านั้น ไม่เข้า system prompt ยังไม่ต่อเข้าหน้าจอ (ทำใน 6d) — เดิมวางแผนไว้ว่า: `src/ai/prompts.ts` (คำสั่งภาษาอังกฤษของ Rex กับ Sam, ให้ตอบเป็นภาษาเดียวกับผู้ใช้) Rex ตอบเป็นคำถามธรรมดา หรือขึ้นต้น `READY:` ตามด้วยชื่องาน (โมเดลเล็กไม่ต้องเขียน JSON) ถ้ารูปแบบเพี้ยนให้ขอซ้ำ 1 ครั้ง เพดานจำนวนคำถาม: ครบแล้วบังคับ `READY` — เทสต์ด้วยโมเดลปลอมที่ตอบตามสคริปต์
- ✅ **6c สถานะและความผิดพลาด** — เสร็จ 2026-10-03 (เทสต์ 166 ข้อ) event ใหม่ `chat.thinking` (+ `ChatPrompt.thinking`, กล่องแชทซ่อนช่องพิมพ์/ปุ่มด้วยคลาส `.thinking`), `MockOffice.think()` ห่อทุกการเรียกสมอง: คิดนานเกิน 250 ms (ตั้งได้ด้วย `thinkDelayMs`) จึงขึ้นกล่อง "กำลังคิด" / "รอโควตา AI" และ Rex ทำท่า thinking/waiting (เลขาใช้กล่อง "กำลังเขียนบรีฟ"), ✕ ระหว่างคิด = ยกเลิกทั้งงาน + `AbortSignal` ยกเลิกคำขอที่ค้าง (ผูกกับรีเซ็ตด้วย), โมเดลพังเมื่อลองซ้ำแล้ว = ถามด้วยปุ่ม ลองอีกครั้ง / ยกเลิกงาน ข้อความตามชนิดความผิดพลาด 9 แบบ (en+th), `IntakeBrain.watchWait` + `GeminiBrain` รับ limiter มาแจ้ง quota-wait สมองสคริปต์ไม่เคยแสดงกล่องคิด ตรวจในเบราว์เซอร์จริงด้วยสมองช้าปลอมแล้ว — แผนเดิม: ตัดสินแล้ว (ผู้ใช้เลือก "ให้มีทั้งคู่"): ระหว่างรอโมเดล (1) ตัวละครทำท่า `thinking` (ถ้ารอโควตา = `waiting` พร้อมโน้ต "รอโควตา AI") **และ** (2) กล่องแชทค้างอยู่ แสดง "Rex กำลังคิด..." ไม่มีช่องพิมพ์ และปุ่ม ✕ ยกเลิกได้ทันที (เรียก `cancel` เดิม) เพราะต้องเพิ่ม event ใหม่ `chat.thinking { id, from }` (store → `state.chat` มีธง `thinking`, กล่องแชทแสดงข้อความจากพจนานุกรม) ต้องแก้ **ตัวจำลอง + store + กล่องแชท + เทสต์ในงานเดียวกัน** ตัวจำลองส่ง event นี้เฉพาะเมื่อการคิดนานเกินราว 0.25 วินาที (สมองสคริปต์ตอบทันที จึงไม่กะพริบ) ทุกอย่างผ่าน `strings.ts` (en+th) ถ้าพังหลังลองใหม่แล้ว Rex ถามผู้ใช้ด้วยปุ่ม **ลองอีกครั้ง / ยกเลิก** (ข้อความเลือกตามชนิดความผิดพลาด: key ผิด, โควตาหมด, เน็ตมีปัญหา, ถูกบล็อก) กดรีเซ็ต/ยกเลิกแล้วคำขอที่ค้างอยู่ต้องถูกยกเลิกจริง (ผูก `AbortSignal` กับรอบการทำงาน) และไม่มี event หลุดหลังรีเซ็ต
- ✅ **6d เลือกสมองตอนเริ่ม** — เสร็จ 2026-10-03 (`ai/brain-factory.ts` `chooseBrain`, `roster.setLiveModels`, เทสต์ 170 ข้อ) มี key = `GeminiBrain` (Rex + Sam) ไม่มี = สคริปต์ ตัดสินตอนเริ่มงานแต่ละงาน ช่อง "โมเดล" ของ Rex/Sam แสดง `gemini-flash-latest` ระหว่างงานแล้วกลับเป็น `mock-script` เมื่อจบ/ยกเลิก ข้อความในเมนูตั้งค่า AI อัปเดตแล้ว **ทดสอบกับ Google จริงด้วย key หลอก:** เบราว์เซอร์เรียก Google ได้ ได้ `API_KEY_INVALID` จริง → Rex ขึ้นข้อความ "AI ไม่รับคีย์..." พร้อมปุ่ม ลองอีกครั้ง/ยกเลิกงาน (ยืนยันแล้ว: CORS, รูปแบบ error 400 ของ key ผิด) ที่ยังไม่ยืนยัน: ชื่อรุ่น `gemini-flash-latest` ใช้ได้จริงไหม, รูปแบบ 429 จริง, คุณภาพคำถามของ Rex — แผนเดิม: มี key ที่บันทึกไว้ = `GeminiBrain` ไม่มี = `ScriptedBrain` ตัดสินตอนเริ่มคำถามแรก (เปลี่ยน key กลางงานไม่กระทบงานที่กำลังทำ) ข้อความสถานะในเมนู "ตั้งค่า AI" เปลี่ยนจาก "ยังไม่ได้ต่อเอเจนต์จริง" เป็นบอกตรงๆ ว่า Rex กับ Sam ใช้ Gemini แล้ว ส่วนที่เหลือยังเป็นเดโม และช่อง "โมเดล" ในแผงตัวละครแสดงชื่อรุ่นจริง
- **6e เก็บบทสนทนากับ brief ไว้กับงาน** — เป็นข้อมูลในหน่วยความจำของงาน (ประวัติแชท + brief ล่าสุด) เพื่อให้ข้อ 8 ส่งต่อให้แผนกวิจัยได้ ยังไม่ทำปุ่มดาวน์โหลด (ข้อ 9)

- **6g ลองจริงกับ key ของผู้ใช้** — ผู้ใช้วาง key เองแล้วลองสั่งงานหนึ่งชิ้น ผมไม่เห็น key ผู้ใช้รายงานผล เพื่อยืนยัน 3 เรื่องที่ยังเดาอยู่: ชื่อรุ่น `gemini-flash-latest` มีจริงไหม, รูปแบบ error 429 จริง, จังหวะที่ตัวคุมอัตราตั้งไว้พอไหม แล้วแก้ตามที่พบ บันทึกบั๊กจริงลง `bugs.md`

### ความเสี่ยง

- โมเดลฟรีรุ่นเล็กอาจถามวนหรือไม่ยอมจบ → เพดานคำถามบังคับ `READY`
- ผู้ใช้พิมพ์คำสั่งแปลกๆ ใส่ในแชท (prompt injection) → Rex/Sam ไม่มีเครื่องมือใดๆ ผลเสียหายสูงสุดคือ brief เพี้ยน ซึ่งผู้ใช้เห็นและขอแก้ได้ก่อนอนุมัติ
- ใช้โควตา: ข้อ 6 ใช้ประมาณ 6–10 คำขอต่องาน (ก่อนถึงขั้นทีมทำงาน เพราะ Rex ถามได้สูงสุด 6 คำถาม)
