# ขั้น 2 — ต่อ agent จริงด้วย Gemini (แผนงาน)

> ร่างเมื่อ 2026-10-03 ตามที่ตกลงกับผู้ใช้ ยังไม่เริ่มลงมือ รออนุมัติ

## ข้อตกลงที่ล็อกแล้ว

- **โมเดล: Gemini อย่างเดียว** ใช้ API key ของผู้ใช้เองจาก Google AI Studio (ชั้นฟรี ไม่ผูกบัตร) ไม่ใช้ Ollama / Groq / OpenRouter ในขั้นนี้
- **เรียกจากเบราว์เซอร์ตรงๆ ไม่มี server** ผู้ใช้วาง key ในหน้าเว็บ เก็บใน `localStorage` (ห่อ try/catch) มีปุ่มลบ key
  - key ห้ามอยู่ใน bundle / repo / `.env` ที่ commit / คอนโซล / ฟีด / event ใดๆ
  - ไม่มี server จึงเขียนโฟลเดอร์งานลงดิสก์ไม่ได้ → เก็บงานในเบราว์เซอร์ + ปุ่มดาวน์โหลดผลลัพธ์
- **บริษัทเปล่า** ผลิตอะไรก็ได้ตาม brief ที่เจ้าของเก็บมา ไม่ผูกกับงานใดงานหนึ่ง (รอบนี้ผลิตได้เฉพาะงานที่เป็นข้อความ)
- **โมเดลสร้างข้อความอย่างเดียว** ลำดับ 7 ขั้น คิวผู้ส่งเอกสาร การตีกลับ 1–2 รอบ และ event เป็นหน้าที่ของโค้ดธรรมดา
- ข้อความดิบจากโมเดลส่งผ่าน `raw()` ข้อความของระบบยังใช้ `msg()` สองภาษา

## ความเสี่ยงที่ต้องตรวจก่อนเชื่อ

| เรื่อง | สถานะ |
|---|---|
| Gemini เรียกจากเบราว์เซอร์ได้ (CORS) | **ยังไม่ทดสอบ** → ทดสอบเป็นข้อแรก (งาน 1) |
| โควตาฟรีจริง (RPM / TPM / RPD ต่อรุ่น) | เอกสารทางการไม่ลงเลข เลขจากเว็บภายนอกไม่ตรงกัน → **ไม่ถามผู้ใช้** (ผู้ใช้กรอกแค่ key) ตัวคุมอัตราเรียนรู้จาก 429 เอง |
| ประมาณการ 20–30 คำขอ และ 60k–120k token ต่องาน | ประมาณเอง วัดจริงในขั้น 3 |
| ชั้นฟรีอาจให้ Google นำข้อมูลไปปรับปรุงผลิตภัณฑ์ | แจ้งผู้ใช้ในหน้าใส่ key |

## รายการงาน (ทำทีละข้อ แต่ละข้อมีเทสต์และ commit ของตัวเอง)

เทสต์ทุกข้อใช้ **โมเดลปลอม (fake model)** ไม่เรียกเครือข่ายจริง เพื่อไม่กินโควตาและไม่ผูกกับผลลัพธ์ของโมเดล

1. ✅ **ทดลองยิง Gemini จากเบราว์เซอร์** — เสร็จ 2026-10-03: ยิงด้วยค่าหลอกแล้วได้ HTTP 400 `API_KEY_INVALID` เป็น JSON อ่านได้ = CORS ไม่เป็นปัญหา (หน้าทดสอบลบทิ้งแล้ว) ส่วนเลขโควตา/รูปแบบ 429 จริงยังไม่ได้วัด รอ key จริง
2. ✅ **ช่องใส่ key ในเมนู** — เสร็จ 2026-10-03: ส่วน "ตั้งค่า AI" ในลิ้นชัก Menu (`ui/ai-settings.ts`, `core/ai-settings.ts`) วาง/บันทึก/ลบ key, ช่องล้างหลังบันทึก, ไม่แสดง key กลับ, ข้อความ en+th, เทสต์ 98 ข้อผ่าน สถานะยังเป็น "ยังไม่ได้ต่อเอเจนต์จริง" จนกว่าข้อ 3 เสร็จ
3. ✅ **`ModelClient` + Gemini adapter** — เสร็จ 2026-10-03 (`src/ai/`: `model-client.ts`, `gemini.ts`, `retry.ts`, `models.ts`; เทสต์ 123 ข้อด้วย fetch ปลอม) ยังไม่เคยยิง Gemini จริง: ชื่อรุ่นเริ่มต้น `gemini-flash-latest` และรูปแบบ error จริงต้องยืนยันตอนใช้ key จริงครั้งแรก 429 ส่งออกเป็น `ModelError{kind:'rate-limit', retryAfterMs}` ให้ข้อ 4 จัดการรอ — เดิมวางแผนไว้ว่า: อินเทอร์เฟซ `generate(prompt, history) → text` ที่ config ได้ต่อตำแหน่ง (`roster.ts` มีฟิลด์ `model` อยู่แล้ว ปัจจุบันเป็น MOCK ทุกตัว) จัดการ timeout, retry, 429 → ส่งสัญญาณ "รอโควตา"
4. ✅ **ตัวคุมอัตรา (rate limiter)** — เสร็จ 2026-10-03 (`src/ai/limiter.ts`) **ผู้ใช้ไม่ต้องกรอกเลขใดๆ นอกจาก key**: ทีละคำขอ เริ่มห่าง 6 วินาที ถูก 429 แล้วหยุดรอตามที่ Google บอก (+1 วิ) และช้าลง ×1.5 ส่วนสำเร็จติดกัน 8 ครั้งเร็วขึ้น ×0.85 (ไม่เร็วกว่า 4 วิ) ถ้า Google ขอรอเกิน 2 นาที (น่าจะโควตารายวันหมด) หรือรอครบ 3 รอบแล้ว จะปล่อย error ออกไปให้ออฟฟิศบอกผู้ใช้ มีสถานะ `idle / working / quota-wait` ให้ UI ดู (`limiter.status`, `onStatus`) ทุกตำแหน่งใช้ตัวเดียวกัน (`createModels`) — **ที่ยังไม่ทำ:** event/ภาพ "กำลังคิด" "รอโควตา" ในออฟฟิศ และปุ่มยกเลิกงานระหว่างรอ เลื่อนไปทำพร้อมข้อ 6 เพราะต้องมีตัวคุมงานจริงเรียกโมเดลก่อน (เปลี่ยน event ต้องแก้ตัวจำลองกับชั้นวาดพร้อมกัน)
5. ✅ **ขยาย `OfficeSource`** — เสร็จ 2026-10-03: `OfficeSource` มี `isRunning/start/reset` เพิ่ม ส่วนปุ่มทดลองแยกเป็น `DemoControls` (+ `isDemoSource`) ที่มีเฉพาะ `MockOffice` `main.ts` รู้จักแค่ `OfficeSource` และซ่อนปุ่มทดลอง (ความเร็ว, QA ตีกลับ, เอเจนต์ขัดข้อง, คูเรียร์ล้น, ตอบอัตโนมัติ — ติด `data-demo`) เมื่อแหล่งไม่ใช่ตัวจำลอง event ชุดเดิมไม่เปลี่ยน เทสต์ 137 ข้อ — เดิมวางแผนไว้ว่า: ตอนนี้ `main.ts` เรียกสมาชิกที่มีเฉพาะ `MockOffice` (`start`, `reset`, `isRunning`, `rejectNextReview`, `injectError`, `jam`, `setSpeed`, `autoAnswer`) ต้องแยกเป็นส่วนควบคุมร่วม (start/reset/isRunning) กับส่วนทดลองที่มีเฉพาะเดโม แล้วให้ UI ซ่อนปุ่มทดลองเมื่อใช้ของจริง — event ชุดเดิม ไม่เพิ่ม/เปลี่ยนรูปแบบถ้าไม่จำเป็น (ถ้าเปลี่ยนต้องแก้ตัวจำลองและชั้นวาดในงานเดียวกัน)
6. **เจ้าของ + เลขา: เก็บ requirement จริง** — เจ้าของถามกลับหลายรอบ (ข้อความดิบผ่าน `raw()`, ปุ่มตอบ `{id,label}` ยังใช้ได้) เลขาสรุปเป็น brief ผู้ใช้อนุมัติหรือขอแก้ก่อนไปต่อ (ขั้น 1–2 ของลำดับงาน)
7. ✅ **เทสต์เส้นทางเต็มด้วยโมเดลปลอม** — ทำรวมไปกับ 6c/6f แล้ว (ขอแก้ brief, โมเดลพัง/ว่าง, 429, ยกเลิกกลางทาง, ตรวจภาษาของสถานะใหม่)

### ทิศทางใหม่ (ตกลงกับผู้ใช้ 2026-10-03) — แทนข้อ 8–10 เดิม

เป้าหมายผู้ใช้: **สั่งบริษัทให้ทำได้แทบทุกอย่างใกล้เคียงแชท AI ใหญ่ (ยกเว้นสร้างรูปและรันโค้ด)** และ **อยากเห็น AI "มีชีวิต"** (ไม่ต้องเร็วเท่าแชท)
กฎที่ล็อกแล้ว:
- **ทุกคำสั่งผ่านบริษัทเสมอ** (เก็บ requirement → ผู้ใช้อนุมัติ brief → แผนก → ผู้ตรวจ → ส่งมอบ) ห้ามให้เจ้าของ "ตอบเอง" ลัดขั้น ความต่างอยู่ที่ขนาดทีม: เจ้าของเลือกเฉพาะแผนกที่งานนั้นต้องใช้ (งานเล็ก = วิจัย + ผู้ตรวจ)
- ความสามารถมาจากแผนก ไม่ใช่ทางลัดของเจ้าของ: วิจัยมีเครื่องมือค้นเว็บ/ข่าว/อ่านหน้า/อ่านไฟล์พร้อมแหล่งอ้างอิง, ผลิตเขียนงานยาวเป็นตอนและสร้างไฟล์ให้ดาวน์โหลด, ผู้ตรวจเทียบ brief และเช็กข้ออ้างที่ไม่มีหลักฐาน
- **ตัวช่วยในเครื่อง (local helper)** — เปลี่ยนจากแผน "ไม่มี server" เพราะเบราว์เซอร์ดึงเว็บ/ข่าวเองไม่ได้ (CORS) ตรวจแล้วจากเครื่องนี้: DuckDuckGo html ค้นเว็บได้ (10 ผล ไม่โดนบล็อก), Google News RSS ได้ข่าวสดวันนี้ (92 ข่าว), ดึงหน้าเว็บมาแปลงเป็นข้อความได้ (เราคุมจำนวนตัวอักษรเอง ไม่กินโควตาเหมือน `url_context`), ราคาตลาดจาก gold-api.com เรียกจากเบราว์เซอร์ได้ ตัวช่วยไม่แตะ API key (ผู้ใช้ยังกรอกแค่ key) เหมาะกับใช้ส่วนตัวบนเครื่องผู้ใช้ ถ้าจะแจกจ่ายต้องหาทางโฮสต์ภายหลัง ข้อเสีย: ค้นผ่าน DuckDuckGo เป็นการอ่านหน้าเว็บ (ไม่ใช่ API ทางการ) อาจโดนจำกัดหรือรูปแบบเปลี่ยน
- ข้อจำกัดที่บอกผู้ใช้แล้ว: ความฉลาดโมเดลฟรีเป็นเพดาน, โควตาจำกัดจำนวนงานต่อวัน, งานผ่านหลายคนจึงช้ากว่าแชทเดี่ยว

ลำดับงานใหม่:
8. **ตัวช่วยในเครื่อง + เอเจนต์ใช้เครื่องมือเองได้** — local helper (ค้นเว็บ, ค้นข่าว, อ่านหน้าเว็บเป็นข้อความ, ราคาตลาด; จองพอร์ตช่วง 8000–8099; จำกัดแค่ localhost; กัน SSRF) + function calling ของ Gemini ให้แผนกวิจัยตัดสินเองว่าจะค้น/อ่านอะไร ตอบพร้อมแหล่งอ้างอิงจริง
9. **แนบไฟล์เข้า + ดาวน์โหลดผลงานออก** — เบราว์เซอร์อ่านไฟล์ (ข้อความ, PDF) ให้ทีม, ผลงานเป็นไฟล์ (md/txt/html/csv ก่อน, docx ถ้าจำเป็น)
10. **แผนกวิจัยจริง** — เจ้าของประชุมหัวหน้า หัวหน้าแตกงานให้ลูกน้อง ลูกน้องใช้เครื่องมือข้อ 8 หัวหน้ารวมผลพร้อมแหล่งอ้างอิง (โปรโตคอลซื่อสัตย์: แยก แน่ใจ/ไม่แน่ใจ ห้ามแต่งตัวเลข/แหล่ง)
11. **แผนกผลิต + ผู้ตรวจ + ส่งมอบ** — เขียนงานยาวเป็นตอน ผู้ตรวจเทียบ brief และเช็กข้ออ้างที่ไม่มีหลักฐาน ตีกลับไม่เกิน 1–2 รอบ ใช้รุ่นฉลาดกว่าในขั้นยาก
12. **เจ้าของเลือกแผนกตามงาน** — ทีมเล็ก/ใหญ่ตามงาน
13. (ทีหลัง) แผนกเพิ่ม (วิเคราะห์ข้อมูล, แปล), งานตั้งเวลาทุกวัน (เช่น สรุปข่าวทอง)
14. **เอกสาร** — อัปเดต `CLAUDE.md` (สถานะ/โครงสร้าง/กฎ key/ตัวช่วยในเครื่อง), `THIRD-PARTY.md` (Gemini API + เงื่อนไขชั้นฟรี), `bugs.md` เมื่อมีบั๊กจริง

### ไอเดีย "ให้ AI มีชีวิต" ที่ผู้ใช้เลือก (2026-10-03) และจุดที่แทรกในลำดับ

เป้าหมายผู้ใช้: อยากเห็น AI มีชีวิต ไม่ต้องเร็ว — ทุกอย่างต้องผูกกับของจริง (การเรียกโมเดล, งานที่ทำ, แหล่งข้อมูล) ไม่ใช่ลูกเล่นลอยๆ และต้องได้คุณภาพภาพ/องค์ประกอบ/ข้อความสองภาษาระดับเดียวกับที่ผ่านมา (ตรวจตาจริงทุกชิ้น)

| รหัส | ไอเดีย | แทรกตรงไหน |
|---|---|---|
| L1 | **ห้องเซิร์ฟเวอร์ = การเรียก AI จริง**: ไฟกะพริบทุกครั้งที่ยิง Gemini/เรียกเครื่องมือ, ตอนรอโควตา เซิร์ฟเวอร์ร้อน (ควัน/พัดลม/ไฟแดง), ตัวช่วยในเครื่องมีไฟของตัวเอง | หลังข้อ 8 (ใช้สถานะ limiter + toolbox) |
| L6 | **ย้อนดูงาน (replay)**: บันทึกสายเหตุการณ์ของงาน เล่นย้อนเร่งความเร็วได้ (ช่วยดีบั๊กด้วย) | ต่อจาก L1 (ถูก เพราะทุกอย่างเป็นเหตุการณ์อยู่แล้ว) |
| L2 | **จอที่โต๊ะแสดงงานจริงแบบพิมพ์สด**: คลิกตัวละครเห็นข้อความที่โมเดลกำลังเขียน (ต้องมี streaming `streamGenerateContent`) | พร้อมข้อ 10 (แผนกวิจัยจริง) |
| L3 | **กระดานหลักฐานในแล็บวิจัย**: แหล่งข้อมูลจริงที่เจอถูกปักบนบอร์ด คลิกเปิดลิงก์ได้, ผู้ตรวจวงแดงข้ออ้างที่ไม่มีแหล่ง, งานส่งมอบมีตรา "ตรวจแล้ว N แหล่ง / ยังไม่ได้ตรวจกับแหล่งจริง" | พร้อมข้อ 10–11 |
| L4 | **นิสัย + ความจำของตัวละคร**: นิสัยประจำตัว, จำความชอบผู้ใช้ข้ามวัน (สรุปจากสิ่งที่ขอแก้บ่อย เก็บในเครื่อง ผู้ใช้ดู/ลบได้) | หลังข้อ 11 |
| (ไม่เลือก ไว้ทีหลัง) | จอ/ตลาดเลื่อนขั้น=เลื่อนโมเดล (5), เสียง 8-bit + TTS (7), รายงานเช้า (8) | รายการรอ |

### สถานะความคืบหน้า (2026-10-03)

- ✅ **8a–8c ตัวช่วยในเครื่อง** (`helper/`): guard กัน SSRF (IPv4/IPv6, ตรวจที่ตอน connect), fetcher บน `node:https` (fetch() ของ Node ถูก DuckDuckGo มองเป็นบอต เพราะเพิ่มหัว `sec-fetch-*`), extract (HTML → ข้อความ, JSON-LD, ตัดแถบแชร์), ค้นเว็บ DuckDuckGo + สำรอง Bing (ตรวจกับหน้าจริงแล้ว), ข่าว Google News RSS + ถอดลิงก์ข่าวเป็นลิงก์จริง, service (แคช/จำกัดอัตรา/พักเครื่องที่บล็อก — DuckDuckGo เริ่มตอบหน้า anti-bot หลังยิงทดสอบถี่ ~15 ครั้ง จึงจำเป็น), server + ปลั๊กอิน Vite เริ่มพร้อม `npm run dev` พอร์ต 8071 (จองใน launch.json กลาง + PROJECTS.md) เทสต์ 93 ข้อ

## ผลทดสอบ "แผนกวิจัยหาข้อมูลจากไหน" (2026-10-03, ลองจริงกับ key ฟรีของผู้ใช้)

ปัญหา: Gemini ตอบจากความรู้ในตัวเอง อาจล้าสมัยหรือผิด จึงลองเครื่องมือของ Google (ผ่าน `generateContent`, `tools: [...]`):

| ลอง | ผล | สรุป |
|---|---|---|
| ค้นเว็บ (`google_search`) กับ `gemini-2.5-*` | HTTP 404 "no longer available to new users" | ใช้ไม่ได้ |
| ค้นเว็บ (`google_search`) กับ `gemini-flash-latest` / `gemini-flash-lite-latest` | HTTP 429 "exceeded your current quota" ทันที ทั้งที่การเรียกธรรมดารุ่นเดียวกันผ่าน (HTTP 200) | **ค้นเว็บไม่รวมในแผนฟรี** (ตรงกับหน้าราคาที่ว่าโควตาฟรีอยู่ใต้แผนจ่ายเงิน = ต้องผูกบัตร ขัดกฎ) → ไม่ใช้ |
| อ่านลิงก์ (`url_context`) กับ `gemini-flash-lite-latest` | HTTP 200, `URL_RETRIEVAL_STATUS_SUCCESS`, ตอบประชากรกรุงเทพจากหน้าวิกิพีเดียได้ | **ใช้ได้ฟรี** |

ข้อมูลเพิ่มจากการทดลอง: 429 จริงของ Google มาแค่ข้อความ "You exceeded your current quota..." + ลิงก์ Help **ไม่มี `RetryInfo`** (ไม่บอกเวลารอ) ตัวคุมอัตราจึงต้องใช้ค่าเดา 15→30→60 วินาที (เป็นไปตามที่เขียนไว้แล้ว) และ 429 แบบนี้อาจแปลว่า "ฟีเจอร์นี้ไม่มีโควตาเลย" ไม่ใช่รอแล้วจะผ่าน — อย่าให้โค้ดไหนส่ง tool ที่ไม่รวมในแผนฟรีโดยไม่จำเป็น

**ลองต่อ: ให้เซิร์ฟเวอร์ Google ดึงข่าวแทน (`url_context` ไม่ผ่าน CORS ของเบราว์เซอร์)** — ผลจริง:
- เบราว์เซอร์ดึงตรงๆ ได้เฉพาะวิกิพีเดีย (GDELT, Google News RSS, Thai PBS RSS, Bangkok Post RSS ถูก CORS บล็อก)
- `url_context` อ่าน **หน้าเว็บข่าวปกติสดๆ ได้** (Bangkok Post หน้าแรก → พาดหัววันนี้ถูกต้อง, ใช้ tool-use ~6,700 token ต่อหน้า = กินโควตามาก)
- แต่ **อ่านผลค้นหา/ฟีด/API ไม่ได้ทุกเจ้าที่ลอง:** Google News RSS ("อ่านไม่ได้"), GDELT JSON (ERROR), Bing web, Bing News RSS, Yahoo News (ERROR), DuckDuckGo html (เจอหน้า anti-bot), Bing ไทย และหน้าค้นวิกิพีเดีย (ไม่มี metadata) → **ไม่มีวิธีค้นข่าวฟรีแบบอัตโนมัติ** ปิดเรื่องนี้ ไม่ลองซ้ำ

**ทางที่เหลือสำหรับข้อ 8 (ยังไม่ตัดสินใจ):** (1) โปรโตคอลซื่อสัตย์: แยก "แน่ใจ/ไม่แน่ใจ" ห้ามแต่งตัวเลข-วันที่-แหล่งอ้างอิง, QA ตรวจข้ออ้างที่ไม่มีหลักฐาน, งานมีหมายเหตุว่าไม่ได้ตรวจกับแหล่งจริงเมื่อไม่มีแหล่ง (2) อ่านลิงก์ที่ผู้ใช้ให้ด้วย `url_context` (ให้ Rex ถามหาลิงก์ครั้งเดียว) (3) ตัวเลือก: ดึงวิกิพีเดียผ่าน API ฟรี (ไม่ต้องใช้ key รองรับ CORS) สำหรับหัวข้อประเภทสารานุกรม ข่าวใหม่ๆ ยังหาแบบฟรีไม่ได้ ต้องบอกผู้ใช้ตรงๆ

## ข้อที่ยังเปิดอยู่

- ค่าเริ่มต้นของตัวคุมอัตรา (ห่าง 6 วิ / ต่ำสุด 4 วิ) เป็นการเดาแบบระวัง ปรับหลังวัดจริงในขั้น 3
- เลือกรุ่น Gemini ต่อตำแหน่ง (เช่น เจ้าของ/ผู้ตรวจรุ่นเก่งกว่า ลูกน้องรุ่นเล็ก) ตอนนี้ทุกตำแหน่งใช้ `gemini-flash-latest` ตัวเดียวกัน (ชื่อรุ่นยังไม่ยืนยันกับ key จริง)
- งานจริงชิ้นแรกสำหรับขั้น 3 — ผู้ใช้สั่งเองผ่านช่องแชทตอนทดลอง ไม่ต้องกำหนดล่วงหน้า
