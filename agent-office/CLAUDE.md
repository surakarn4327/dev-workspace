# agent-office

> อยู่ใต้ธรรมนูญ `C:\dev\CLAUDE.md` — อ่านไฟล์นั้นก่อน กฎในไฟล์นี้ชนะเมื่อขัดกัน

## โปรเจกต์นี้คืออะไร

"บริษัทเปล่า" ของ AI agent ที่แสดงเป็นออฟฟิศพิกเซล 8-bit ผู้ใช้สั่งว่าอยากผลิตอะไร บริษัทผลิตให้ตามลำดับชั้น

ลำดับการทำงาน (ออกแบบไว้ 2026-10-02):

1. ผู้ใช้บอกเจ้าของบริษัท (agent ใหญ่สุด) ว่าต้องการผลิตอะไร
2. เจ้าของเก็บ requirement จนตรงใจผู้ใช้ → **ผู้ใช้อนุมัติ brief ก่อนเริ่ม**
3. เจ้าของเลือกเฉพาะแผนกที่งานนี้ต้องใช้ แล้วประชุมกับหัวหน้าแผนก
4. หัวหน้าแตกงานให้ลูกน้อง
5. ลูกน้องทำงานตามตำแหน่ง
6. ส่งงานคืนหัวหน้า → ผู้ตรวจเทียบกับ brief (ตีกลับได้ไม่เกิน 1–2 รอบ)
7. ผู้ใช้ตรวจและรับงาน

ตัวละครผู้ส่งเอกสารเป็นแอนิเมชันล้วน ไม่เรียกโมเดล

## Requirements ขั้น 1 (ตกลงกับผู้ใช้ 2026-10-02)

- **ตำแหน่ง 10 ตัว**: เจ้าของ 1, เลขาเจ้าของ 1 (จด brief / สรุปผลส่งผู้ใช้), 2 แผนก (**วิจัย** และ **ผลิตงาน**) แผนกละหัวหน้า 1 + ลูกน้อง 2, ผู้ตรวจ 1, ผู้ส่งเอกสาร 1
- **ผู้ส่งเอกสาร**: เป็นตัวจัดคิวงานจริง (โค้ดธรรมดา ไม่ใช่ AI) ถือหน้าที่ส่งต่องานระหว่างตำแหน่ง แอนิเมชันสะท้อนการส่งต่อนั้น
- **ภาพ**: Claude วาดสไปรต์พิกเซลเองด้วยโค้ด (ยังไม่ใช้ชุดสไปรต์ภายนอก) มุมกล้องเฉียง 3/4 แบบ Game Dev Story ตัวละครเดินได้ 4 ทิศ
- **หน้าจอ**: ภาพออฟฟิศ + แถบสถานะ (งานปัจจุบัน/ขั้นตอน) + คลิกตัวละครเพื่อดูบทสนทนา/กำลังทำอะไร
- **สั่งงาน**: กล่องแชทแบบหน้าจอสนทนา RPG คุยกับเจ้าของ (เจ้าของถามกลับหลายรอบเพื่อเก็บ requirement)
- **เดโมจำลอง**: สคริปต์ 1 งานตัวอย่างที่เล่นครบ 7 ขั้นและครบทุกเหตุการณ์ + ปุ่มทดลองเหตุการณ์พิเศษ (QA ตีกลับ, error, รอคิว ฯลฯ) ตัวจำลองต้องส่งเหตุการณ์รูปแบบเดียวกับของจริง
- **เทคนิค**: Canvas 2D ล้วน ไม่เพิ่มไลบรารีเกมจนกว่าจะจำเป็น (ผู้ใช้ยืนยัน) ข้อความใน UI/เกมทั้งหมดเป็น **ภาษาอังกฤษ** (ผู้ใช้สั่ง) ส่วนเอกสารโปรเจกต์ยังเป็นไทยได้

## สถานะ / ขั้นการพัฒนา

- **ขั้น 1 (เสร็จรอบแรก 2026-10-02)**: UI ออฟฟิศ + ลำดับเหตุการณ์ **จำลอง** ยังไม่ต่อ AI ไม่กิน token — ทำแล้ว: ห้อง 10 ตำแหน่ง, เดิน/นั่ง/ท่าทาง, แชท RPG, inspector, คิวคูเรียร์, ปุ่มทดลอง (QA reject / agent error / courier jam), เทสต์ 12 ข้อ ที่ยังไม่ทำ: เสียง, ปรับสไปรต์ให้สวยขึ้น, ให้ผู้ใช้ซูม/แพนห้อง
- **ขั้น 2**: ต่อ agent จริงทีละตำแหน่ง (เจ้าของ + 1 แผนกก่อน)
- **ขั้น 3**: ลองงานจริง 1 ชิ้น วัดคุณภาพและเวลา

ยังไม่ตัดสินใจ: รูปแบบการแจกจ่าย (ฝังโมเดลในโปรแกรม / ให้ผู้ใช้ใส่ API key เอง / โหมดเดโม NPC ล้วน) — ออกแบบให้ไม่ผูกกับแบบใดแบบหนึ่ง

## สถาปัตยกรรม (หลักการ)

แยก 3 ชั้น คุยกันผ่าน "เหตุการณ์กลาง" (JSON) เท่านั้น:

```
[ UI 8-bit ] <-- เหตุการณ์ --> [ orchestrator ] <--> [ adapter ของโมเดล ]
```

- UI ไม่รู้ว่า agent ใช้โมเดลอะไร แค่วาดตามเหตุการณ์ (เช่น `agent เริ่มงาน`, `ส่งเอกสารให้หัวหน้า`, `QA ตีกลับ`, `error`)
- โมเดลของแต่ละตำแหน่งตั้งด้วย config (ตำแหน่งละบรรทัด) สลับเป็นโมเดลอื่นได้โดยไม่แก้ UI
- ขั้น 1 ใช้ตัวจำลองส่งเหตุการณ์แทน orchestrator จริง — ต้องส่งรูปแบบเหตุการณ์เดียวกับของจริง
- งานแต่ละชิ้นควรมีโฟลเดอร์ของตัวเอง (brief.md, งานของแต่ละตำแหน่ง, ผลลัพธ์) แทนการส่งข้อความยาวต่อกัน

## คำสั่งที่ใช้จริง

## โครงสร้าง

```
src/
├── core/          # ไม่แตะ DOM — เทสต์ด้วย node ได้
│   ├── types.ts   # AgentId, PlaceId, OfficeEvent (เหตุการณ์กลาง), OfficeSource
│   ├── roster.ts  # 10 ตำแหน่ง: ชื่อ/บทบาท/หน้าตา/model ต่อตำแหน่ง
│   ├── world.ts   # layout ห้อง, ที่ที่เดินไปได้ (places), A*, เวลาเดิน
│   └── state.ts   # OfficeStore: reducer เหตุการณ์ -> state + describeEvent
├── sim/
│   └── simulator.ts  # MockOffice: สคริปต์ 7 ขั้น + courier queue จริง (FIFO) + ปุ่มทดลอง
├── render/        # วาด 384x224 canvas (Canvas 2D ล้วน)
│   ├── characters.ts # สไปรต์ตัวละครวาดจากโค้ด + outline อัตโนมัติ + cache
│   ├── furniture.ts, background.ts, icons.ts, particles.ts
│   └── view.ts    # OfficeView: เดิน/นั่ง/ท่าทาง/ฟอง จาก state + events
└── ui/            # DOM: dialog.ts (แชท RPG), panels.ts (inspector/queue/feed/steps)
```

เลย์เอาต์จอ (`core/layout.ts`): ห้องคงที่ 384x224 วางกลางแคนวาสที่ใหญ่เท่าหน้าต่าง สเกลเป็นจำนวนเต็มเมื่อจอพอ (คม) ส่วนที่เหลือเติมฉากออฟฟิศต่อเนื่อง (`render/background.ts`: พื้น ผนัง หน้าต่างซ้อนแถวเมื่อจอสูง ตู้เอกสาร ต้นไม้ ประตูกระจกที่ผนังหน้าเมื่อจอสูงพอ — ผู้ใช้ไม่ชอบพรมทางเข้าแถบยาว ห้ามเอากลับมา) พิกัดทุกอย่างยังเป็นพิกัดห้อง ชั้นวาดใช้ `translate(ox, oy)` และเมาส์แปลงด้วย `view.toOffice()` — ห้ามใส่ของที่ agent เดินถึงนอกห้อง 384x224
ยังไม่ทำ: บีบนิ้วซูม/ลากบนมือถือแนวตั้ง (ห้องจะเล็ก)

กฎโครง: ชั้นวาด (`render/`) และ `ui/` อ่านได้แค่ `OfficeStore` กับ `OfficeEvent` — ห้ามรู้ว่าใครขับ (mock หรือ agent จริง)
Source ใหม่ (orchestrator จริง) ต้อง implement `OfficeSource` และส่ง event ชุดเดียวกัน

## กฎเฉพาะของโปรเจกต์นี้

- ใช้เฉพาะทรัพยากรที่ฟรีและไม่ผูกบัตร (ตามธรรมนูญข้อ 4)
- สไปรต์/เสียง/ฟอนต์ ต้องเป็นชุดที่อนุญาตให้ใช้เชิงพาณิชย์ได้ (เช่น CC0) เพราะอาจขายหรือแจกจ่ายภายหลัง
- จดทุกอย่างที่นำมาใช้ (โมเดล สไปรต์ ไลบรารี + ลิงก์ + ใบอนุญาต) ลง `THIRD-PARTY.md`
- ห้ามฝังหรือแจกจ่ายบัญชี/session ของ Claude ไปกับโปรแกรม ถ้าจะรองรับ Claude ต้องใช้ API key ของผู้ใช้เอง
- ดาวน์โหลดโมเดลหรือไฟล์ใหญ่ (เช่น Ollama, ไฟล์โมเดลหลาย GB) ต้องถามผู้ใช้ก่อนทุกครั้ง พร้อมบอกชื่อ แหล่ง ขนาด
- ห้ามคิดว่าเครื่องผู้ใช้ปลายทางแรงเท่าเครื่องนี้ (i3-12100F, RAM 16 GB, RTX 4060 Ti 8 GB — รันโมเดล 7–8B ได้ทีละ 1–2 งาน)
- เปลี่ยนรูปแบบ "เหตุการณ์กลาง" ต้องอัปเดตทั้งตัวจำลองและชั้นวาดในงานเดียวกัน
- ก่อนแก้จุดที่เคยมีปัญหา ดู `bugs.md` (ถ้ามี) ก่อน และจดบั๊กที่แก้จริงทุกครั้ง
