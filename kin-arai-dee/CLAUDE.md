# กินอะไร"ดี" (kin-arai-dee)

> อยู่ใต้ธรรมนูญ `C:\dev\CLAUDE.md` — อ่านไฟล์นั้นก่อน กฎในไฟล์นี้ชนะเมื่อขัดกัน

ชื่อที่แสดงในแอป: **กินอะไร"ดี"** (ใช้ชื่อนี้ทุกที่ที่ผู้ใช้เห็น) — `kin-arai-dee` ใช้แค่เป็นชื่อโฟลเดอร์/แพ็กเกจ

## ⭐ จุดประสงค์ของแอป (อ่านก่อนทุกครั้ง — ทุกการตัดสินใจต้องรับใช้ข้อนี้)

> **ผู้ใช้ขี้เกียจไปหาข้อมูลทุกครั้งว่าวัตถุดิบอะไรกินได้/ไม่ได้
> → กรอกเมนูปุ๊บ แอปไล่หาวัตถุดิบ + เครื่องปรุง (ชนิด/ยี่ห้อ) ที่กินได้สำหรับการควบคุมอาหารนั้นมาให้ทันที**

- แอปคือ **เครื่องมือหาข้อมูลแทนผู้ใช้** ไม่ใช่แอปติดตามการรักษา
- ผู้ป่วยรู้ขั้นการรักษาของตัวเองอยู่แล้ว → **ห้ามถามประวัติ วันเริ่ม/วันจบ จำนวนวัน หรือขั้นการรักษา**
  และไม่ต้องแสดงเรื่องระยะเวลาควบคุมอาหาร
- **ขั้นตอนต้องน้อยที่สุด:** เลือก chip → กรอกเมนู → ได้ผล ห้ามเพิ่มคำถามต่อ/ขั้นตอนคั่นกลาง
- ผู้ใช้จริงคนแรก: หลานที่ดูแลคุณยายซึ่งกำลังจะกลืนแร่ แต่ต้องใช้ได้กับคนทั่วไปที่ไม่มีความรู้เรื่องอาหารด้วย

## การตัดสินใจที่ตกลงกับผู้ใช้แล้ว

### ยึด "การควบคุมอาหาร" ไม่ใช่ "โรค"
- บางการรักษาไม่ใช่โรค (เช่น กลืนแร่) และบางโรคไม่ต้องคุมอาหาร
- ภายใน: **อาหารเฉพาะ** (`diet`) เช่น ไอโอดีนต่ำ, ลดโซเดียม — เขียนกฎครั้งเดียว ใช้ร่วมหลายโรคได้
- ผู้ใช้เห็น: **chip ชื่อโรค/การรักษาภาษาง่ายๆ** ที่คนทั่วไปรู้จัก (เช่น "กลืนแร่", "ความดันสูง") แอป map ไปหาอาหารเฉพาะเอง
  ผู้ใช้ไม่ต้องรู้ว่าต้องคุมอาหารแบบไหน
- ค้นหา chip ด้วยชื่อเรียกหลายแบบได้ (กลืนแร่ / ไอโอดีนรังสี / I-131 / ไทรอยด์)
- **"กลืนแร่" เป็น chip เดียว** — ก่อน/หลังกลืนแร่ใช้รายการอาหารเดียวกัน (ดู `docs/research-low-iodine.md`)

### 2 หน้า
1. **หน้าแรก — กินอะไร"ดี"**: ช่องกรอกเมนู + ปุ่มสุ่มเมนู + chip โรค/การรักษา (เลือกได้หลายอัน, หน้าตา chip ออกแบบทีหลัง)
   - ไม่เลือก chip = โหมดคนทั่วไป (ดูสูตร/วัตถุดิบ/สุ่มเมนู ไม่ตรวจกฎ)
   - เลือกหลาย chip = ตรวจทุกชุดกฎพร้อมกัน ใช้ข้อที่เข้มที่สุด
2. **หน้าคลังข้อมูล**: เรียงตามโรค/การรักษา กดเข้าไปดูว่าต้องคุมอาหารแบบไหน กินอะไรได้/ไม่ได้ ยี่ห้อแนะนำ แหล่งอ้างอิง
   + ปุ่ม "ตรวจเมนูด้วยอันนี้" → ไปหน้าแรกพร้อมเลือก chip ให้

### ผลตรวจเมนู 3 แบบ
- วัตถุดิบในเมนูแบ่งเป็น **วัตถุดิบหลัก** (ตัวตนของเมนู เช่น แซลมอนใน "ข้าวผัดแซลมอน") กับ **วัตถุดิบเปลี่ยนได้** (น้ำปลา ซีอิ๊ว เกลือ)
- ✅ **กินได้** — ทุกอย่างผ่าน หรือเปลี่ยนเป็นของที่ผ่านได้ → แสดงรายการวัตถุดิบ + ชนิด/ยี่ห้อที่ต้องใช้
  (ของที่ต้องจำกัดปริมาณ เช่น ไข่แดง ยังเป็น ✅ แต่มีหมายเหตุปริมาณ)
- ❌ **ห้ามกิน** — เฉพาะเมื่อ **วัตถุดิบหลักไม่ผ่านและไม่มีของแทน** → บอกเหตุผล + เสนอเมนูใกล้เคียงที่กินได้ (เช่น ข้าวผัดหมู/ไก่)
- ❓ **ไม่แน่ใจ** — มีวัตถุดิบที่ไม่มีข้อมูล → บอกว่าตัวไหน และแนะนำให้เลี่ยง

### ข้อมูล 3 ชั้น
| ชั้น | เนื้อหา | ผูกกับอาหารเฉพาะ? |
|---|---|---|
| ข้อมูลอาหาร | สารอาหาร/100 ก. (ไอโอดีน โซเดียม โพแทสเซียม ฯลฯ) | ไม่ — ใช้ร่วม |
| สินค้า/ยี่ห้อ | เครื่องปรุงยี่ห้อไหนมีอะไร ขายร้านไหน | ไม่ — ใช้ร่วม |
| ชุดกฎอาหารเฉพาะ | เพดานสารอาหาร + รายการห้าม/จำกัด | ใช่ |

- วัตถุดิบต้องประกอบจากวัตถุดิบอื่นได้หลายชั้น (น้ำพริกเผา → กุ้งแห้ง, แกง → กะปิ)

## กฎเรื่องข้อมูล (ข้อมูลสุขภาพ ผิดแล้วมีผลจริง)

- **ใช้หลายแหล่งอ้างอิง ไม่พึ่งแหล่งเดียว** ทุกข้อมูลจำว่ามาจากแหล่งไหน (หลายแหล่งได้) + วันที่ตรวจล่าสุด
- ระดับแหล่ง: คู่มือ รพ./หน่วยงานรัฐ/แนวทางสากล > ฉลาก/ผู้ผลิต > ประสบการณ์ผู้ป่วย (ใช้แค่เป็นสัญญาณเตือน ห้ามใช้ยืนยันว่ากินได้)
- **แหล่งขัดกัน → ใช้ข้อที่เข้มกว่า** และแสดงให้เห็นว่ามีความเห็นต่าง
- ยี่ห้อที่ยืนยันจากแหล่งเดียว ต้องมีป้ายบอก
- **ไม่แน่ใจ = ไม่ผ่าน** ห้ามเดาว่ากินได้
- ในไทย เกลือ/น้ำปลา/ซีอิ๊วส่วนใหญ่เติมไอโอดีน (อย. บังคับ) → ยี่ห้อต้องยืนยันรายตัว และฉลาก "ไม่มีไอโอดีน" อย่างเดียวไม่พอ
- **ลำดับหาข้อมูล:** หายี่ห้อที่ผ่านจากแหล่งแพทย์ก่อน แล้วค่อยเช็กว่าร้านไหนมีขาย — ร้านคือ "ซื้อที่ไหน" ไม่ใช่ตัวตัดสิน
- **ร้านที่ผู้ใช้กำหนด:** 7-Eleven, Lotus's, Big C, Tops, Makro, CJ (CJ More / CJ Express) — ห้ามเพิ่ม/ตัดเองโดยไม่ถาม
- ข้อมูลร้านเก็บเป็นข้อมูลที่ค้นเตรียมไว้ (มีวันที่ค้น) ไม่ดึงเว็บร้านสดตอนรันแอป
- **AI (ถ้าใช้) ทำแค่แตกเมนูเป็นวัตถุดิบ** ห้ามตัดสินว่ากินได้ — ใช้บริการฟรีไม่ผูกบัตรเท่านั้น, key อยู่ใน `.env.local`
- แอปต้องมีข้อความ **ไม่ใช่คำแนะนำทางการแพทย์ ให้ยึดคำสั่งแพทย์**
- งดไอโอดีน ≠ งดเค็ม (เสี่ยงโซเดียมต่ำในผู้สูงอายุ) → ทุกครั้งที่ของไม่ผ่าน ต้องเสนอของแทน
- งานค้นคว้าทั้งหมดจดใน `docs/` พร้อมลิงก์

## เฟส

1. ฐาน 3 ชั้น + chip "กลืนแร่" + ตรวจเมนู (✅/❌/❓ + ยี่ห้อ + เมนูทดแทน) + ชุดทดสอบจากเมนูตัวอย่างในคู่มือรามาฯ
2. สุ่มเมนู + หน้าคลังข้อมูล + ข้อมูล 6 ร้าน + รายการซื้อของ + ส่งออก/พิมพ์ให้แพทย์ดู
3. chip โรคอื่น + ใช้ AI แตกเมนูที่พิมพ์อิสระ

## โครงสร้าง

ตอนนี้ยังเป็น template Vite vanilla-ts (`src/main.ts`) — โครงที่วางแผนไว้ (อัปเดตเมื่อสร้างจริง):

- `src/data/foods.ts` — ข้อมูลอาหาร/วัตถุดิบ + สารอาหาร (ชั้น 1)
- `src/data/products.ts` — สินค้า/ยี่ห้อ + ร้านที่ขาย (ชั้น 2)
- `src/data/diets/<id>.ts` — ชุดกฎอาหารเฉพาะ เช่น `low-iodine.ts` (ชั้น 3)
- `src/data/conditions.ts` — chip โรค/การรักษา + ชื่อเรียกอื่น → map ไปหา diet
- `src/data/menus.ts` — เมนู → วัตถุดิบ (หลัก/เปลี่ยนได้)
- `src/data/sources.ts` — ทะเบียนแหล่งอ้างอิง
- `src/engine/` — logic ตรวจเมนู (ไม่ผูกกับ diet ใด)
- `src/ui/` — หน้าจอ
- `docs/` — งานค้นคว้า
