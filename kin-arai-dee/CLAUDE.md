# กินอะไร"ดี" (kin-arai-dee)

> อยู่ใต้ธรรมนูญ `C:\dev\CLAUDE.md` — อ่านไฟล์นั้นก่อน กฎในไฟล์นี้ชนะเมื่อขัดกัน

ชื่อที่แสดงในแอป: **กินอะไร"ดี"** (ใช้ชื่อนี้ทุกที่ที่ผู้ใช้เห็น) — `kin-arai-dee` ใช้แค่เป็นชื่อโฟลเดอร์/แพ็กเกจ

## ⭐ จุดประสงค์ของแอป (อ่านก่อนทุกครั้ง — ทุกการตัดสินใจต้องรับใช้ข้อนี้)

> **ผู้ใช้ขี้เกียจไปหาข้อมูลทุกครั้งว่าวัตถุดิบอะไรกินได้/ไม่ได้
> → กรอกเมนูปุ๊บ แอปไล่หาวัตถุดิบ + เครื่องปรุง (ชนิด/ยี่ห้อ) ที่กินได้สำหรับการควบคุมอาหารนั้นมาให้ทันที**

- แอปคือ **เครื่องมือหาข้อมูลแทนผู้ใช้** ไม่ใช่แอปติดตามการรักษา
- ผู้ป่วยรู้ขั้นการรักษาของตัวเองอยู่แล้ว → **ห้ามถามประวัติ วันเริ่ม/วันจบ จำนวนวัน หรือขั้นการรักษา**
  และไม่ต้องแสดงเรื่องระยะเวลาควบคุมอาหาร
- **ขั้นตอนต้องน้อยที่สุด:** เลือก chip → กรอกเมนู → ได้ผล ห้ามเพิ่มคำถามต่อ/ขั้นตอนคั่นกลาง
- ผู้ใช้จริงคนแรก: หลานที่ดูแลคุณยายซึ่งกำลังจะกลืนแร่ แต่ต้องใช้ได้กับคนทั่วไปที่ไม่มีความรู้เรื่องอาหารด้วย

## ⭐ กลุ่มเป้าหมาย + หน้าตา (โฟกัสเสมอ)

**ผู้ใช้ส่วนใหญ่เป็นผู้หญิงที่ดูแลผู้ป่วยในบ้าน หลายคนไม่คุ้นกับเทคโนโลยี**
→ ใช้ง่าย ไม่ซับซ้อน เข้าใจทันที ขั้นตอนน้อย **แต่ต้องสวย**
- ปุ่ม/ตัวอักษรใหญ่พอ กดง่าย ไม่มีศัพท์เทคนิค ไม่มีเมนูซ่อนลึก
- 1 หน้าทำ 1 อย่าง ผลลัพธ์อ่านจบได้โดยไม่ต้องเดา

**ภาษา:** ภาษาไทย **ภาษาเขียนที่ถูกหลัก** ดูเป็นมืออาชีพ ไม่ใช่ภาษาพูด และไม่ให้ดูเหมือน AI เขียน
(ไม่มีอีโมจิในข้อความ ไม่มีคำฟุ่มเฟือย ไม่มีคำลงท้ายแบบแชท) — ตรวจคำ/วรรณยุกต์/การเว้นวรรคทุกข้อความ

**ต้นแบบหน้าตา:** Dribbble "Recipe App with Meal Planner" by Metamorph Lab
https://dribbble.com/shots/25092909-Recipe-App-with-Meal-Planner
- พื้นขาว/เทาอ่อน สะอาด มีสีเน้น 1 สี (ต้นแบบใช้เขียว) การ์ดมุมโค้งมาก ไม่มีเส้นขอบหนา
- **รูปอาหารจริง** ขนาดใหญ่เป็นจุดเด่นของหน้า (จานกลมตัดพื้นหลัง)
- chip หมวดแบบเม็ดยาค่อนข้างใหญ่ มีรูปเล็กประกอบ
- รายการวัตถุดิบเป็นแถว: **รูปวัตถุดิบจริง** + ชื่อ + ปริมาณ (สีเน้นรอง)
- ปุ่มหลักเม็ดยาสีเน้นตัวใหญ่ลอยด้านล่าง, แถบนำทางล่างแบบเม็ดยา

**รูปภาพ:** ต้องเป็นรูปจริงทั้งอาหารและวัตถุดิบ/สินค้า เพื่อให้ผู้ใช้ไปหาซื้อได้ง่าย — แอปเปิดให้คนทั่วไปใช้
จึงต้องมีที่มา/สิทธิ์ใช้งานทุกรูป (ดู `docs/research-images.md`)
- ห้ามคัดลอกรูปจากเว็บร้าน (ตรวจข้อกำหนดครบ 6 ร้านแล้ว ห้ามทุกร้าน) — ใช้ได้แค่ลิงก์ออกไปหน้าสินค้า
- ห้ามเก็บข้อมูลจาก Makro ด้วยโปรแกรมอัตโนมัติ (ข้อกำหนดห้ามชัด)
- รูปสินค้ายี่ห้อ: Open Food Facts (CC BY-SA ต้องระบุที่มา) / อาหาร+วัตถุดิบสด: Unsplash, Pexels, Wikimedia Commons

**ธีม:** มีปุ่มเลือกธีมได้ (สว่าง/มืด + ชุดสีเน้น) — ทุกชุดสีต้อง **ไม่ฉูดฉาด ไม่รกตา** (สีหม่น/นุ่ม)

## การตัดสินใจที่ตกลงกับผู้ใช้แล้ว

### ยึด "การควบคุมอาหาร" ไม่ใช่ "โรค"
- บางการรักษาไม่ใช่โรค (เช่น กลืนแร่) และบางโรคไม่ต้องคุมอาหาร
- ภายใน: **อาหารเฉพาะ** (`diet`) เช่น ไอโอดีนต่ำ, ลดโซเดียม — เขียนกฎครั้งเดียว ใช้ร่วมหลายโรคได้
- ผู้ใช้เห็น: **chip ชื่อโรค/การรักษาภาษาง่ายๆ** ที่คนทั่วไปรู้จัก (เช่น "กลืนแร่", "ความดันสูง") แอป map ไปหาอาหารเฉพาะเอง
  ผู้ใช้ไม่ต้องรู้ว่าต้องคุมอาหารแบบไหน
- ค้นหา chip ด้วยชื่อเรียกหลายแบบได้ (กลืนแร่ / ไอโอดีนรังสี / I-131 / ไทรอยด์)
- **"กลืนแร่" เป็น chip เดียว** — ก่อน/หลังกลืนแร่ใช้รายการอาหารเดียวกัน (ดู `docs/research-low-iodine.md`)

### 2 หน้า
1. **หน้าแรก — กินอะไร"ดี"**: ช่องกรอกเมนู + ปุ่มสุ่มเมนู + chip โรค/การรักษา (เลือกได้หลายอัน, หน้าตา chip ออกแบบทีหลัง)
   - ช่องกรอกเมนู **แนะนำชื่อเมนูจากฐานระหว่างพิมพ์** และถ้าพิมพ์เมนูที่ไม่มีในฐาน → ผล ❓
   - ปุ่มสุ่มเมนู **สุ่มจากทุกเมนู** ไม่ว่าจะเลือก chip หรือไม่ (ถ้าเลือก chip ผลที่สุ่มได้ก็ผ่านการตรวจตามปกติ)
   - ไม่เลือก chip = โหมดคนทั่วไป (ดูสูตร/วัตถุดิบ/สุ่มเมนู ไม่ตรวจกฎ)
   - เลือกหลาย chip = ตรวจทุกชุดกฎพร้อมกัน ใช้ข้อที่เข้มที่สุด
2. **หน้าคลังข้อมูล**: เรียงตามโรค/การรักษา กดเข้าไปดูว่าต้องคุมอาหารแบบไหน กินอะไรได้/ไม่ได้ ยี่ห้อแนะนำ แหล่งอ้างอิง
   + ปุ่ม "ตรวจเมนูด้วยอันนี้" → ไปหน้าแรกพร้อมเลือก chip ให้

### ผลตรวจเมนู 3 แบบ
- วัตถุดิบในเมนูแบ่งเป็น **วัตถุดิบหลัก** (ตัวตนของเมนู เช่น แซลมอนใน "ข้าวผัดแซลมอน") กับ **วัตถุดิบเปลี่ยนได้** (น้ำปลา ซีอิ๊ว เกลือ)
- ✅ **กินได้** — ทุกอย่างผ่าน หรือเปลี่ยนเป็นของที่ผ่านได้ → แสดงรายการวัตถุดิบ + ชนิด/ยี่ห้อที่ต้องใช้
  (ของที่ต้องจำกัดปริมาณ เช่น ไข่แดง ยังเป็น ✅ แต่มีหมายเหตุปริมาณ)
- ❌ **ห้ามกิน** — เฉพาะเมื่อ **วัตถุดิบหลักไม่ผ่านและไม่มีของแทน** → บอกเหตุผล + เสนอเมนูใกล้เคียงที่กินได้ (เช่น ข้าวผัดหมู/ไก่)
- ❓ **ไม่แน่ใจ** — มีวัตถุดิบที่ไม่มีข้อมูล → บอกว่าตัวไหน และแนะนำให้เลี่ยง

### ข้อมูล 3 ชั้น
| ชั้น | เนื้อหา | ผูกกับอาหารเฉพาะ? |
|---|---|---|
| ข้อมูลอาหาร | สารอาหาร/100 ก. (ไอโอดีน โซเดียม โพแทสเซียม ฯลฯ) | ไม่ — ใช้ร่วม |
| สินค้า/ยี่ห้อ | เครื่องปรุงยี่ห้อไหนมีอะไร ขายร้านไหน | ไม่ — ใช้ร่วม |
| ชุดกฎอาหารเฉพาะ | เพดานสารอาหาร + รายการห้าม/จำกัด | ใช่ |

- วัตถุดิบต้องประกอบจากวัตถุดิบอื่นได้หลายชั้น (น้ำพริกเผา → กุ้งแห้ง, แกง → กะปิ)

## กฎเรื่องข้อมูล (ข้อมูลสุขภาพ ผิดแล้วมีผลจริง)

- **ใช้หลายแหล่งอ้างอิง ไม่พึ่งแหล่งเดียว** ทุกข้อมูลจำว่ามาจากแหล่งไหน (หลายแหล่งได้) + วันที่ตรวจล่าสุด
- ระดับแหล่ง: คู่มือ รพ./หน่วยงานรัฐ/แนวทางสากล > ฉลาก/ผู้ผลิต > ประสบการณ์ผู้ป่วย (ใช้แค่เป็นสัญญาณเตือน ห้ามใช้ยืนยันว่ากินได้)
- **แหล่งขัดกัน → ใช้ข้อที่เข้มกว่า** และแสดงให้เห็นว่ามีความเห็นต่าง
- ยี่ห้อที่ยืนยันจากแหล่งเดียว ต้องมีป้ายบอก
- **ไม่แน่ใจ = ไม่ผ่าน** ห้ามเดาว่ากินได้
- ในไทย เกลือ/น้ำปลา/ซีอิ๊วส่วนใหญ่เติมไอโอดีน (อย. บังคับ) → ยี่ห้อต้องยืนยันรายตัว และฉลาก "ไม่มีไอโอดีน" อย่างเดียวไม่พอ
- **ลำดับหาข้อมูล:** หายี่ห้อที่ผ่านจากแหล่งแพทย์ก่อน แล้วค่อยเช็กว่าร้านไหนมีขาย — ร้านคือ "ซื้อที่ไหน" ไม่ใช่ตัวตัดสิน
- **ร้านที่ผู้ใช้กำหนด:** 7-Eleven, Lotus's, Big C, Tops, Makro — ห้ามเพิ่ม/ตัดเองโดยไม่ถาม
  (ตัด CJ ออกก่อน — ไม่มีแคตตาล็อกออนไลน์ ผู้ใช้สั่ง 2026-10-05)
- **ข้อมูลร้าน = แค่ "วางขายที่ร้าน/เครือไหน หาซื้อได้ที่ไหน"** ไม่เช็กสต็อก ไม่ระบุสาขา (ผู้ใช้ยืนยัน 2026-10-05)
- **ข้อมูลทุกอย่างรวบรวมเก็บไว้ในฐานข้อมูลล่วงหน้า (Supabase — ผู้ใช้เลือก)** แอปอ่านจากฐานของเราเท่านั้น
  ห้ามไปค้นเว็บอื่นตอนผู้ใช้ใช้งาน — ทุกแถวมีแหล่งที่มา + วันที่ตรวจ, มีไฟล์สำรองข้อมูลใน git
- **AI (ถ้าใช้) ทำแค่แตกเมนูเป็นวัตถุดิบ** ห้ามตัดสินว่ากินได้ — ใช้บริการฟรีไม่ผูกบัตรเท่านั้น, key อยู่ใน `.env.local`
- แอปต้องมีข้อความ **ไม่ใช่คำแนะนำทางการแพทย์ ให้ยึดคำสั่งแพทย์**
- งดไอโอดีน ≠ งดเค็ม (เสี่ยงโซเดียมต่ำในผู้สูงอายุ) → ทุกครั้งที่ของไม่ผ่าน ต้องเสนอของแทน
- งานค้นคว้าทั้งหมดจดใน `docs/` พร้อมลิงก์

### ตกลงรอบ 2 (2026-10-05)
- **เมนู:** ก่อนอื่นต้องรวบรวมรายชื่อเมนูให้มากที่สุด — **อาหารไทยเท่านั้น ครบทุกภาค**
  เอาเฉพาะเมนูที่คนทั่วไปรู้จัก/ทำกินจริง ไม่เอาเมนูแปลกหรือหายาก (เปลือง DB)
- **เมนูชุดแรก:** เมนูตัวอย่างในคู่มือรามาฯ (3 เมนู) + อาหารไทยที่ทำกินบ่อย
- **แสดงปริมาณวัตถุดิบ** ในผลลัพธ์ **ต่อ 1 ที่** — สูตร: ลองหาแหล่งเดียวที่น่าเชื่อถือและอนุญาตให้ใช้ก่อน (ข.)
  ถ้าไม่ได้จริงๆ ค่อยเทียบหลายแหล่งแล้วเขียนปริมาณมาตรฐานเอง (ก.) — ห้ามคัดลอกข้อความสูตรของใคร
- **ขอบเขตเมนู:** อาหารคาวเท่านั้น แบ่ง 5 ภาค (กลาง/เหนือ/อีสาน/ใต้/ตะวันออก) ต้องพบในแหล่งรวมเมนู ≥ 2 แหล่ง
  หรือขายทั่วไป, เป้า 200–300 เมนู — ร่างรายชื่ออยู่ที่ `docs/menu-list.md` + `docs/menu-candidates.csv`
- **เมนูที่หารูปถูกลิขสิทธิ์ไม่ได้ → ไม่ใส่ในแอปจนกว่าจะมีรูป** (ห้ามใช้รูปกราฟิกแทน)
- **เมนูที่ใช้เนื้อสัตว์ได้หลายแบบ = 1 เมนู + รายการเนื้อสัตว์ให้เลือก** (เช่น ข้าวผัด → หมู/ไก่/กุ้ง)
  ผลตรวจแยกตามเนื้อสัตว์ และพิมพ์ "ข้าวผัดกุ้ง" ต้องเจอ
- **เฉพาะเมนูที่ทำกินเองได้** — ตัดเมนูแบบร้าน/ของซื้อสำเร็จ (หมูกระทะ, ก๋วยเตี๋ยวเรือ ฯลฯ)
  สินค้าแปรรูป (แหนม หมูยอ ไส้กรอกอีสาน แคบหมู ไส้อั่ว หม่ำ) ย้ายไปอยู่ชั้นสินค้า ไม่ใช่เมนู
- **เมนูรามาฯ ใช้ 3 เมนูที่พบใน PDF:** ลาบปลาทับทิม, ต้มซุปไก่มะเขือเทศ, ข้าวผัดหมู
- **ข้อมูลใน Supabase ผู้ใช้กรอก/แก้เองผ่านหน้า Supabase** — ไม่ทำหน้าผู้ดูแลในแอป
- **แพลตฟอร์ม:** เว็บเปิดในมือถือเป็นหลัก เข้าผ่านลิงก์ หรือเพิ่มไปที่หน้าจอโฮม — ยังไม่ต้องออฟไลน์
- **ไม่มีการเข้าสู่ระบบ** (รายการซื้อของเก็บในเครื่องผู้ใช้)
- **ไม่เก็บสิ่งที่ผู้ใช้พิมพ์/ค้น** (ยังไม่ต้องทำ)
- **ไม่มีระบบถ่ายรูปฉลาก/ส่งรูปขึ้น Open Food Facts** (ยังไม่ต้องทำ)
- **ตรวจข้อมูลซ้ำทุก 3 เดือน** (นับจากวันที่ตรวจล่าสุดของแต่ละแถว)
- **Hosting: Vercel** (Hobby — ฟรี ไม่ผูกบัตร, ใช้ได้เฉพาะงานไม่เชิงพาณิชย์)
- **ไม่ทำระบบส่งออก/พิมพ์ให้แพทย์ดู**

   + ชุดทดสอบจากเมนูตัวอย่างในคู่มือรามาฯ — เริ่มจากรวบรวมรายชื่อเมนูอาหารไทยทุกภาคก่อน
2. สุ่มเมนู + หน้าคลังข้อมูล + ข้อมูล 5 ร้าน + รายการซื้อของ
3. chip โรคอื่น + ใช้ AI แตกเมนูที่พิมพ์อิสระ

## คำสั่งที่ใช้จริง

```bash
npm run dev -- --port 5172      # รัน dev (พอร์ต 5172)
npm run build    # build
npm run test   # ยังไม่ได้ตั้ง
```

หรือใช้ Browser pane: `preview_start` ชื่อ `kin-arai-dee`

## โครงสร้าง

ตอนนี้ยังเป็น template Vite vanilla-ts (`src/main.ts`) — โครงที่วางแผนไว้ (อัปเดตเมื่อสร้างจริง):

- ข้อมูลทั้งหมดอยู่ใน **Supabase** (ไม่ใช่ไฟล์ใน `src/`) — ตาราง: อาหาร/สารอาหาร (ชั้น 1), สินค้า/ยี่ห้อ + ร้าน (ชั้น 2),
  ชุดกฎ diet (ชั้น 3), chip โรค/การรักษา + ชื่อเรียกอื่น, เมนู → วัตถุดิบ (หลัก/เปลี่ยนได้) + ปริมาณ, แหล่งอ้างอิง
  — ไฟล์สำรองข้อมูลเก็บใน git (ออกแบบ schema ตอนเริ่มทำจริง)
- `src/engine/` — logic ตรวจเมนู (ไม่ผูกกับ diet ใด)
- `src/ui/` — หน้าจอ
- `docs/` — งานค้นคว้า
