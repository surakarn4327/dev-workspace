- ตรวจ ✅/❌/❓ ตามกฎกลืนแร่ มีปุ่มสุ่ม ปุ่มธีม ปุ่ม i (เครดิตรูป คำเตือนทางการแพทย์)

- ส่งข้อมูลขึ้น Supabase: `node --env-file=.env.local scripts/seed-supabase.mjs` (ต้องรันทุกครั้งหลังแก้ CSV แล้ว build:data)
- ไฟล์ `.env.local` มี key อยู่ ห้ามเปิดอ่านหรือพิมพ์ค่า key ในแชท (ระบบกันไม่ให้อ่านอยู่แล้ว)

งานที่ต้องทำ (ทีละข้อ แจ้งแผนและเวลาก่อนเริ่มแต่ละข้อ):

1. ตรวจสูตรเมนูต่อ — ค้นสูตรจริงเทียบรายการวัตถุดิบใน `docs/menu-ingredients.csv`
   - ตอนนี้ค้นยืนยันแค่ 5 เมนู (ผัดกะเพรา ผัดผักบุ้ง ผัดฉ่า ต้มยำ ข้าวผัดหมู) ที่เหลือ 126 เมนูอ่านเทียบความรู้ทั่วไปเท่านั้น
   - ทำรอบละ 10-20 เมนู เทียบ 2-3 แหล่ง (Cookpad, Wongnai, Kapook, สถาบันโภชนาการ) หาวัตถุดิบที่มักแอบใส่ เช่น กะปิ กุ้งแห้ง ปลาร้า ซีอิ๊ว ผงปรุงรส
   - เพิ่มได้เฉพาะวัตถุดิบที่มีแหล่งยืนยัน จดสิ่งที่เพิ่มลง docs/audit-2026-10-05.md (หรือไฟล์ audit ใหม่) พร้อมลิงก์แหล่ง
   - แก้ CSV แล้ว build:data, test, seed Supabase

2. รูปวัตถุดิบและรูปสินค้า (ยี่ห้อเครื่องปรุง)
   - รูปต้องตรงวัตถุดิบ/ตรงรุ่นสินค้าจริงเท่านั้น รูปคล้ายใช้ไม่ได้ (กฎใน CLAUDE.md)
   - สินค้า: Open Food Facts (CC BY-SA ต้องระบุที่มา) ดู docs/research-low-iodine.md หัวข้อ "เทียบรูป Open Food Facts" มีรายการที่ตรงรุ่นแล้ว 14 กลุ่ม พร้อมบาร์โค้ด
   - วัตถุดิบสด: Unsplash หรือ Wikimedia Commons (Pexels ใช้ไม่ได้) ห้ามคัดลอกรูปจากเว็บร้านค้า
   - รูปแทนกันได้เมื่อ "สินค้าชนิดเดียวกัน" และ "กลุ่มไอโอดีนเดียวกัน" เท่านั้น
   - ทุกรูปต้องมีที่มาและสิทธิ์ (ผู้สร้าง สัญญาอนุญาต ลิงก์) แสดงใน ปุ่ม i
   - ผู้ใช้เคยพักงานหารูปที่ขาดไว้ จะส่งมาให้ตรวจทีหลัง ถามก่อนว่าให้หาเองหรือรอ

3. หน้าคลังข้อมูล (แท็บ "คลังข้อมูล" ตอนนี้ขึ้น "อยู่ระหว่างจัดทำ")
   - ตาม CLAUDE.md: เรียงตามโรค/การรักษา กดเข้าไปดูว่าต้องคุมอาหารแบบไหน กินอะไรได้/ไม่ได้ ยี่ห้อแนะนำ แหล่งอ้างอิง + ปุ่ม "ตรวจเมนูด้วยอันนี้"
   - ทำแบบสะอาด ไม่รก ใช้ข้อมูลที่มีแล้ว (ingredient-iodine.csv, rama-seasonings.csv) ถามผู้ใช้เรื่องหน้าตาก่อนเขียนโค้ด (ส่งภาพตัวอย่างให้อนุมัติ)

4. push: ผู้ใช้กด push เองเสมอ (ระบบเครื่องปฏิเสธการ push ของ Claude) เมื่อมี commit ค้าง ให้เตือนผู้ใช้ Vercel จะอัปเดตเว็บเองหลัง push

วิธีทำงานที่ผู้ใช้ต้องการ (สำคัญ):
- ตอบภาษาไทย ทีละขั้น สั้น ไม่ยัดข้อมูลเยอะ ผู้ใช้เคยบอก "ใจเย็นๆ สอนทีละอย่าง"
- ทำเฉพาะที่สั่ง ห้ามเพิ่มปุ่ม ข้อความ แท็บ ฟีเจอร์เอง หน้าจอต้องสะอาด ไม่มีบรรทัดอธิบายซ้ำซ้อน ถ้าอยากเพิ่มให้ถามก่อน
- ห้ามแสดงข้อมูลที่ยังไม่ยืนยัน (เช่น ร้านที่หาซื้อได้) ไม่แน่ใจ = ไม่ผ่าน
- ข้อมูลสุขภาพ มีผลกับชีวิตคน ตรวจกับแหล่งอ้างอิงเสมอ บอกตรงๆ ว่าอะไรยืนยันแล้ว อะไรเป็นการอนุมาน
- หลังแก้ ต้องทดสอบเองในเบราว์เซอร์ ไม่ให้ผู้ใช้ตรวจแทน และรายงานตามจริงว่าตรวจอะไรไปแล้ว อะไรยังไม่ได้ตรวจ
- งานนาน แจ้งแผน เวลา และความคืบหน้าเองเป็นระยะ
- แก้บั๊กจริงต้องจดลง bugs.md (อาการ / สาเหตุ / วิธีแก้)
- commit ภาษาอังกฤษ ขึ้นต้นด้วยคำกริยา
- Wikimedia API จำกัดการเรียก: รวมคำขอเป็นชุด และรอเมื่อโดนจำกัด (scripts/resolve-images.mjs ทำไว้แล้ว)
- เมนูไม่มีรูป = ไม่ใส่ในแอป
