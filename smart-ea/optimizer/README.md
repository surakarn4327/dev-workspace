# optimizer — ไล่หาค่าตั้งต้นที่ดีที่สุดของ MARibbonEA

ทุกอย่างที่ต้องใช้ในการรัน optimization ซ้ำบนเครื่องไหนก็ได้ อยู่ในโฟลเดอร์นี้

```
optimizer\
├── bin\run-opt.ps1   ← สคริปต์สั่ง MT5 รันจากคอมมานด์ไลน์ แล้วเก็บผลเป็น CSV
├── sets\*.set        ← ช่วงค่าที่ไล่หาในแต่ละรอบ
└── results\*.csv     ← ผลที่รันไปแล้ว
```

## รูปแบบไฟล์ผล

คั่นด้วย `;` ไม่มีหัวคอลัมน์ (แต่ละ pass เขียนมาจาก `DumpPass()` ใน core ของ EA)
**อย่านับคอลัมน์ด้วยตา** ใช้ `bin\show-results.ps1` อ่าน — สคริปต์นั้นเป็นที่เดียวที่นิยาม
ชื่อคอลัมน์ไว้ และเดาผังได้เองจากจำนวนช่อง

```powershell
.\show-results.ps1 -OutName rf2_M15 -Top 15
.\show-results.ps1 -OutName rf2_M15 -All -Raw | Where-Object { $_.winrate -ge 0.5 }
```

ทุกกลยุทธ์ลงท้ายด้วยคอลัมน์ตัวชี้วัดชุดเดียวกัน 17 ช่อง (มาจาก `MetricsCsvTail()`
ใน [`src\TesterMetrics.mqh`](../src/TesterMetrics.mqh)) ต่างกันแค่คอลัมน์พารามิเตอร์ข้างหน้า

```
เงินฝากตั้งต้น; ไม้; กำไรสุทธิ; ขาดทุนสูงสุด; PF; กำไรเฉลี่ยต่อไม้;
winrate; เดือนทั้งหมด; เดือนที่กำไร; สัดส่วนเดือนที่กำไร; เดือนแย่สุด; เดือนกลาง;
ไม้ใหญ่สุด/กำไรสุทธิ; ไม้ใหญ่สุด/กำไรฝั่งบวก; ชั่วโมงถือเฉลี่ย; แพ้ติดกันมากสุด; คะแนน
```

หกช่องแรกมาจาก `TesterStatistics()` ส่วนที่เหลือคำนวณเองจากประวัติดีล เพราะ MT5
ไม่มีตัวชี้วัดว่ากำไร "กระจายตัว" ยังไง ซึ่งเป็นหัวใจของการถอนเงินรายเดือน

**เงินฝากตั้งต้นอยู่ในไฟล์ผลเพื่อให้ตรวจย้อนได้** ช่องนั้นเคยค้างเป็น 3000 จากรอบตรวจ
real tick แล้วผลเทียบกับรอบอื่นไม่ได้ ตอนนี้ `run-opt.ps1` ทั้งส่งค่าและมีด่านตรวจให้

คอลัมน์พารามิเตอร์ของ `MARibbonEA` (14 ช่อง รวมเป็น 31):

```
symbol; timeframe; ใช้ATR; atrMult; โหมดTP; TP1; TP2; TP3; BE;
เลื่อนคาบ ribbon; ชนิดเส้น MA; จำนวนแท่ง swing; ปิดเมื่อสัญญาณกลับ; ระยะล็อก BE
```

`โหมดTP`: 0 = แบ่งปิด 3 ไม้ย่อย, 1 = ปิดครั้งเดียวที่ TP3, 2 = ไม่ใช้ TP
`ชนิดเส้น MA`: 0 = SMA, 1 = EMA, 2 = SMMA (เท่ากับ RMA ของ Pine), 3 = LWMA

ของ `RangeFadeEA` (16 ช่อง รวมเป็น 33):

```
symbol; timeframe; คาบค่ากลาง; ตัวคูณ dev; zEntry; โหมดTP; ตัวคูณ TP; ตัวคูณ SL;
แท่งหมดอายุ; โหมดกรองเทรนด์; คาบเทรนด์; ใช้ RSI; RSI ซื้อ; RSI ขาย; รอกลับตัว; พักกี่แท่ง
```

`โหมดTP`: 0 = ค่ากลางของแบนด์, 1 = ATR x ตัวคูณ, 2 = R x ตัวคูณ
`โหมดกรองเทรนด์`: 0 = ไม่กรอง, 1 = เข้าฝั่งเดียวกับเทรนด์, 2 = เข้าฝั่งสวนเทรนด์

**ไฟล์เก่าก่อน 2026-09-11 มี 15/18 คอลัมน์** (`stage1_*`, `stage2_*`, `half*`, `oos_*`,
`verify_*`) ยังไม่มีตัวชี้วัดความสม่ำเสมอและยังใช้คะแนนสูตรเก่า `show-results.ps1`
อ่านไฟล์พวกนั้นไม่ได้ ต้องดูดิบ

**ระวังตอนอ่าน** — พารามิเตอร์บางตัวไม่ถูกใช้ในบางโหมด ค่าที่เห็นจึงไม่มีความหมาย:
- `atrMult` ไม่มีผลเมื่อ `ใช้ATR = 0` (SL มาจาก swing high/low แทน)
- `TP2` ไม่มีผลเมื่อ `โหมดTP = 1`
- `TP1/TP2/TP3` ไม่มีผลเลยเมื่อ `โหมดTP = 2` และถ้า `BE = 0` ด้วย ก็ไม่เหลือตัวไหนมีผล
- `ตัวคูณ TP` ไม่มีผลเมื่อ `โหมดTP = 0` ของ RangeFade
- `RSI ซื้อ/ขาย` ไม่มีผลเมื่อ `ใช้ RSI = 0`

ทำให้หลายแถวที่ดูต่างกัน จริงๆ เป็นชุดเดียวกัน — MT5 ไม่รู้เรื่องนี้จึงเสียรอบไปกับชุดซ้ำ
เวลาตั้งช่วงค้นหารอบใหม่ ควรแยกกิ่ง (เช่น รันเฉพาะ swing รอบหนึ่ง เฉพาะ ATR อีกรอบหนึ่ง)

## เกณฑ์ให้คะแนน — เปลี่ยนแล้ว 2026-09-11

`Custom max` ยังคืนค่าจาก `OnTester()` เหมือนเดิม แต่สูตรเปลี่ยนจาก
"กำไรสุทธิ ÷ ขาดทุนสูงสุด" มาเป็นสูตรนั้นคูณตัวประกอบความสม่ำเสมอ 4 ตัว

```
คะแนน = (กำไรสุทธิ / ขาดทุนสูงสุด)
       x min(winrate / 0.50, 1)
       x (สัดส่วนเดือนที่กำไร)^2
       x min(0.15 / (ไม้ใหญ่สุด/กำไรสุทธิ), 1)
       x min((ไม้ต่อเดือน) / 20, 1)
```

เหตุผล: เกณฑ์เดิมให้รางวัลชุดที่ปล่อยกำไรไหลเสมอ โหมดที่มี TP จึงแพ้ทุกรอบและไม่เคย
ได้โอกาส แต่ชุดที่ชนะแบบนั้นถอนเงินรายเดือนไม่ได้ เพราะกำไรมาจากไม้ใหญ่นานๆ ครั้ง

ตัวประกอบทุกตัวอยู่ในช่วง 0..1 และ **อิ่มตัวเมื่อถึงเป้า** จึงไม่ให้รางวัลการเกินเป้าเปล่าๆ
และยังมีความชันให้ genetic algorithm ไต่ ไม่ใช่ประตูตัด 0/1 ซึ่งจะทำให้ทุกชุดได้ 0
เท่ากันหมดแล้วค้นหาต่อไม่ได้ เป้าทั้งสามตัวอยู่เป็น `TGT_*` ต้นไฟล์ `TesterMetrics.mqh`

## โมเดล tick กับ delay — วัดแล้ว ไม่ต้องเดาอีก

**`Model` และ `ExecutionMode` ต้องระบุในไฟล์ ini เสมอ** MT5 รีเซ็ตสองช่องนี้กลับเป็นค่า default
ทุกครั้งที่เปิดด้วย `/config:` แล้วเขียนค่าที่รีเซ็ตทับ `terminal.ini` ตอนปิดตัวเอง — ตั้งใน GUI ไว้เท่าไร
ก็ไม่มีผล `run-opt.ps1` ส่งให้แล้ว (default `-Model 0 -ExecutionMode 37`)

- **Every tick (`-Model 0`) กับ 1 minute OHLC (`-Model 1`) ใช้ข้อมูลต้นทางเดียวกัน** คือแท่ง M1
  ย้อนหลัง (มีถึง 2565) ครอบคลุมช่วง 1 ปีเท่ากัน ต่างกันที่ Every tick ปั้นจุดระหว่างแท่งละเอียดกว่า
  ซึ่งเหมาะกับ EA ตัวนี้เพราะ SL/TP วางไว้ที่ broker ลำดับการโดนชนภายในแท่งมีผลจริง
  **ผลที่เก็บไว้ทั้งหมดใช้ `-Model 0`** ถ้าจะเทียบกับของเก่าต้องใช้ค่านี้
- **real ticks (`-Model 4`) ย้อนได้แค่ประมาณ 8 เดือน** (เริ่ม 2569.01.01) ใช้ตรวจซ้ำชุดที่ชนะได้
  แต่ครอบคลุมไม่ถึง 1 ปี
- **delay แทบไม่มีผลกับ EA ตัวนี้** วัดจากชุดเดียวกันบน M15: delay 0 ได้กำไร 8,031.04
  delay 37 ms ได้ 8,030.78 — ต่างกัน 26 สตางค์ (0.003%) จำนวนไม้เท่ากันเป๊ะ 637 ไม้
  เพราะทองใน 35 ms แทบไม่ขยับ และ EA ส่งคำสั่งแค่ ~600 ครั้งต่อปี ต้นทุนจริงอยู่ที่สเปรด
  (~$0.26 ต่อไม้) ซึ่งถูกคิดอยู่ในทุกโมเดลอยู่แล้ว — **ถ้า timeframe ถี่กว่านี้มาก (M1 เข้าไม้
  3,000-5,700 ครั้งต่อปี) ต้องวัดใหม่ อย่าเหมาว่าน้อยเหมือนกัน**

  ขยับ winrate แค่ 24% เป็น 31% เพราะปิดหนึ่งในสามที่ 0.5R ได้ +0.17R แต่อีกสองในสาม
  โดน SL −0.67R สุทธิยังติดลบ
- **ปิดทั้งไม้ที่เป้าใกล้**: ได้ winrate 50-68% จริง แต่ PF ร่วงเหลือ 1.07-1.11 และขาดทุนสูงสุด
  พุ่งกลับไปเท่ากำไรราว 10 เดือน

**เลือกได้อย่างเดียว** และตัวที่ให้ DD ต่ำ (ซึ่งคือสิ่งที่ต้องการจริงเพื่อถอนเงิน) คือตัวที่ winrate ต่ำ
— winrate 50% เป็นแค่*ตัวแทน*ของ "รายได้นิ่ง" ส่วนของจริงคือเดือนที่กำไรและ DD ซึ่งวัดตรงๆ
ได้แล้วและผ่านทั้งคู่

ช่วงตรวจสอบยาว **9 เดือน** สั้นกว่าที่ควร และอยู่ในกรอบ 2568+ ทั้งหมด จึงยังไม่รู้ว่าทนได้แค่ไหน
ถ้าตลาดเปลี่ยนโหมดอีก ถ้าจะใช้จริงควรเริ่มที่ทุนเสี่ยงต่ำ รัน demo คู่ขนาน และตั้งเส้นถอยไว้ล่วงหน้า
