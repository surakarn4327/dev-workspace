# optimizer — ไล่หาค่าตั้งต้นที่ดีที่สุดของ MARibbonEA

ทุกอย่างที่ต้องใช้ในการรัน optimization ซ้ำบนเครื่องไหนก็ได้ อยู่ในโฟลเดอร์นี้

```
optimizer\
├── bin\run-opt.ps1   ← สคริปต์สั่ง MT5 รันจากคอมมานด์ไลน์ แล้วเก็บผลเป็น CSV
├── sets\*.set        ← ช่วงค่าที่ไล่หาในแต่ละรอบ
└── results\*.csv     ← ผลที่รันไปแล้ว
```

### 4. ตั้งค่าใน Strategy Tester ครั้งเดียว (สำคัญที่สุด)

## รูปแบบไฟล์ผล

คั่นด้วย `;` ไม่มีหัวคอลัมน์ (แต่ละ pass เขียนมาจาก `DumpPass()` ใน EA)

รอบแรก (`stage1_*.csv`) 15 คอลัมน์:

```
symbol; timeframe; ใช้ATR; atrMult; โหมดTP; TP1; TP2; TP3; BE;
ไม้; กำไรสุทธิ; ขาดทุนสูงสุด; PF; กำไรเฉลี่ยต่อไม้; คะแนน
```

รอบสอง (`stage2_*.csv`) แทรก 3 คอลัมน์หลัง BE:

```
... BE; เลื่อนคาบ ribbon; ชนิดเส้น MA; จำนวนแท่ง swing; ไม้; ...
```

`โหมดTP`: 0 = แบ่งปิด 3 ไม้ย่อย, 1 = ปิดครั้งเดียวที่ TP3, 2 = ไม่ใช้ TP
`ชนิดเส้น MA`: 0 = SMA, 1 = EMA, 2 = SMMA (เท่ากับ RMA ของ Pine), 3 = LWMA

**ระวังตอนอ่าน** — พารามิเตอร์บางตัวไม่ถูกใช้ในบางโหมด ค่าที่เห็นจึงไม่มีความหมาย:
- `atrMult` ไม่มีผลเมื่อ `ใช้ATR = 0` (SL มาจาก swing high/low แทน)
- `TP2` ไม่มีผลเมื่อ `โหมดTP = 1`
- `TP1/TP2/TP3` ไม่มีผลเลยเมื่อ `โหมดTP = 2` และถ้า `BE = 0` ด้วย ก็ไม่เหลือตัวไหนมีผล

ทำให้หลายแถวที่ดูต่างกัน จริงๆ เป็นชุดเดียวกัน — MT5 ไม่รู้เรื่องนี้จึงเสียรอบไปกับชุดซ้ำ
เวลาตั้งช่วงค้นหารอบใหม่ ควรแยกกิ่ง (เช่น รันเฉพาะ swing รอบหนึ่ง เฉพาะ ATR อีกรอบหนึ่ง)

## โมเดล tick กับ delay — วัดแล้ว ไม่ต้องเดาอีก

**`Model` และ `ExecutionMode` ต้องระบุในไฟล์ ini เสมอ** MT5 รีเซ็ตสองช่องนี้กลับเป็นค่า default
ทุกครั้งที่เปิดด้วย `/config:` แล้วเขียนค่าที่รีเซ็ตทับ `terminal.ini` ตอนปิดตัวเอง — ตั้งใน GUI ไว้เท่าไร
ก็ไม่มีผล `run-opt.ps1` ส่งให้แล้ว (default `-Model 0 -ExecutionMode 37`)

- **Every tick (`-Model 0`) กับ 1 minute OHLC (`-Model 1`) ใช้ข้อมูลต้นทางเดียวกัน** คือแท่ง M1
  ย้อนหลัง (มีถึง 2565) ครอบคลุมช่วง 1 ปีเท่ากัน ต่างกันที่ Every tick ปั้นจุดระหว่างแท่งละเอียดกว่า
  ซึ่งเหมาะกับ EA ตัวนี้เพราะ SL/TP วางไว้ที่ broker ลำดับการโดนชนภายในแท่งมีผลจริง
  **ผลที่เก็บไว้ทั้งหมดใช้ `-Model 0`** ถ้าจะเทียบกับของเก่าต้องใช้ค่านี้
- **real ticks (`-Model 4`) ย้อนได้แค่ประมาณ 8 เดือน** (เริ่ม 2569.01.01) ใช้ตรวจซ้ำชุดที่ชนะได้
  แต่ครอบคลุมไม่ถึง 1 ปี
- **delay แทบไม่มีผลกับ EA ตัวนี้** วัดจากชุดเดียวกันบน M15: delay 0 ได้กำไร 8,031.04
  delay 37 ms ได้ 8,030.78 — ต่างกัน 26 สตางค์ (0.003%) จำนวนไม้เท่ากันเป๊ะ 637 ไม้
  เพราะทองใน 35 ms แทบไม่ขยับ และ EA ส่งคำสั่งแค่ ~600 ครั้งต่อปี ต้นทุนจริงอยู่ที่สเปรด
  (~$0.26 ต่อไม้) ซึ่งถูกคิดอยู่ในทุกโมเดลอยู่แล้ว — **ถ้า timeframe ถี่กว่านี้มาก (M1 เข้าไม้
  3,000-5,700 ครั้งต่อปี) ต้องวัดใหม่ อย่าเหมาว่าน้อยเหมือนกัน**

## สิ่งที่รู้แล้วจากรอบที่ผ่านมา

- **M15 ดีที่สุด** M5 กำไรได้แต่ขาดทุนสูงสุดเกือบเท่าพอร์ต **M1 ไม่มีสักชุดที่กำไรจาก 111 ชุด**
  (เข้าไม้ 3,000–5,700 ครั้งต่อปี ค่าสเปรดกินหมด)
- เลื่อนคาบ ribbon ช่วยได้จริง — M15 ชุดคะแนนสูงสุด เลื่อน +14 เปลี่ยนเป็น SMA แล้ว
  กำไรเพิ่ม 13% พร้อมขาดทุนสูงสุดลดลง 31%
- ชุดที่เลื่อนไปมากๆ จะเข้าไม้น้อยลงมาก (625 เหลือ 149 ไม้ต่อปี) คะแนนสวยขึ้นแต่เชื่อได้น้อยลง
  ให้ดูค่าข้างเคียงประกอบเสมอ ถ้า +13/+14/+15 ให้ผลใกล้กันจึงถือว่าเป็นที่ราบจริง

## ผลที่เก็บไว้

| ไฟล์ | คืออะไร |
|---|---|
| `stage1_M15/M5/M1_partial` | รอบแรก ไล่หา SL/TP ล็อก ribbon ไว้ตามที่ Pine ออกแบบ |
| `stage2_M15a` | จูน ribbon บนฐาน swing SL (ปิดครั้งเดียว 5R, BE เปิด) |
| `stage2_M15b/c/f` | จูน ribbon บนฐาน ATR SL (ไม่ใช้ TP, BE ปิด) — `f` คือ shift 21-26 |
| `stage2_M5` | จูน ribbon ของ M5 (ฐาน ATR 2.25, ไม่ใช้ TP, BE ปิด) |
| `half1_*` / `half2_*` | ตรวจทานชุดผู้ชนะโดยแบ่งปีที่ใช้จูนออกเป็นสองครึ่ง |
| `oos_*_y1/y2/y3` | **ทดสอบบน 3 ปีที่ไม่เคยใช้จูน** (มิ.ย. 2565 ถึง มิ.ย. 2568) |

## บทสรุปสำคัญที่สุด — อ่านก่อนเชื่อตัวเลขใดๆ ในโฟลเดอร์นี้

**ชุดที่ชนะบนปีที่ใช้จูน ไม่ได้แปลว่าใช้ได้จริง** ผลจากไฟล์ `oos_*`:

| | ปีที่ใช้จูน | มิ.ย.65-66 | มิ.ย.66-67 | มิ.ย.67-68 |
|---|---|---|---|---|
| M5 (SMMA เลื่อน -4) | +16,923 · PF 1.21 | **-9,838** | **-9,951** | **-9,915** |
| M15 (ATR 2.50 เลื่อน +23) | +9,499 · PF 1.59 | +3,589 | **-3,871** | +1,478 |

**M5 ล้างพอร์ตทุกปี** ตัวเลขหยุดที่ราว -9,900 เพราะเงินหมด ไม่ใช่เพราะขาดทุนแค่นั้น — ชุดนั้นคือค่าที่พอดี
กับปี 2569 อย่างเดียว ห้ามนำไปใช้

**M15 รอดแบบก้ำกึ่ง** รวมสามปีได้ +1,196 และขาดทุนสูงสุดจริง 4,200-5,500 ไม่ใช่ 1,377 อย่างที่เห็น
ในปีที่จูน ถ้าจะใช้จริงต้องคิดจาก PF ราว 1.05 และลดทุนเสี่ยงจาก 100 เหลือ 30-40 ต่อไม้

**และการตรวจทานแบบแบ่งครึ่งปี (`half*`) ผ่านทั้ง M5 และ M15 ทั้งที่ M5 พังยับ** — เพราะสองครึ่งนั้น
ยังเป็นปีเดียวกับที่ใช้คัดค่ามา บทเรียนคือ **แบ่งครึ่งข้อมูลชุดเดิมไม่ใช่การตรวจสอบจริง**
ต้องใช้ข้อมูลคนละช่วงที่ไม่มีส่วนในการเลือกค่าเลยเท่านั้น

## ถ้าจะจูนต่อ

อย่าเอาผล `oos_*` ไปเลือกค่าใหม่ ไม่งั้นข้อมูลก้อนนั้นก็จะกลายเป็นข้อมูลที่ใช้จูนไปด้วย แล้วจะไม่เหลือ
อะไรไว้ตรวจสอบอีก วิธีที่ควรใช้คือ walk-forward — จูนบนช่วง 1-2 ทดสอบช่วง 3 แล้วจูนบน 1-3 ทดสอบช่วง 4
