# งานต่อ: AMD Po3 ไม่ถ่ายไปคู่เงินอื่นแบบพารามิเตอร์ตรงๆ — ต้องเลือกทางถัดไป

อ่าน `smart-ea/CLAUDE.md` และ `optimizer/README.md` ก่อน (มีบริบททั้งหมดของโปรเจกต์)
โดยเฉพาะหัวข้อ **"AMD Po3 หลายคู่เงิน — เอาพารามิเตอร์ของทองไปใช้ตรงๆ ขาดทุนทั้ง 5 คู่"** ท้ายไฟล์

## สถานะล่าสุด (จบ session ก่อนหน้าตรงนี้ — 2026-09-12)

1. **ทดสอบ AMD Po3 (`BestM5_AmdPo3.mq5`) บน 5 คู่เงินที่สเปรดแคบสุดของบัญชีนี้แล้ว — ขาดทุนทั้ง 5 คู่**
   (EURUSDc -1,518 / GBPUSDc -1,025 / AUDUSDc -3,297 / USDCADc -296 / USDJPYc -7,232, PF 0.72-0.92
   ทุกคู่) ใช้พารามิเตอร์ชุดเดียวกับที่จูนบนทองตรงๆ ไม่ได้จูนใหม่ — **0 จาก 5 คู่กำไร** จึงไม่เข้าเงื่อนไข
   ที่จะรวมพอร์ตด้วย `combine-monthly.ps1` (ต้องมี ≥2 คู่กำไรจริงก่อน) รายละเอียดเต็ม + ตารางผลอยู่ใน
   `optimizer/README.md`

2. **แก้สูตร `InpRiskPointUnit` ที่จดผิดไว้จาก session ก่อนแล้ว** — `1/contract_size` ใช้ได้แค่ตอน
   quote currency ของ symbol = USD (EURUSDc/GBPUSDc/AUDUSDc) ส่วนคู่ที่ USD เป็น **base**
   (USDJPYc, USDCADc) ต้องคูณด้วยเรตปัจจุบันด้วย (`pointUnit = rate/contract`) ไม่งั้นทุนเสี่ยงเพี้ยน
   ไปหลักสิบ-ร้อยเท่าแบบเงียบๆ — รายละเอียดเต็มอยู่ใน `bugs.md` หัวข้อ 2026-09-12
   **ถ้าจะเพิ่มคู่เงิน `USDxxx` ตัวอื่นอีก ต้องใช้สูตรที่แก้แล้วนี้เสมอ**

3. ไฟล์ที่เพิ่มเข้ามารอบนี้: `.set` ทั้ง 5 คู่ที่ `optimizer/sets/AmdPo3_M5_{EURUSDc,GBPUSDc,AUDUSDc,
   USDCADc,USDJPYc}.set`, ผลดิบที่ `optimizer/results/amdpo3_{eurusd,gbpusd,audusd,usdcad,usdjpy}.csv`
   (+ `_monthly.csv` รายตัว)

## ทางที่ยังไม่ได้ลอง — เรียงตามที่น่าจะคุ้มที่สุดก่อน

1. **ย้ายไปทดสอบแนวทางหลายสัญลักษณ์กับ `MARibbon H4` แทน** — เป็นตัวเดียวในโปรเจกต์นี้ที่พิสูจน์แล้วว่า
   edge ทนข้ามยุคจริง (93/160 ชุดกำไรทั้งช่วงจูนและช่วงกันไว้ตรวจสอบ 3 ปีเก่า ดูหัวข้อ "ผลบวกที่เจอ
   ตอนท้าย" ใน README) จุดอ่อนเดียวคือไม้น้อย (3-5 ไม้/เดือนต่อสัญลักษณ์) ซึ่งหลายสัญลักษณ์แก้ได้ตรงจุด
   ต้องจูนแบบ walk-forward ก่อน (จูนช่วงหนึ่ง ทดสอบช่วงที่ยังไม่แตะ) ไม่ใช่หยิบชุดจากตารางเดิมมาใช้ตรงๆ
2. **ถ้ายังอยากลุยกับ AMD Po3 ต่อ**: ต้องจูนพารามิเตอร์ใหม่แยกทีละคู่เงิน (ไม่ใช่ยกพารามิเตอร์ทองมาใช้)
   ก่อนถึงจะสรุปได้ว่า "ตระกูลตาย" บนคู่เงินเหล่านี้จริงไหม (ตอนนี้รู้แค่ว่า "ค่าที่จูนบนทองใช้ข้ามไม่ได้"
   ซึ่งเป็นคนละคำถามกับ "ไม่มี edge เลย") ต้นทุนสูงกว่าทางที่ 1 มาก (ต้องรันกริดแยกทีละคู่)
3. **walk-forward จริงจังของ MARibbon/AMD Po3 บนทอง** — จูนบนช่วง 1-2 ทดสอบช่วง 3 แล้วจูนบน 1-3
   ทดสอบช่วง 4 (ยังไม่เคยทำแบบนี้จริงจัง มีแต่ SATS ที่ลองแล้วพังตอน validate — ดูหัวข้อ "SATS —
   ลอง interaction... พังตอน validate" ใน README เป็นตัวอย่างว่าทำไมต้องระวัง)
