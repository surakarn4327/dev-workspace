# smart-ea

> อยู่ใต้ธรรมนูญ `C:\dev\CLAUDE.md` — อ่านไฟล์นั้นก่อน กฎในไฟล์นี้ชนะเมื่อขัดกัน

## โปรเจกต์นี้คืออะไร

EA (Expert Advisor) เทรด forex อัตโนมัติ ใช้กับ broker Exness

- แพลตฟอร์ม: **MT5 (MQL5)** — ตัดสินใจแล้ว (2026-09-04) เหตุผล: ใหม่กว่า MT4, Exness รองรับเต็ม,
  MQL5 เขียนโค้ดยืดหยุ่นกว่า (OOP, มี built-in indicator เยอะกว่า) EA ทั้งหมดในโปรเจกต์นี้เขียนเป็น
  `.mq5` เท่านั้น
- โปรเจกต์พี่น้อง: [`ma-ribbon`](../ma-ribbon/CLAUDE.md) เก็บ Pine indicator ต้นฉบับของกลยุทธ์เดียวกัน
  ฝั่งนั้นเป็น Pine บน TradingView ฝั่งนี้เป็น MT5 ที่เทรดจริงและ backtest ได้
  **ห้าม import ข้ามโฟลเดอร์โปรเจกต์** (ตามธรรมนูญ) ถ้าต้องเทียบตรรกะให้อ่านไฟล์ แล้วเขียนซ้ำฝั่งนี้เอง

## คำสั่งที่ใช้จริง

MQL ไม่มี dev server — compile ด้วย MetaEditor แล้วแนบ EA เข้ากับ chart ใน MetaTrader
Strategy Tester ใช้ backtest ได้โดยไม่ต้องเทรดเงินจริง

compile จากคอมมานด์ไลน์ได้ ไม่ต้องเปิด GUI:

```bash
"C:\Program Files\MetaTrader 5 EXNESS\metaeditor64.exe" /compile:"C:\dev\smart-ea\src\MARibbonEA.mq5" /log:"%TEMP%\c.log"
```

process คืนค่าก่อนเขียน log เสร็จ — รอสัก 5 วินาทีแล้วค่อยอ่าน log หา `Result: 0 errors`

  ม.ค.-ธ.ค. 2568 กับกันช่วง ม.ค.-ก.ย. 2569 ไว้ตรวจครั้งเดียวตลอดไป — ผู้ใช้ตัดสินใจว่าจะจูนซ้ำเป็นระยะเอง
  (ประมาณทุก 6 เดือน ยังไม่ล็อกตายตัว) แทนที่จะแช่ค่าเดิมไว้ตลอดกาล กฎใหม่:
  - **ช่วงจูนของแต่ละรอบ = ตั้งแต่จุดเริ่มต้นข้อมูล ถึงวันที่สั่งจูนจริง** (ไม่ใช่ตรึงที่ 2568-12-31 อีกต่อไป)
    กินข้อมูลล่าสุดเข้าไปด้วยเสมอ เพื่อให้ตามทันการเปลี่ยน regime ของตลาด (ดูเหตุผลที่ AMD Po3
    ด้านล่าง — edge ผูกกับ regime จริง)
  - **แต่ละรอบจะไม่มีช่วงกันไว้ตรวจสอบแบบถาวรอีกต่อไป** — ผู้ใช้รับทราบแล้วว่านี่คือการแลก (ไม่มีข้อมูล
    เหลือพิสูจน์ทันทีหลังจูน) เพื่อแลกกับการจูนซ้ำเป็นระยะแทน (คล้าย walk-forward validation)
    **ห้ามเข้าใจว่ากฎเก่าเรื่อง "ห้ามเชื่อผลจากช่วงที่ใช้เลือกค่า" ถูกยกเลิก** — แค่เปลี่ยนจาก "กันช่วงถาวร"
    เป็น "จูนใหม่เรื่อยๆ แล้วดูว่ารอบถัดไปยังทำกำไรต่อเนื่องจากรอบก่อนไหม" (เดือนถัดจากที่จูนล่าสุด
    = out-of-sample ธรรมชาติของรอบนั้น จนกว่าจะจูนรอบใหม่ทับเข้าไป)
  - ก่อนจูนรอบใหม่ทุกครั้ง เช็คผลจริงของค่าที่ใช้เทรดอยู่ในช่วงตั้งแต่จูนครั้งก่อนจนถึงตอนนี้ก่อน (ถือเป็น
    การตรวจสอบ out-of-sample แบบธรรมชาติของรอบนั้น) แล้วค่อยจูนทับด้วยข้อมูลทั้งหมดรวมช่วงนั้นเข้าไปด้วย

  (ตาม [ธรรมนูญข้อ 4](../CLAUDE.md)) ถ้า EA ต้องต่อ API ภายนอก ให้อ่านค่าจากไฟล์ config
  ที่ไม่เข้า git เท่านั้น
- ก่อนรันด้วยเงินจริงทุกครั้ง ต้อง backtest ผ่าน Strategy Tester และ/หรือทดสอบบนบัญชี demo ก่อนเสมอ
- Exness สมัครฟรี ไม่ผูกบัตร (ตรงตามกฎข้อ 4) — แต่การเติมเงินเข้าบัญชีเทรดจริงเป็นเรื่องการเงิน
  ที่ Claude ห้ามทำแทนผู้ใช้ (ดูกฎ "การกระทำต้องห้าม" ของระบบ) ผู้ใช้ต้องทำเองทุกขั้นตอนที่เกี่ยวกับเงิน
- **เจอผลลัพธ์ผิดปกติ (เช่น backtest ได้ 0 trades, PF/winrate เพี้ยนผิดคาด) ห้ามเดาสาเหตุแล้วแก้เลย**
  ต้องใส่ diagnostic counter/log เข้าไปในโค้ดก่อน (นับว่าทุกเงื่อนไข/ทุกจุด early-return โดนตัดออกกี่ครั้ง)
  รันแล้วดู log จริงว่าไปตายที่จุดไหนมากสุด ค่อยแก้ตรงจุดนั้นตามข้อมูลจริง — เหตุผล: 2026-09-04 แก้ EA
  แบบเดาสาเหตุ 2 รอบติด (ผ่อนเงื่อนไข breakout, แก้ full-body requirement) ไม่ได้ผลเพราะเดาผิดจุด
  พอใส่ counter (`gCnt_*` + `PrintFormat` ใน `OnDeinit`) ถึงเจอตัวการจริง (z-score ATR ที่ไม่ได้ log-transform
  ก่อน ทำให้ squeeze แทบไม่เกิด) ใส่ counter ไว้ก่อนเสมอเมื่อ debug entry/exit logic ของ EA
- **ห้ามสรุปว่าชุดที่ชนะใช้ได้จริง จนกว่าจะทดสอบบนข้อมูลที่ไม่มีส่วนในการเลือกค่านั้นเลย**
  การแบ่งข้อมูลชุดเดิมออกเป็นครึ่งแล้วรันแยกกัน **ไม่ใช่การตรวจสอบ** — พิสูจน์แล้ว 2026-09-10:
  ชุด M5 ผ่านการแบ่งครึ่งฉลุย (PF 1.19 และ 1.22) แต่พอเจอ 3 ปีที่ไม่เคยใช้จูน **ล้างพอร์ตทั้งสามปี**
  ต้องใช้ช่วงเวลาคนละก้อนเท่านั้น และห้ามเอาผลจากก้อนนั้นกลับมาเลือกค่าต่อ ไม่งั้นก้อนนั้นก็เสียไปด้วย
- **ผล optimization ที่ชนะแบบโดดเดี่ยว ห้ามเชื่อ** ต้องดูค่าข้างเคียงเสมอ ถ้าขยับพารามิเตอร์ 1 ขั้นแล้ว
  ผลตกฮวบ แปลว่าบังเอิญ ไม่ใช่ edge — เลือกค่าที่อยู่กลางแถบที่ดีทั้งแถบแทน (เจอจริง 2026-09-10:
  ribbon shift 19 ได้คะแนน 6.29 แต่ shift 18 กับ 20 ได้ 0.88 กับ 2.28)
- **เกณฑ์ "ถอนกำไรได้สม่ำเสมอ" ที่ผู้ใช้ตั้งไว้ (2026-09-11)** — winrate 50%+ · ไม้ใหญ่สุดไม่เกิน
  10-15% ของกำไรรวม · เดือนที่กำไรเกิน 70% ของเดือนทั้งหมด · DD ไม่เกินกำไร 2-3 เดือน ·
  ไม้พอให้ถอนจริง (20+ ไม้/เดือน) **ยังไม่มี EA ตัวไหนผ่านครบทั้ง 5 ข้อบนข้อมูลที่ไม่ได้ใช้เลือกค่า**
  ไล่ไปแล้วราว 4,000 ชุด 2 ตระกูลกลยุทธ์ 5 timeframe — ตารางสรุปว่าตกข้อไหนอยู่ใน
  `optimizer\README.md` หัวข้อ "ยังไม่มี EA ที่ถอนกำไรได้สม่ำเสมอ" อ่านก่อนเริ่มรอบใหม่
  จะได้ไม่ไล่ซ้ำทางที่วัดแล้วว่าตัน
- **ชุดที่ผ่านเกณฑ์ความสม่ำเสมอครบทุกข้อ "บนปีที่ใช้จูน" ยังบอกอะไรไม่ได้เลย** พิสูจน์แล้ว
  2026-09-11: Range Fade ผ่านทั้ง 5 ข้อพร้อมกัน (winrate 59.5%, 11/13 เดือนกำไร, DD = กำไร
  2.6 เดือน) แล้วขาดทุนทั้ง 3 ปีที่ไม่เคยใช้จูน — ตัวเลข "เดือนที่กำไร" ที่วัดบนปีเดียวกับที่คัดค่ามา
  เป็นผลของการเลือก ไม่ใช่คุณสมบัติของกลยุทธ์ **เกณฑ์ความสม่ำเสมอต้องวัดบนช่วงที่ไม่ได้ใช้เลือกค่า**
- **ก่อนสรุปว่าชุดไหนตาย ให้แยกระหว่าง "เลือกค่าผิด" กับ "ตระกูลนี้ไม่มี edge"** วิธีตรวจคือรัน
  กริดทั้งกริดบนช่วงที่กันไว้ แล้วนับว่ามีกี่ชุดที่กำไร ถ้า 0 จาก 280 ก็ไม่ใช่เรื่องค่า (ทำแบบนี้กับ
  Range Fade แล้ว) — ผลเชิงลบแบบนี้ใช้ช่วงที่กันไว้ได้โดยไม่เสียหาย เพราะไม่ได้เอาไปเลือกค่าต่อ
