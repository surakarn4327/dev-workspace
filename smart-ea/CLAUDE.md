## โปรเจกต์นี้คืออะไร

EA (Expert Advisor) เทรด forex อัตโนมัติ ใช้กับ broker Exness

- แพลตฟอร์ม: **MT5 (MQL5)** — ตัดสินใจแล้ว (2026-09-04) เหตุผล: ใหม่กว่า MT4, Exness รองรับเต็ม,
  MQL5 เขียนโค้ดยืดหยุ่นกว่า (OOP, มี built-in indicator เยอะกว่า) EA ทั้งหมดในโปรเจกต์นี้เขียนเป็น
  `.mq5` เท่านั้น
- โปรเจกต์พี่น้อง: [`ma-ribbon`](../ma-ribbon/CLAUDE.md) เก็บ Pine indicator ต้นฉบับของกลยุทธ์เดียวกัน
  ฝั่งนั้นเป็น Pine บน TradingView ฝั่งนี้เป็น MT5 ที่เทรดจริงและ backtest ได้
  **ห้าม import ข้ามโฟลเดอร์โปรเจกต์** (ตามธรรมนูญ) ถ้าต้องเทียบตรรกะให้อ่านไฟล์ แล้วเขียนซ้ำฝั่งนี้เอง

## คำสั่งที่ใช้จริง

MQL ไม่มี dev server — compile ด้วย MetaEditor แล้วแนบ EA เข้ากับ chart ใน MetaTrader
Strategy Tester ใช้ backtest ได้โดยไม่ต้องเทรดเงินจริง

compile จากคอมมานด์ไลน์ได้ ไม่ต้องเปิด GUI:

```bash
"C:\Program Files\MetaTrader 5 EXNESS\metaeditor64.exe" /compile:"C:\dev\smart-ea\src\SelfAwareTrendEA.mq5" /log:"%TEMP%\c.log"
```

process คืนค่าก่อนเขียน log เสร็จ — รอสัก 5 วินาทีแล้วค่อยอ่าน log หา `Result: 0 errors`

    **ห้ามเข้าใจว่ากฎเก่าเรื่อง "ห้ามเชื่อผลจากช่วงที่ใช้เลือกค่า" ถูกยกเลิก** — แค่เปลี่ยนจาก "กันช่วงถาวร"
    เป็น "จูนใหม่เรื่อยๆ แล้วดูว่ารอบถัดไปยังทำกำไรต่อเนื่องจากรอบก่อนไหม" (เดือนถัดจากที่จูนล่าสุด
    = out-of-sample ธรรมชาติของรอบนั้น จนกว่าจะจูนรอบใหม่ทับเข้าไป)
  - ก่อนจูนรอบใหม่ทุกครั้ง เช็คผลจริงของค่าที่ใช้เทรดอยู่ในช่วงตั้งแต่จูนครั้งก่อนจนถึงตอนนี้ก่อน (ถือเป็น
    การตรวจสอบ out-of-sample แบบธรรมชาติของรอบนั้น) แล้วค่อยจูนทับด้วยข้อมูลทั้งหมดรวมช่วงนั้นเข้าไปด้วย

## บัญชีจริงที่ใช้เทรด

- บัญชีจริง `257551547 Exness-MT5Real36` เป็น **Cent Account** — สกุลเงินบัญชีคือ **USC** ("US Cent",
  ไม่ใช่ USDC คริปโต และไม่ใช่ ISO currency มาตรฐาน) **1 USD จริง = 100 USC** ตัวเลข Balance/Equity
  ที่ MT5 โชว์ต้อง**หาร 100** ถึงจะได้มูลค่าจริงเป็นดอลลาร์ (เช่น 15,163.20 USC = **151.63 USD จริง**
  ยืนยันกับผู้ใช้แล้ว 2026-09-14) เทรดสัญลักษณ์ **`XAUUSDc`** (Digits=3, Contract size=1 XAU,
  Profit currency=USD) **ไม่ใช่ `XAUUSDm`** ที่ `optimizer\bin\run-opt.ps1` ใช้จูน/แบ็กเทสต์มาตลอด
  (Contract size มาตรฐาน 100 oz/lot) — ผลบันทึกทั้งหมดใน CLAUDE.md นี้จึงวัดจากราคา `XAUUSDm`
  ไม่ใช่ `XAUUSDc` ที่เทรดจริง (ราคาทองควรใกล้เคียงกันมากเพราะตลาดเดียวกัน แต่ spread/ต้นทุนจริงของ
  บัญชี cent ยังไม่เคยเทียบโดยตรงกับที่ backtest จำลองไว้) แบ็กเทสต์ทุกอันรันด้วย Deposit เป็น
  **USD จริง** (เช่น 10,000 USD ใน Strategy Tester) ไม่ใช่ USC — เทียบ **เปอร์เซ็นต์**กำไร/ขาดทุนได้
  ตรงๆ แต่**ห้ามเทียบตัวเลขดอลลาร์ตรงๆ ข้ามบัญชีสองแบบนี้**
- **ผลคือ**: `InpRiskFixedUsd`/`InpRiskPct` ที่ตั้งในบัญชีจริงคำนวณจาก `AccountInfoDouble(ACCOUNT_EQUITY)`
  ตรงๆ โดยไม่แปลงหน่วย ดังนั้นค่าเหล่านี้เป็น**หน่วย USC** ไม่ใช่ USD จริง (เช่น เสี่ยง 5% ของ equity
  15,163.20 USC = 758.16 USC = แค่ **~$7.58 USD จริง** ต่อไม้ ไม่ใช่ $758) — ก่อนประเมินความเสี่ยงเป็น
  เงินจริงทุกครั้ง ต้องหาร 100 เสมอ
- **เกณฑ์ VPS ฟรีของ Exness (ยอด $500 USD จริง)** ยังไม่ถึง เพราะบัญชีมีมูลค่าจริงแค่ ~$151.63 USD
  (ดู `optimizer\README.md` หรือถามผู้ใช้ก่อนสรุปว่าเข้าเกณฑ์ VPS ฟรีหรือยัง)
- **`InpRiskPointUnit` ต้องคำนวณจาก `1 / contract_size` ของสัญลักษณ์ที่เทรดจริง เสมอ** — สำหรับ
  `XAUUSDc` (contract=1) คือ `1`, สำหรับ `XAUUSDm` (contract=100) คือ `0.01` **ห้ามเดาจากชื่อ symbol
  หรือจากค่า default ในโค้ด** เปิด Market Watch → คลิกขวา symbol จริง → Specification เช็ค
  Contract size/Digits ก่อนเชื่อค่านี้ทุกครั้งที่สลับ symbol หรือก่อนรันจริงครั้งแรก
  รายละเอียดการไล่เจอเรื่องนี้อยู่ใน `bugs.md` หัวข้อ 2026-09-13

   ต้อง `#include "PositionLib.mqh"` (หรือ implement `PastCutoff()` เองถ้า core ไม่ได้ใช้ PositionLib
   แบบ `AmdPo3Core.mqh`) แล้วเรียก `PL_PastCutoff(InpCutoffServerHour)` โดย**ต้องห่อด้วย `InpUseCutoff &&`
   เสมอ** (ดูข้อ 2) **ทั้งสองจุด**: (ก) guard ก่อนเปิดไม้ใหม่ทุกจุดที่เปิดไม้ (ข) บังคับปิดไม้ที่เหลือใน
   `OnTick()` ทันทีที่เลย cutoff — ดูโค้ดจริงใน `SelfAwareTrendCore.mqh`/`AmdPo3Core.mqh` เป็นตัวอย่างอ้างอิง
2. **ต้องมี input `InpUseCutoff` (bool, default true) คู่กับ `InpCutoffServerHour` (default 17) เสมอ**
   ในทุกไฟล์ `.mq5` ที่ EA ตัวนั้นเปิดไม้เอง — `InpUseCutoff=false` ต้องปิดกฎคัตไม้ทั้งหมดได้ (ทั้งปิดไม้
   บังคับและ guard ห้ามเปิดใหม่) ไม่ใช่แค่ปรับเวลา ผู้ใช้ขอไว้ 2026-09-14 ว่าต้องเลือกปิดกฎนี้ได้ทั้งบาน
   (default 17 ของ `InpCutoffServerHour` มาจากการวัดจริง 2026-09-14 ว่า server ของ Exness ช้ากว่าเวลาไทย
   7 ชม. — **ถ้า broker/บัญชีเปลี่ยนไปวัดใหม่เสมอ อย่าใช้ 17 เป็นค่าตายตัวข้ามบัญชี**)
3. **ช่อง `input` ทุกตัวต้องมีคอมเมนต์ภาษาไทยที่เข้าใจง่าย** ไม่ใช่แค่ชื่อตัวแปรภาษาอังกฤษเปล่าๆ —
   เปิด Inputs tab ใน MT5 แล้วต้องอ่านรู้เรื่องโดยไม่ต้องเปิดโค้ดดู
4. **ต้องมี 3 โหมด TP เสมอ**: **Fix RR** (เป้าเดียว ปิดทีเดียว ไม่แบ่งปิด) · **Fix Multiple RR**
   (แบ่งปิดหลายเป้าตามระยะ R คงที่) · **Dynamic RR** (ปรับ R ตาม indicator/volatility ของกลยุทธ์นั้น)
   — สามโหมดนี้เป็น enum เดียว ไม่ใช่แค่ 2 โหมดแบบเดิม (Fixed/Dynamic ของ SATS ตอนนี้ยังไม่ครบ 3
   ต้องรีแฟกเตอร์เพิ่ม `SATS_TP_SINGLE` ทีหลัง — ดู TODO ท้ายไฟล์นี้)
5. **สูตรให้คะแนน optimize ต้องมี `InpMinTrades` เสมอ** (`ConsistencyScore()` ใน `TesterMetrics.mqh`
   คัดคะแนน 0 ให้ชุดที่ไม้น้อยกว่าเกณฑ์อยู่แล้ว) — EA ใหม่ต้องประกาศ input นี้แล้วส่งเข้าฟังก์ชันเสมอ
   ห้ามปล่อย default ต่ำเกินไปจนชุดไม้น้อย/ไม่ทนทานหลุดผ่าน
6. **คะแนน optimize (recovery factor กำไร/DD) ต้อง cap ไม่เกิน 10** ก่อนคูณตัวประกอบความสม่ำเสมอ —
   ทำไว้ที่ `TesterMetrics.mqh` แล้ว (ใช้ร่วมกันทุกกลยุทธ์อัตโนมัติเพราะเรียกสูตรเดียวกัน ข้อนี้เดียวที่
   "อัตโนมัติ" จริงๆ โดยไม่ต้องเขียนซ้ำ)
7. **ทุก `input group` ต้องติด tag บอกชัดว่าจูนหรือไม่จูน** — ขึ้นต้นชื่อ group ด้วย `[จูน]` (พารามิเตอร์ที่
   optimizer ควรไล่หาค่า เช่น ATR length, threshold, SL/TP multiplier) หรือ `[ไม่จูน]` (ค่าที่ตั้งครั้งเดียว
   ตามการตัดสินใจของผู้ใช้ ไม่ใช่ค่าที่ optimize หาให้ เช่น โหมดความเสี่ยง %/fix + จำนวนเงิน, magic number,
   เปิด/ปิดกฎคัตไม้เที่ยงคืน, เกณฑ์ `InpMinTrades`/`InpMinProfit` ตอน optimize) ตกลงกับผู้ใช้ 2026-09-14 —
   ดู `SelfAwareTrendEA.mq5`/`AmdPo3EA.mq5` เป็นตัวอย่างการแท็กที่ถูกต้อง

**ข้อ 1-2, 4, 7 ไม่มีกลไกภาษาบังคับข้ามไฟล์ — MQL5 ไม่มี inheritance ระหว่าง EA** ต้องเขียนซ้ำ/เรียก
ฟังก์ชันที่มีอยู่แล้วด้วยมือทุกครั้งที่สร้างไฟล์ `.mq5` ใหม่ ข้อ 3, 5 ก็เช่นกัน (ต้องประกาศ input เองทุกไฟล์)
มีแค่ข้อ 6 ที่ automatic จริงเพราะ EA ทุกตัวเรียก `ConsistencyScore()` สูตรเดียวกัน — **ก่อนบอกว่าพอร์ต EA
เสร็จ ต้องไล่เช็คทีละข้อใน 7 ข้อนี้ทุกครั้ง อย่าข้าม**

## กฎเฉพาะของโปรเจกต์นี้ (ทั่วไป ไม่ผูกกับ EA ตัวใดตัวหนึ่ง)

- ห้ามใส่ API key / login / password ของ Exness ลงในโค้ดหรือ commit ใดๆ เด็ดขาด
  (ตาม [ธรรมนูญข้อ 4](../CLAUDE.md)) ถ้า EA ต้องต่อ API ภายนอก ให้อ่านค่าจากไฟล์ config
  ที่ไม่เข้า git เท่านั้น
- ก่อนรันด้วยเงินจริงทุกครั้ง ต้อง backtest ผ่าน Strategy Tester และ/หรือทดสอบบนบัญชี demo ก่อนเสมอ
- Exness สมัครฟรี ไม่ผูกบัตร (ตรงตามกฎข้อ 4) — แต่การเติมเงินเข้าบัญชีเทรดจริงเป็นเรื่องการเงิน
  ที่ Claude ห้ามทำแทนผู้ใช้ (ดูกฎ "การกระทำต้องห้าม" ของระบบ) ผู้ใช้ต้องทำเองทุกขั้นตอนที่เกี่ยวกับเงิน
- **เจอผลลัพธ์ผิดปกติ (เช่น backtest ได้ 0 trades, PF/winrate เพี้ยนผิดคาด) ห้ามเดาสาเหตุแล้วแก้เลย**
  ต้องใส่ diagnostic counter/log เข้าไปในโค้ดก่อน (นับว่าทุกเงื่อนไข/ทุกจุด early-return โดนตัดออกกี่ครั้ง)
  รันแล้วดู log จริงว่าไปตายที่จุดไหนมากสุด ค่อยแก้ตรงจุดนั้นตามข้อมูลจริง — เหตุผล: 2026-09-04 แก้ EA
  แบบเดาสาเหตุ 2 รอบติด (ผ่อนเงื่อนไข breakout, แก้ full-body requirement) ไม่ได้ผลเพราะเดาผิดจุด
  พอใส่ counter (`gCnt_*` + `PrintFormat` ใน `OnDeinit`) ถึงเจอตัวการจริง (z-score ATR ที่ไม่ได้ log-transform
  ก่อน ทำให้ squeeze แทบไม่เกิด) ใส่ counter ไว้ก่อนเสมอเมื่อ debug entry/exit logic ของ EA
- **ห้ามสรุปว่าชุดที่ชนะใช้ได้จริง จนกว่าจะทดสอบบนข้อมูลที่ไม่มีส่วนในการเลือกค่านั้นเลย**
  การแบ่งข้อมูลชุดเดิมออกเป็นครึ่งแล้วรันแยกกัน **ไม่ใช่การตรวจสอบ** — พิสูจน์แล้ว 2026-09-10:
  ชุด M5 ผ่านการแบ่งครึ่งฉลุย (PF 1.19 และ 1.22) แต่พอเจอ 3 ปีที่ไม่เคยใช้จูน **ล้างพอร์ตทั้งสามปี**
  ต้องใช้ช่วงเวลาคนละก้อนเท่านั้น และห้ามเอาผลจากก้อนนั้นกลับมาเลือกค่าต่อ ไม่งั้นก้อนนั้นก็เสียไปด้วย
- **ผล optimization ที่ชนะแบบโดดเดี่ยว ห้ามเชื่อ** ต้องดูค่าข้างเคียงเสมอ ถ้าขยับพารามิเตอร์ 1 ขั้นแล้ว
  ผลตกฮวบ แปลว่าบังเอิญ ไม่ใช่ edge — เลือกค่าที่อยู่กลางแถบที่ดีทั้งแถบแทน (เจอจริง 2026-09-10:
  ribbon shift 19 ได้คะแนน 6.29 แต่ shift 18 กับ 20 ได้ 0.88 กับ 2.28)
- **เกณฑ์ "ถอนกำไรได้สม่ำเสมอ" ที่ผู้ใช้ตั้งไว้ (2026-09-11)** — winrate 50%+ · ไม้ใหญ่สุดไม่เกิน
  10-15% ของกำไรรวม · เดือนที่กำไรเกิน 70% ของเดือนทั้งหมด · DD ไม่เกินกำไร 2-3 เดือน ·
  ไม้พอให้ถอนจริง (20+ ไม้/เดือน) **ยังไม่มี EA ตัวไหนผ่านครบทั้ง 5 ข้อบนข้อมูลที่ไม่ได้ใช้เลือกค่า**
  ไล่ไปแล้วราว 4,000 ชุด 2 ตระกูลกลยุทธ์ 5 timeframe — ตารางสรุปว่าตกข้อไหนอยู่ใน
  `optimizer\README.md` หัวข้อ "ยังไม่มี EA ที่ถอนกำไรได้สม่ำเสมอ" อ่านก่อนเริ่มรอบใหม่
  จะได้ไม่ไล่ซ้ำทางที่วัดแล้วว่าตัน
- **ชุดที่ผ่านเกณฑ์ความสม่ำเสมอครบทุกข้อ "บนปีที่ใช้จูน" ยังบอกอะไรไม่ได้เลย** พิสูจน์แล้ว
  2026-09-11: Range Fade ผ่านทั้ง 5 ข้อพร้อมกัน (winrate 59.5%, 11/13 เดือนกำไร, DD = กำไร
  2.6 เดือน) แล้วขาดทุนทั้ง 3 ปีที่ไม่เคยใช้จูน — ตัวเลข "เดือนที่กำไร" ที่วัดบนปีเดียวกับที่คัดค่ามา
  เป็นผลของการเลือก ไม่ใช่คุณสมบัติของกลยุทธ์ **เกณฑ์ความสม่ำเสมอต้องวัดบนช่วงที่ไม่ได้ใช้เลือกค่า**
- **ก่อนสรุปว่าชุดไหนตาย ให้แยกระหว่าง "เลือกค่าผิด" กับ "ตระกูลนี้ไม่มี edge"** วิธีตรวจคือรัน
  กริดทั้งกริดบนช่วงที่กันไว้ แล้วนับว่ามีกี่ชุดที่กำไร ถ้า 0 จาก 280 ก็ไม่ใช่เรื่องค่า (ทำแบบนี้กับ
  Range Fade แล้ว) — ผลเชิงลบแบบนี้ใช้ช่วงที่กันไว้ได้โดยไม่เสียหาย เพราะไม่ได้เอาไปเลือกค่าต่อ
